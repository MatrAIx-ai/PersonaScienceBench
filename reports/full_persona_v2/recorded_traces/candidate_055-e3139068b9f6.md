## Proposed experiment design

### Question and estimand
Estimate whether adding cross-file context changes code-completion quality relative to using only the target file’s context. The primary estimand is the paired difference in exact-match completion accuracy between the cross-file and in-file-only conditions on the same held-out targets.

### Explicit proposed choices (not established by the repository)

Record source URLs, licenses, commit/revision identifiers, and filtering decisions. If repository-level source files needed for retrieval are unavailable in the chosen snapshot, select a repository corpus that preserves them before preregistration; do not silently substitute data after seeing evaluation outcomes.
- **Split:** Split by repository, not by completion example, so no repository contributes examples to both development and evaluation. Use training/development repositories only to settle prompt and retrieval implementation; hold out evaluation repositories until all choices are fixed. Deduplicate exact or near-duplicate files across partitions where feasible.
- **Task:** Construct deterministic infill examples at eligible function-body locations. Give the model the file prefix through the insertion point and request the next fixed-size span (proposed maximum: 64 tokens, stopping earlier at the original span boundary). Retain the original continuation as the reference. Exclude cases that cannot be represented consistently by the model tokenizer or exceed the specified input budget. State eligibility and filtering rules before evaluation.

The repository does not specify any model, and this choice must be confirmed by a feasibility check before protocol lock. Do not fine-tune separately by condition.
