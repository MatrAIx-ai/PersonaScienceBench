## Paired conditions and context construction
For every held-out completion target, build both conditions from the same frozen repository snapshot and the same target prefix:

1. **In-file only (baseline):** the target file’s permitted surrounding code and prefix; no content from other files.
2. **Cross-file (treatment):** the identical in-file content plus cross-file snippets selected by a deterministic retrieval procedure.

A reasonable operational default is to rank eligible files by static relevance—such as import/dependency relationships and symbol references to names used in the target—then break ties deterministically (e.g., stable path ordering). Select snippets under a fixed token budget, without using the held-out completion, reference suffix, tests, or future repository information. Log selected paths, ranks, and token counts for auditability. This retrieval rule is a proposed operationalization; the materials do not prescribe one. If the research question concerns another retrieval method, specify and freeze that method instead.

Match the total prompt/context token budget across conditions. In the treatment, cross-file tokens should displace a prespecified amount of otherwise available in-file context (for example, retain the target prefix and truncate more distant in-file context). This avoids giving one condition a larger input budget, though it changes which in-file material is visible; report this tradeoff explicitly.
