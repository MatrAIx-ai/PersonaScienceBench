## 2. Quantizer का पूर्ण specification

सभी range/scale गणनाएँ FP32 में होंगी। Round-to-nearest, ties-to-even उपयोग करेंगे; clip integer endpoints सहित होगा। NaN/Inf मिलने पर run invalid माना जाएगा। Dequantized tensor model computation के लिए FP16 में cast होगा। Diagnostics में pre-cast quantization error तथा FP16 cast के बाद का error अलग दर्ज होगा।

### 2.1 Symmetric input

एक vector x के लिए m=max_i |x_i| और a=r·m, जहाँ 0<r≤1। Signed 4-bit representation में **q∈[−7,7]**; −8 code अनुपयोगी रहेगा ताकि symmetry ठीक बनी रहे।

यदि m>0:

s=a/7,

q_i=clip(round(x_i/s),−7,7),

x̂_i=s·q_i.

Zero-point 0 है और zero ठीक representable है। यदि m=0, सभी codes और outputs 0 रखेंगे; implementation scale 1 रख सकती है। Nonzero constant vector पर सामान्य formula ही लागू होगा: r<1 पर clipping जानबूझकर होगी, कोई constant-vector bypass नहीं।

### 2.2 Asymmetric K/V

स्थानीय vector x के लिए a=min x, b=max x, c=(a+b)/2। पहले midpoint-centered retained interval बनाएँ:

L₀=c−r(b−a)/2, U₀=c+r(b−a)/2.

फिर **zero inclusion** करें:

L=min(L₀,0), U=max(U₀,0).

Unsigned 4-bit codes **q∈[0,15]** होंगे। U>L होने पर:

s=(U−L)/15,

z=clip(round(−L/s),0,15),

q_i=clip(round(x_i/s)+z,0,15),

x̂_i=s(q_i−z).

Zero ठीक representable है। Zero-point rounding के कारण वास्तविक representable endpoints L*=−s·z और U*=s(15−z) होंगे; वे L,U से अधिकतम आधे quantization step तक खिसक सकते हैं। इसलिए r=1 भी वास्तविक endpoints पर थोड़ी clipping दे सकता है; वह **no intentional range shrink** control है, exact no-saturation guarantee नहीं।

**Retained-range convention की सीमा:** r, zero inclusion से *पहले* midpoint interval की width को नियंत्रित करता है। Zero बाहर होने पर inclusion interval फैलाएगा, इसलिए अंतिम range width आवश्यक नहीं कि r(b−a) हो। यह percentile ratio या clipped-elements fraction नहीं है। L₀/U₀, L/U और L*/U* सभी diagnostic में रखेंगे; input और K/V पर समान r का अर्थ समान saturation fraction नहीं है।

**Constant vectors:** सभी entries zero हों तो scale 1, z=0, q=0 और output 0। Constant t≠0 में zero inclusion से interval [0,t] अथवा [t,0] बनेगा; सामान्य formula लागू होगा और endpoint t FP32 precision तक representable रहेगा। ऐसे vectors पर r का प्रभाव नहीं होगा।

## 3. Reproducible PPL protocol

1. Checkpoint revision/hash, tokenizer files, dataset revision, framework versions और numerical backend pin करेंगे। Dropout off, model.eval(), no gradients; sampling/generation नहीं।
2. प्रत्येक dataset split की `text` rows को मौजूदा क्रम में newline से जोड़ेंगे; empty rows बनाए रखेंगे। कोई stripping, lowercase या अन्य normalization नहीं। Tokenizer को `add_special_tokens=False` के साथ चलाएँगे। Split boundaries कभी पार नहीं होंगी।
3. Token stream को अधिकतम **2047 data tokens** के लगातार, non-overlapping blocks में बाँटेंगे: data-token stride 2047। हर block के आगे ठीक एक BOS जोड़ेंगे; EOS नहीं जोड़ेंगे। Model context अधिकतम **2048 positions**, BOS सहित। अंतिम छोटा block भी उपयोग होगा। यह sliding overlapping-window PPL नहीं, स्पष्ट रूप से block-reset PPL है।
4. हर block में cache reset और position IDs 0 से शुरू। BOS अथवा पिछले ground-truth token को sequentially feed कर अगले data token की NLL score करेंगे। BOS score नहीं होगा; हर data token ठीक एक बार score होगा। Block के बाहर context नहीं मिलेगा। Padding, यदि आवश्यक हो, पूरी तरह mask और unscored होगी।
5. हर forward step में उस token के K/V को quantize करके cache में डालेंगे, फिर attention में current तथा past cache के **dequantized** tensors उपयोग होंगे। किसी hidden FP16 shadow cache से attention नहीं चलेगा। एक ही quantized cache entry पढ़ने पर पुनः quantize नहीं होगी।
6. Log probabilities FP32 log-softmax से; token NLL sums FP64 में accumulate करेंगे।

NLL = (Σ scored token negative log-probabilities)/N;

PPL = exp(NLL).

Window PPL का औसत नहीं लेंगे। सभी conditions में token IDs, scored positions, masks और resets समान होंगे। Quantization का graph correctness सत्यापित होने के बाद ही equivalent faster teacher-forced implementation स्वीकार होगी।

## 4. Controls और sweep

**प्राथमिक controls:**
- FP16 reference, बिना किसी quantization के।
- संयुक्त 4-bit input+KV, r=1। यह quantization rounding और clipping-shrink के प्रभाव अलग करने का anchor है।

**मुख्य sweep:** r∈{1.00,0.99,0.975,0.95,0.925,0.90,0.85,0.80}। सभी validation tokens पर हर candidate का मूल्यांकन होगा।

**पूर्वनिर्धारित boundary और refinement नीति:**
- सबसे कम validation NLL वाले candidate को anchor मानेंगे; exact tie में बड़ा r। यदि anchor वर्तमान न्यूनतम ratio है, नीचे 0.05 के steps में candidate जोड़ेंगे: 0.75, 0.70, …, 0.05। हर addition के बाद रुकेंगे जब best anchor निचली boundary पर न रहे, अथवा 0.05 पहुँच जाए।
- Coarse/extension search के बाद anchor के दोनों निकटतम evaluated neighbors से bounded interval में 0.005 spacing की grid चलाएँगे; existing points दोहराएँगे नहीं। Boundary anchor के लिए उपलब्ध एक-sided interval लेंगे। केवल एक refinement pass होगा।
- यदि अंत में 0.05 best है, उसे **boundary-limited finding** कहेंगे, interior optimum नहीं; नीचे extrapolate या test देखकर search नहीं बढ़ाएँगे। r>1 इस clipping-shrink प्रश्न का हिस्सा नहीं होगा।

**Attribution controls:** validation-selected r* और r=1 पर input-only तथा KV-only quantization। अतिरिक्त validation diagnostics में all-components-quantized settings (r*,1,1), (1,r*,1), (1,1,r*) चलाएँगे, क्रम input/K/V है। ये shared-ratio assumption की sensitivity दिखाएँगे, स्वतंत्र तीन-dimensional optimum नहीं खोजेंगे और primary selection में सम्मिलित नहीं होंगे।

## 5. Quantization error और mechanistic diagnostics

दो प्रकार का error अलग रखेंगे:

**A. Common-reference local error:** FP16 reference के उसी validation activation/K/V vector पर प्रत्येक candidate quantizer offline/streaming लागू करेंगे। इससे अलग-अलग runs में बदलते hidden states के confounding के बिना clipping/rounding तुलना होगी। पूरा activation dump आवश्यक नहीं; sufficient statistics online accumulate होंगे।

**B. End-to-end propagated error:** actual quantized runs में उन्हीं tokens पर logits/NLL differences, स्थानीय pre-quantizer बनाम reconstructed tensor error, तथा reference से selected layer/head deviations दर्ज होंगे। इसे A के समान अर्थ वाला error नहीं कहेंगे।

प्रत्येक quantization site j के लिए प्राथमिक local normalized error:

E_j(r)=Σ||x̂_r−x||² / max(Σ||x||²,10⁻¹²),

जहाँ sums validation के सभी उस-site vectors और elements पर हैं और x̂ model को मिलने वाला FP16-cast reconstruction है। Input sites के E_j का समान-weight औसत E_in; layer×head K sites का समान-weight औसत E_K; V के लिए E_V। Tie-break scalar:

E(r)=(E_in+E_K+E_V)/3.

इससे बड़े tensors या अधिक input sites अकेले metric dominate नहीं करेंगे। E_j तथा तीन components अलग भी report होंगे; aggregate में collapse होने से outlier layers छिपेंगे नहीं।

**अन्य diagnostics:** zero/constant-vector counts, scale distribution, intended और actual range, actual-bound saturation fraction, MSE/normalized MSE, layer/head-wise tails, तथा FP16 से token NLL changes।

Clipping-versus-rounding breakdown के लिए x_c=clip(x,L*,U*) लें; symmetric case में bounds ±r·m। e_clip=x_c−x और e_round=x̂−x_c। Squared error में दोनों squared terms के साथ 2·e_clip·e_round cross-term भी report करेंगे; केवल दो MSE जोड़कर total मानना गलत होगा। Pre-cast और post-cast diagnostics से numerical casting effect पहचाना जाएगा।

## 6. निष्पक्ष ratio selection

सभी search और diagnostics validation तक सीमित रहेंगे। Test न scan होगा, न threshold चुनने में उपयोग होगा।

1. Evaluated candidates में न्यूनतम validation NLL को n_min कहें।
2. पूर्वनिर्धारित **numerical tolerance τ=10⁻⁵ nats/token** के भीतर candidates रखें: NLL(r)≤n_min+τ। यह व्यावहारिक accuracy-equivalence margin नहीं है।
3. इस set में सबसे कम E(r) वाला ratio चुनें। E के exact numerical tie में बड़ा r, अर्थात कम clipping, चुनें। यही r* होगा।

यह **NLL-first** rule है; arbitrary weighted PPL+MSE objective नहीं। बहुत कम quantization MSE लेकिन स्पष्ट खराब NLL वाला candidate नहीं चुना जाएगा। Numerical repeatability pilot में observed variation τ से बड़ी हो तो backend deterministic बनाकर/reduction सुधारकर search से पहले protocol ठीक करेंगे; observed PPL देखकर τ नहीं बढ़ाएँगे।

**Uncertainty को equivalence न समझें:** confidence interval में zero होना या intervals overlap करना इस tolerance set में प्रवेश का आधार नहीं है। Statistical uncertainty और numerical tolerance अलग अवधारणाएँ हैं।

## 7. Analysis और held-out test

- Validation पर r के विरुद्ध NLL/PPL, FP16 और r=1 से ΔNLL, E_in/E_K/E_V, aggregate E तथा saturation plot करेंगे। PPL-error Pareto plot सहायक होगा, selection rule का स्थानापन्न नहीं। Curve को monotonic या U-shaped मानकर fit करना आवश्यक नहीं।
- प्रत्येक block के token NLL sum/count सुरक्षित होंगे। **Paired block bootstrap**, 2,000 resamples, fixed seed 1729, सभी compared settings के लिए समान sampled block IDs उपयोग करेंगे। हर resample में ratio-of-sums NLL, उससे PPL, ΔNLL और PPL ratio निकालेंगे; 2.5/97.5 percentiles से 95% intervals।
- Dataset order dependence की sensitivity के लिए 8 consecutive blocks की moving-block bootstrap भी report करेंगे। ये intervals इसी corpus की sampling variability का approximation हैं; unseen domains का assurance नहीं। Validation sweep intervals descriptive हैं और adaptive selection bias दूर नहीं करते।
- Ratio lock होने के बाद test पर FP16, संयुक्त r=1 और संयुक्त r* चलाएँगे। Primary comparison r* बनाम r=1 का paired ΔNLL और PPL ratio; secondary r* बनाम FP16 accuracy gap। Input-only/KV-only r* attribution controls भी report किए जा सकते हैं, पर test पर selection नहीं बदलेंगे।
- Test पर improvement न मिले तो वही report करेंगे; validation winner को जबरन successful या statistically equivalent नहीं कहेंगे। Error metric और PPL में असहमति भी substantive finding होगी।

## 8. Planned correctness checks और feasibility

**Execution से पहले checks:** integer bounds, ties-to-even, symmetric sign behavior, zero reconstruction, positive-only/negative-only ranges, constant vectors और mixed-sign zero-point rounding के छोटे unit tests। r=1 को identity न मानें। Synthetic outliers से intentional shrink और saturation सही होने की जाँच करें।

Quantization bypass में cached और uncached reference logits/NLL को छोटे sequence पर compare करें; masks/position IDs और BOS handling जाँचें। Cache read instrumentation से पुष्टि करें कि attention quantized-dequantized K/V ही पढ़ता है; bit-width बदलने पर cache representation बदलनी चाहिए। Block scoring में हर data-token ID/position ठीक एक बार आए। FP16 values पर fake-quant cache का reference implementation स्वीकार्य है, लेकिन वह वास्तविक packed-cache memory या speed benefit का प्रमाण नहीं है।

**व्यावहारिक संसाधन:** वर्तमान environment में GPU, datasets, installed project dependencies या उपलब्ध model weights का प्रमाण नहीं है; network disabled है। भविष्य के execution में authorized checkpoint/tokenizer, pinned WikiText-2 data, compatible framework और GPU access देना होगा। 7B के FP16 weights अकेले लगभग 14 GB लेते हैं; batch-1, 2048 context और framework workspace के लिए अतिरिक्त memory चाहिए। लगभग 24 GB-class GPU एक संभावित starting point है, गारंटी नहीं; instrumented implementation में अधिक memory/offloading लग सकता है। Sequential cache-based scoring और अनेक ratios के कारण यह साधारण एक-pass PPL से काफी महँगा होगा। Runtime का अनुमान केवल छोटे future pilot से लेना चाहिए।
