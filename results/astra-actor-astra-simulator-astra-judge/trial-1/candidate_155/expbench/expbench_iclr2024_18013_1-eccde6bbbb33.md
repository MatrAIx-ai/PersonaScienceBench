# FuseLLM 与 Llama-2 零样本常识比较：最终设计

## 1. 目标、事实边界与假设
**固定目标：**设计实验回答 FuseLLM 是否在常识标准基准零样本评测中优于 Llama-2；不要求执行。

**材料支持的事实：**本地 task.json 只确认模型名称、CS、zero-shot 和设计任务。所给 `iclr2024/18013/1:setup_2`、`iclr2024/18013/1:setup_9` 没有对应设置正文。原研究的 CS 清单、模型规模/checkpoint、基础版或对话版、数据版本及评分方式仍未知。

**经批准的独立协议：**以下七任务集合、规模匹配基础模型优先、任务等权宏平均差及分层配对 bootstrap，是本设计的选择，不是已确认的原研究设置。不能把本实验称为原研究复现。

目标量为固定七任务集合上的差值：
`Δ = (1/7) Σ_t [Accuracy(FuseLLM,t) − Accuracy(Llama-2,t)]`。
报告单位为百分点。方向性研究假设是 Δ>0；主要统计判据为双侧 95% 配对 bootstrap 区间下界>0。区间跨越或触及 0 判为不足以支持优势，不代表等效；区间上界<0 支持反方向的平均优势。平均优势不等于每项任务均优。

## 2. 任务、划分与逐任务主评分
以下均使用执行前冻结的数据发布版本中的**完整 validation 划分**，原因是通常可取得公开标签，且便于一致重算。本设计不将其称为隐藏测试成绩。版本、配置和样本数需执行前核验并写入清单；不得将惯常样本数当作已核验事实。

| 任务 | 拟用配置/划分 | 固定英文模板概略 | 候选答案 | 主评分 |
|---|---|---|---|---|
| BoolQ | validation | `Passage: {passage}\nQuestion: {question}\nAnswer:` | ` yes`、` no` | 未归一化候选对数似然 |
| PIQA | validation | `Goal: {goal}\nSolution:` | sol1、sol2 | 按候选 token 数归一化 |
| HellaSwag | validation | `{context}` 后直接续写 | 四个 ending | 按候选 token 数归一化 |
| WinoGrande | winogrande_xl / validation | 下划线之前的句子作为前缀 | 选项替换下划线后，连同句子剩余部分 | 未归一化的完整续写对数似然 |
| ARC-Easy | ARC-Easy / validation | `Question: {question}\nAnswer:` | 实际提供的全部选项文本 | 按候选 token 数归一化 |
| ARC-Challenge | ARC-Challenge / validation | 同上 | 实际提供的全部选项文本 | 按候选 token 数归一化 |
| OpenBookQA | main / validation | 同上，只用 question_stem | 四个选项文本，不输入辅助事实 | 按候选 token 数归一化 |

**定义：**对提示 P 和候选续写 c，`L(c|P)=Σ_j log p(c_j|P,c_<j)`，仅累加候选 token，不计提示或 EOS；长度归一化为 `L/N`，N 是该模型原生 tokenizer 对候选区域产生的 token 数。选最高分候选，预测与 gold 相符记 1，否则为 0；每任务准确率为正确题数除以该任务冻结题数。BoolQ 使用短的二元答案；WinoGrande 给候选之后的句子后缀计分，使替换选项能由后文约束；其他任务用 token 平均似然作为默认长度偏差控制。这些是自定评分口径，不宣称与官方排行榜或原研究完全一致。

每个普通答案续写统一加一个前导空格；WinoGrande 使用原句空白连接，HellaSwag 在 context/ending 间保证一个连接空格。所有文本保留大小写、标点与内容，只将换行编码统一为 LF 并去掉字段外侧空白；不擅自删除 HellaSwag 标记或改写题目。完整模板、连接规则和 tokenizer 边界处理写入版本化协议：分别编码提示与候选区域、拼接 token 序列计算条件似然，避免跨边界合并导致提示 token 混入评分；特殊 token 仅按各 checkpoint 文档插入一次 BOS，不自动添加 EOS。保存代表性编码例子以便审核。

不提供字母标签列表，也不让模型生成解释；逐一计算候选文本的似然。这使两模型使用相同的语义输入，不受生成长度和答案提取规则干扰。完全同分时取原始顺序最靠前候选，并报告平局次数。

## 4. 零样本与公平性控制
- 禁止 in-context 示例、演示答案、chain-of-thought 示例或诱导推理提示、检索、外部知识库、工具调用、额外事实字段、测试时训练及任何验证集反馈调参。OpenBookQA 的附加事实不输入模型。
- 两模型同题、同模板、同候选文本、同原始顺序和同题目集合；基础模型不添加 chat template 或系统提示。零样本指推断时无示例，不保证训练时未见评测数据。
- 使用各自原生 tokenizer；固定同一数值精度政策，默认非量化 BF16，若任一模型不支持则两者统一切换 FP16 并声明。启用 eval、禁用 dropout；似然求和用 FP32。无需采样解码。
- 上下文预算设为两模型支持上限的较小值。原则上不截断题目/候选；在无标签预检中识别超长样本，先选择两者都支持的预算。仍超长时记为协议失败，不能单边截断或悄悄删题。
- batch size 可因显存不同而调整，但不改变输入、精度或评分规则。padding 必须掩码；抽查单样本与批量评分一致性。记录库、内核版本和数值容差。
- 不使用验证成绩优化提示。语法/索引检查采用合成例子；若检查真实样本，仅核对字段与编码，不凭模型答对率修订协议。

这些控制把比较限制为相同任务和推断协议下的两个 checkpoint，减少提示、标签提取、数据选择和精度差异造成的偏差。但它们不能令两个模型的训练经历相同。

## 5. 主要分析与敏感性分析
**主要分析：**保留逐题两模型得分、预测和正确性。对每任务内的同一题配对重采样，不能独立抽两模型结果；每次计算各任务准确率差后等权平均。固定种子，做 10,000 次 bootstrap，采用第 2.5 和 97.5 百分位作为区间。

如果同一 passage、context 或来源场景产生多题，则执行前按可用 ID 或标准化文本确定簇，任务内抽簇并保留簇中全部配对样本；每次仍按题计算任务准确率。若发现跨任务共享来源簇，应同步抽取共享簇并保持任务等权，报告调整，不能假设独立。区间表示固定任务集合内题目/簇抽样不确定性，不涵盖不同训练随机种子或随机选择新任务的变异。

报告两模型逐任务准确率、差值、样本/簇数、总体宏平均与 Δ 区间。逐任务推断是次要分析：独立题用双侧精确 McNemar；有簇时用簇级配对方法，并对七项检验采用 Holm 校正。

**预先指定的敏感性分析：**
- 在同一题集上，对所有候选任务同时计算 raw log-likelihood 与 token 平均 log-likelihood 两套结果；再用候选 UTF-8 字节数作分母检查 tokenizer 长度差异的影响。不能从中选最好看的作为主终点。
- 报告按题数加权的微平均及逐一去掉任务的宏平均，只检查任务权重与单任务支配，不替代主分析。
- 若可取得去污染标记，另报未标记污染的共同子集；不能据结果临时定义污染规则。
- 建议将 +1 个百分点作为描述性实际意义参考阈值，非来源要求。只有区间下界也超过该阈值时才支持“至少达到该幅度”的结论；不另行事后调阈值。

## 6. 失败、缺失和质量检查
- 运行前核对数据 schema、gold 到候选的映射、候选数量、空字段、重复 ID、完整覆盖及共享上下文。原始数据中的重复不得静默去重；可另作共同去重敏感性分析。
- OOM 首先降低 batch size，对失败项按相同协议重试；记录每次失败。NaN、空候选、超长及损坏样本按预先定义类别登记，不将技术失败误记为模型知识错误。
- 主分析要求七任务全部可用，并且冻结的有效题集合上两模型均有可用预测。任一模型仍有技术失败时，不宣称主终点完整；可报告配对完整子集作为探索结果，同时给出将每个缺失正确性分别置 0/1 的保守上下界，说明缺失可能非随机。
- 确认是数据错误且无法评分的题，可由不查看模型结果的审核统一排除并冻结更新清单，报告数量和原因。模型单边失败不能用这种理由删除。
- 缺失一个完整任务时，不以六任务平均冒充七任务终点，不用其他任务补位；只报告可用任务结果，主要结论暂不可判定。
- 未来执行前的可行检查包括手算合成 logits 的评分单元测试、BOS/掩码/候选 token 边界检查、batch 不变性、标签索引测试及小样本复算。这些尚未执行，不属于已完成实验。

## 7. 污染与归因限制
收集公开训练/融合语料说明与数据时间线；有权限访问语料时按预注册的精确/近重复匹配规则审计，且同样处理两模型。无法访问语料时明确“无法排除训练污染”，不得将零样本解释为无泄漏。

即使 FuseLLM 平均更高，也只支持所选 checkpoint 在本协议下的模型级比较。训练数据、额外 token、融合后训练、架构/tokenizer 和优化过程均可能不同；规模匹配并非因果消融，不能把差异直接归因于融合方法。七任务本身包含科学问答及阅读理解成分，也不是所有常识能力的代表性抽样。

## 8. 可复现记录与未来资源
归档冻结协议及变更历史、模型与数据哈希、软件/硬件版本、精度、模板、tokenizer 设置、候选区域长度、簇映射、种子、全部逐题候选分数/预测/gold、失败日志、bootstrap 配置和汇总脚本。敏感文本或受限权重不擅自重新分发，可记录可访问 ID 与哈希。

当前没有模型、数据或 GPU，也没有下载、训练或试跑。本实验只需推断，无需重新训练。**条件性资源估计：**若两模型均为约 7B 的稠密模型，BF16 权重每个约 14 GB（十进制），单模型顺序加载后，一张 24–48 GB GPU 通常是可规划的起点；长序列、工作区及批量会增加显存，24 GB 不作保证。两模型不必同时驻留。磁盘需权重、缓存及日志空间，可按至少 50–100 GB 预留，实际由权重格式和数据决定。更大模型需重新估算或多 GPU；不得为了适配硬件单方面量化。

耗时取决于冻结样本数、每题候选数、序列长度和硬件吞吐，现阶段不报虚构运行时。未来可在冻结协议后用不用于调参的少量样本测吞吐，再按全部候选 token 工作量估计。CPU 可承担数据检查及统计分析，当前 CPU 环境不足以证明完整推断可行。

## 9. 未来结果的回答形式
