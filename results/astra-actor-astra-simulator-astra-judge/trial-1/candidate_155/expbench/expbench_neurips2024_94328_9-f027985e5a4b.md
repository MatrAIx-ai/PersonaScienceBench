# Phi-3-mini-4k-instruct 上 QuaRot-RTN 与 QuaRot-GPTQ 的实验设计

**性质：设计稿；没有执行模型实验，没有经验结果。**

## 1. 研究问题与约束

任务固定要求是：以 Phi-3-mini-4k-instruct 为目标，比较 QuaRot-RTN 与 QuaRot-GPTQ 在 4、6、8 位下的困惑度和零样本准确率。

经批准，本研究选择 **WbAbKVb** 为主口径，b∈{4,6,8}，六个主条件统一使用量化—反量化（QDQ）模拟。RTN/GPTQ 仅改变权重量化求解方法，其他量化规则和旋转保持一致。该口径及下文没有来源依据的参数都是**本设计选择，不是已经核实的 QuaRot 论文配置**。不评价原生整数内核速度、吞吐量、实际缓存压缩率或部署内存收益。

研究分为两个问题：
1. 在同一位宽与同一旋转下，GPTQ 相对 RTN 改善、持平还是恶化？
2. 量化后相对原始浮点模型保留多少质量，旋转对这种保留是否有帮助？

不预设 GPTQ 优于 RTN，也不以“优于未旋转量化”代替“接近浮点质量”。

## 3. 数值协议

### 3.1 浮点执行与量化器

所有主比较使用相同 FP32 运算路径，关闭 dropout、TF32 和混合精度，采用显式注意力实现，避免不同融合内核改变 QDQ 位置。QDQ 后仍以 FP32 计算；不是整数执行模拟的逐指令复现。若资源迫使采用 BF16/FP16，应作为修改后的独立实验分支，同时重跑其全部基线；不得与 FP32 主表混用。

对 b 位张量采用有符号、对称、零点为 0 的窄范围量化：

- qmax=2^(b−1)−1；码值为 [−qmax,qmax] 内的整数，即 4/6/8 位分别为 [−7,7]、[−31,31]、[−127,127]。
- q=clip(round_to_nearest_even(x/s),−qmax,qmax)，反量化为 s·q。
- scale 为 FP32，不量化；全零组直接返回零并记 scale=1。
- 窄范围会少用一个通常可用的负码值，这是本设计的公平共享选择，不等同于所有实现的“INTb”。

### 3.2 张量覆盖范围

|张量/操作|主条件精度与粒度|scale/裁剪|
|---|---|---|
|注意力 Q/K/V/O 投影权重、MLP gate/up/down 权重，包括融合实现中的对应切片|b 位；按每个输出通道、连续输入通道组 128 量化；末组不足 128 不填充参与统计|每组独立 scale；按下述 MSE 搜索裁剪|
|上述线性层输入激活|b 位；每 token、沿最后一维每 128 通道一组|动态 absmax/qmax，不额外裁剪|
|进入 QKᵀ 的 Q|b 位；每 token、每 query head 一组|动态 absmax/qmax|
|进入 QKᵀ 的 K 及缓存 K|b 位；每 token、每 KV head 一组|RoPE 和指定头内旋转之后，动态 absmax/qmax|
|进入 PV 的 V 及缓存 V|b 位；每 token、每 KV head 一组|头内旋转之后，动态 absmax/qmax|
|softmax 后注意力概率 P|FP32|不量化|
|embedding、LM head、norm 参数、偏置、残差流、RoPE 运算、softmax、累加、logits、scale|FP32|不量化|

这里的 Ab **不是每个中间张量均为整数**：其覆盖线性层输入和指定 Q/K/V 张量；P、非线性输出若尚未进入下一线性层则仍为 FP32。WO4 条件关闭全部激活与 KV QDQ。融合 QKV、融合 gate/up 的输入只 QDQ 一次，共享该输入，不能因模块切分重复施加。

权重裁剪搜索：对每组待求解权重 x，候选 α∈{0.50,0.55,…,1.00}，s=α·max|x|/qmax；以该组普通 FP32 平方重构误差选 scale，相同误差选较大的 α。RTN/GPTQ 使用完全相同的候选集、分组、误差准则及舍入规则。**公平不要求两方法得到数值相同的 scale**：GPTQ 当前组可能已经接受前组的误差补偿。

### 3.3 RTN 与 GPTQ 的默认实现

- **RTN：** 对旋转融合后的权重逐组搜索 scale，然后独立舍入，无 Hessian 补偿。
- **GPTQ：** 以同一校准集上的层输入构造 H=XᵀX/N（按 token 行存储 X）；每组 128 列，处理 block size=128，输入通道按原顺序处理，关闭 act-order/desc_act。处理当前组时在其补偿后的权重上确定 scale，随后该组内 scale 固定。依照标准二阶逐列消元式 GPTQ 更新尚未处理的权重。
- 阻尼 λ=0.01·mean(diag(H))，使用 H+λI。严格全零的输入列单独标记：其校准贡献为零，权重仍按 RTN 处理且不作二阶补偿；H 完全为零的层全部回退 RTN，并必须披露。
- 使用 Cholesky 构造标准 GPTQ 所需的逆 Hessian 因子。若分解失败，先用 FP64 重算同一问题；仍失败时依次尝试 damping 0.1、1.0 并报告层名和变更。出现这些回退时另列为协议偏差，不静默计入无偏差复现。
- H 及损失检查采用 FP64 累积/诊断，权重更新和推理采用 FP32。不得以硬件 OOM 为由临时更改分组、排序或校准样本数后仍保留同一条件标签。
- 为隔离权重求解，本设计使用**共同浮点参考轨迹**：旋转条件从 R 收集输入，无旋转条件从 F 收集输入。主条件对记录输入施加对应 Ab QDQ 后构造 H；WO4 使用浮点输入。不会在 GPTQ 校准时使用其逐层量化前缀、却让 RTN 使用另一条轨迹。该选择有别于某些逐层顺序校准实现，须记录。

## 4. 旋转与 Phi-3 适配门禁

### 4.1 执行前必须核验，不能视为已检查事实

固定模型仓库 revision、tokenizer revision、配置和权重哈希；检查实际 hidden/intermediate/head 维度、query/KV head 数、RoPE 配置、norm 类型及 epsilon、残差连接、QKV 和 gate/up 融合布局、偏置和权重绑定情况。禁止直接替换 LLaMA 层名后默认正确。

先建立模块映射表和权重切片单元测试。若实现使用带均值中心化的 LayerNorm、并行残差或其他非预期结构，必须重新推导对应变换；不能以 RMSNorm 的推导覆盖它。若 embedding/LM head 共享权重但旋转后不能继续共享，允许在 FP32 中解除共享，并记录这不是新的可训练参数。

### 4.2 具体变换位置

统一采用行向量记法 y=xW。对 residual stream 选正交 R，令 x′=xR：

- embedding 输出变为 ER；每个 residual-to-internal 线性映射变为 RᵀW；每个 internal-to-residual 输出映射变为 WR；相应偏置按输出坐标变换；LM head 使用 RᵀW_head。
- 对确认存在的 RMSNorm，先把其逐通道 gain 融入紧随的所有投影；随后无 gain 的 RMSNorm 与正交变换相容。最终 norm gain 融入 LM head。若存在 norm 偏置，必须在消费者中显式吸收相应仿射项。
- Q/K 的相同头内正交变换放在 **RoPE 之后、QDQ 之前**，保持 QKᵀ。GQA 时，一个 KV head 对应的所有 query heads 使用同一变换；不与 RoPE 擅自交换次序。
- V 的头内变换可融合到 V 投影；PV 的相同变换由 O 投影输入侧的逆变换抵消。K/V 在这些变换之后写入逻辑缓存。
- 对 MLP，先正常计算门控非线性及逐元素乘积 u，再在 down projection 前在线计算 uS，同时将其权重变为 SᵀW_down；不得穿过 SiLU/GELU 或逐元素乘积移动 S。
- 在线旋转必须在对应激活 QDQ 之前执行。所有逆变换均在浮点基线 R 中存在且有匹配的融合权重。

### 4.3 非二次幂维度

二次幂维度使用归一化 Walsh–Hadamard，配固定种子的随机符号/置换。对于 n=m·2^k、m 为奇数的维度，选 Q_m⊗H_(2^k)：Q_m 由固定种子高斯矩阵 QR 得到，并固定 QR 对角符号约定；继续允许固定符号/置换。m=1 时退化为普通 Hadamard。

不通过截断 Hadamard、非正交填充后裁切或删除通道来“适配”。该非二次幂规则是本设计的精确正交扩展，而非经来源核实的 QuaRot 标准实现。若实际需要使用它，结果应标注 **“QuaRot-style Phi-3 适配变体”**，不宣称严格复现官方算法。即使维度均兼容，也要公开各位置的实际矩阵形式。在线变换可用分解形式实现，QDQ 模拟不要求快速整数内核。

### 4.4 验收与失败处理

量化关闭，使用合成输入和校准集首 8 段，覆盖长度 1、17、128、2048：

1. 验证每个旋转的正交性，FP64 下相对 Frobenius 残差 ≤1e−10。
2. 局部模块：将输出变回同一坐标后，FP32 相对 L2 误差 ≤1e−5；逐层 residual 输出 ≤1e−4。
3. 整模 logits：相对 L2 误差 ≤1e−4，最大绝对差 ≤1e−3；同一计分 token 上平均 NLL 差绝对值 ≤1e−4 nats/token。
4. 浮点缓存逐 token 解码与无缓存全前缀结果亦满足 logits 门限；QDQ 路径在给定相同前缀下检查相同位置的 K/V 码值和 scale，并检查 logits 最大绝对差 ≤1e−3、相对 L2 ≤1e−4。

这些容差是预设工程门禁，不是理论保证。先记录 F 重复执行的数值噪声；若其本身不能满足门限，先改用确定性路径而非放宽门限。失败时停止质量评价，定位 norm 融合、RoPE 次序、融合切片、布局、缓存或变换错误；修复后重新验收。若证明因数值条件而需要改阈值，应在看到正式评估结果前修订协议，并保留原失败记录，不事后放宽来接受有利结果。

## 5. 数据、边界与重复

### 5.1 固定版本与去重

所有数据在执行前冻结 dataset revision、文件哈希、样本 ID、文本哈希及处理脚本。保持原始文本，不做任务外 lowercasing 或清理；仅跳过空文本。使用固定目标 tokenizer，不启用 chat template，不自动添加 BOS/EOS。保留 tokenizer 原有特殊符号处理规则。模型最大输入长度不超过 4096。

### 5.2 校准

- 数据：C4 English train；seed∈{17,29,43}，共 3 个配对重复。
- 每个 seed 从冻结的文档清单中均匀无放回选 128 篇 token 数不少于 2048 的文档，每篇均匀选一个合法的 2048-token 连续片段。总计 128×2048 tokens，不跨文档拼接。
- 为避免“流式 shuffle 缓冲区”改变抽样分布，可对合格文档 ID 计算带 seed 的哈希，取排序最前 128 篇；起点使用独立派生 RNG。
- 先冻结评估 ID，再排除文档级相同文本哈希和相同评估窗口 token 哈希的校准候选；记录仍可能存在的近重复，不声称完成语义去重。
- 相同重复内，所有位宽、RTN/GPTQ 和相应对照共享校准片段。旋转 RNG 与校准 RNG 使用独立子流；同一重复内各方法和位宽共享旋转。不同重复改变校准抽样与旋转，用于量化构建敏感性。

### 5.3 困惑度

- **WikiText-2 raw test：** 使用完整 test 文本，按数据集文章标题记录恢复文章边界；冻结解析后的文章 ID/文本清单，并人工抽查边界。若下载版本没有可靠文章边界，先修订并冻结解析规则，不在结果阶段临时拼接。
- **C4 held-out：** 从 English validation 独立取 1024 篇非空、至少含 2 tokens 的文档，固定 evaluation seed=2026，无放回、与校准清单排重。仅纳入每篇前 4096 tokens，以限定预算；此结果称为 C4 held-out 子集 PPL，不冒称全量 C4。
- 每篇独立处理，不跨文档提供上下文。长度 L=2048、stride=1024 的重叠窗口。第一个窗口计分位置 1…min(n−1,2047)；之后每个窗口仅计此前未计过的末端 token。文档第一个 token 不计分，所有其余纳入范围的 token 恰好计分一次。公开窗口起止与 loss mask。
- 不使用 BOS/EOS 引入额外计分事件。NLL 为所有有效 token 的负对数似然之和除以 token 总数，PPL=exp(NLL)；不能平均文档 PPL。各数据集独立报告，不把二者合成任意加权总 PPL。

### 5.4 零样本

采用冻结版本的 lm-evaluation-harness 或等价、经过逐样本一致性验证的实现：PIQA validation、HellaSwag validation、WinoGrande validation（固定 winogrande_xl 配置）、ARC-Easy test、ARC-Challenge test、BoolQ validation，均使用公开标签的完整对应划分。

0 demonstrations、无聊天模板、无 chain-of-thought、无生成采样；采用任务规范中的选项条件似然评分。固定任务配置文件和提示示例，并记录 tokenizer 在提示/答案连接处的边界行为。

|任务|主报告口径|
|---|---|
|PIQA|acc_norm|
|HellaSwag|acc_norm|
|WinoGrande|acc|
|ARC-Easy|acc_norm|
|ARC-Challenge|acc_norm|
|BoolQ|acc|

acc 为选项 continuation 总 log likelihood 最大者的准确率；acc_norm 为冻结 harness 定义的长度归一化选项分数准确率，本协议选用按选项字符长度归一化的实现。正式执行前须核对代码确实如此；若版本不同，先冻结等价自定义 scorer，不混用 token 归一化口径。WinoGrande 按任务实现对候选替换后的固定待评分部分计算似然，不擅自改成孤立词概率；BoolQ 固定 yes/no 映射。并列分数选原始选项顺序最前者。

## 6. KV 路径检查

即便 PPL/选项评分使用 use_cache=False，也必须在每层显式执行：Q/K 完成 RoPE → 匹配的头内旋转 → QDQ(Q)、QDQ(K)；V 变换后 QDQ(V)；再使用反量化张量计算 QKᵀ 和 PV。不得只包装 cache.update 而让无缓存路径使用原始 K/V。

缓存路径保存逻辑码值与每 token/head scale，读取后反量化；已经量化的旧 token 不再次量化。QDQ 模拟可以使用普通整数容器，不宣称真实 b-bit 存储。GQA 在 K/V 量化之后按需要广播，不能分别为复制出的 head 拟合不同 scale。

以固定短前缀及长前缀、不同 batch/padding 布局，对照无缓存评分、prefill 后逐 token 解码的 logits、K/V 码值及 scale。各层记录 hook 调用次数、实际 bit 参数、张量尺寸和饱和比例；检查未旋转/WO4/浮点条件是否确实禁用了不应出现的变换或 QDQ。所有量化张量测试码值范围、零输入、组尾、舍入边界及饱和情况。

## 7. 比较与统计计划

### 7.1 主要估计量

每个位宽下，配对比较 GPTQ−RTN：
- 两个数据集分别报告 ΔNLL；PPL 比率=exp(ΔNLL)，小于 1 表示 GPTQ 较好。
- 六任务等权宏平均准确率差，单位为百分点，正值表示 GPTQ 较好。

同时对每个量化条件报告相对 F 的 ΔNLL、PPL 比率、各任务和宏平均准确率变化，并对 R 报告同类差异。F→R 表示数值适配影响，R→量化表示量化影响。四位旋转/未旋转对照估计旋转贡献；W4A4KV4 与 W4A32KV32 对比反映加入激活和 KV 量化后的联合影响，不能据此分离激活与 KV 各自贡献。

### 7.2 配对区间与检验

- 3 个构建重复分别给出结果，再报告重复间均值和范围。不得把 3 个 seed 视为 3 倍独立测试样本。
- bootstrap 次数 10,000，统计 RNG seed=8128。PPL 以整篇文档为抽样单位，保留文档全部计分窗口，在每次重采样中重新汇总 NLL 分子和 token 分母；不把重叠窗口或 token 当独立样本。
- 准确率在各任务内按题配对重采样，始终将两方法、全部 seed 的同一道题作为同一个抽样单位；宏平均每次重新按六任务等权计算。
- 主区间为 **固定这三个构建种子的平均方法差** 的配对百分位 95% 区间；这是评估样本不确定性，不声称覆盖全部量化随机性。单独展示 seed 差异；可给同时重采样 seed 和样本的层级区间作为敏感性分析，但仅 3 个 seed 时不能据此声称稳定估计 seed 总体方差。
- 确证比较族预先固定为 3 位宽×{WikiText-2 NLL、C4 NLL、宏平均 accuracy}=9 项。使用配对随机化检验：文档或题为单位，交换两方法对应的完整 seed 向量，100,000 次随机交换，双侧 p 值按 (极端次数+1)/(置换次数+1)；对 9 项做 Holm 校正，family-wise α=0.05。95% 效应区间为未校正区间，明确标注，不能把它与 Holm 后显著性混为一谈。
- 单任务差异、旋转对照、权重消融为探索性分析，报告效应和区间；如要作其显著性声明，应另定义比较族并校正。每 seed 的 McNemar 可作正确/错误转移诊断，但不作为额外未经校正的确证证据。

### 7.3 如何讨论迁移

以连续的相对浮点退化曲线为主要结论，避免自定义二元“泛化成功”掩盖差异。为提供可解释的工程参照，预先采用 **两项 PPL 各不超过 F 的 1.05 倍，宏平均准确率下降不超过 1 个百分点** 作为本设计的参考容忍带；它不是公认标准或任务要求。

若需要称某条件“质量基本保留”，须同时报告各指标及 seed 敏感性，并用上述三指标的一侧 Bonferroni 98.33% 置信界均落入容忍带作条件性依据。区间跨界属于证据不足，而不是证明劣化或等价。逐任务较大退化仍须突出，不能被宏平均掩盖。旋转等价性未通过时不得讨论 QuaRot 的量化迁移。

## 9. 资源与分阶段可行性

1. **当前可完成：** 本设计、配置规范、统计计划、数据/层映射清单模板。当前工作区仅有任务 JSON；不能验证模型架构、数据边界、旋转等价性或指标。
2. **拿到代码但尚无模型/数据：** 可做随机矩阵的正交性、QDQ、GPTQ 小矩阵和 mask 单元测试。这不是 Phi-3 实验结果。
3. **拿到固定模型与数据：** 先运行 FP32 适配与缓存门禁，再单个短样本检查全部条件的 hook，随后构建完整条件；门禁通过后才正式评估。
4. **完整评估：** 建议具备 PyTorch、Transformers、固定 harness 和数据工具；离线准备模型、tokenizer、评估数据及许可信息。规划单张 48–80 GB GPU 或可分层卸载方案、64–128 GB 主存和足够本地磁盘；这些是预算建议，不是实测最低要求。FP32 权重约需 4P 字节，逐层 Hessian 需 O(d_in²)，注意力和长序列中间量也需预算；先依据实际配置核算，再确定 batch size，不能用 batch size 改动数学协议。
5. Hessian 按层流式累积，校准输入可逐层重算，避免同时驻留所有激活。保留可复现配置与逐样本统计，量化权重可按需重建，不必同时保存所有条件。

当前无 GPU、无权重/数据、网络关闭，不能开展第 3–4 阶段；CPU 在未来可支持部分正确性检查，但不据此承诺全规模评估时长。本交付不要求当前环境安装依赖或取得额外资源。
