# 最终实验设计：JaxMARL 中 IPPO 与独立深度 Q-learning 的 SMAX 比较

**交付性质：仅设计，没有运行训练，也没有实测结果或预期胜者。** 已知来源仅支持比较 PPO 与 Q-Learning 的 SMAX 训练效率与性能这一目标及一般背景。以下算法配对、数值、场景选择规则、指标和资源额度均是本实验的操作性建议，不代表原作者设置。

## 1. 问题与结论范围

主对照为：
- **共享参数 IPPO**：分散执行，actor 与 critic 仅使用智能体局部信息，不使用集中式全局状态。
- **共享参数独立深度 Q-learning（IQL）**：每个智能体利用自身动作价值选择动作，以独立 TD 目标训练共享 Q 网络，不进行 VDN/QMIX 式价值分解。

参数共享不等于集中式训练信息访问。双方使用相同局部观测、可行动作掩码和必要的智能体/单位类型标识；异质单位的填充和动作映射一致。奖励输入固定为同一环境奖励约定，不添加算法专属奖励塑形。

执行前必须核实目标 JaxMARL 提交是否支持这些变体及 SMAX。若缺少其中一项，暂停、修订算法和实现方案并重新冻结协议，**不得静默用 MAPPO、QMIX 或其他算法替换**。报告准确类名、文件、提交、配置和 TD 目标形式；结果只适用于这些实现，而非整个 PPO 或 Q-learning 家族。MAPPO/QMIX 仅为可选扩展，不计入主预算。

## 2. 场景与环境冻结

主实验选 **4 个场景**。由于没有经确认的场景清单，采用下述不依赖实验成绩的规则，而不虚构场景名称：
1. 在冻结的 SMAX 版本中列出正式注册、可与两种实现兼容的离散动作场景，依据环境元数据记录双方单位总数和单位类型构成。
2. 将双方各自只有一种单位类型的场景归为同质组，其余归为异质组；每组按双方单位总数排序，平局按注册名称字典序。
3. 每组选规模最小与最大的不同场景；若某组不足两个，以剩余列表中按规模排序最小、最大交替补足，始终去重。总共不足四个则在训练前修订协议，不以训练表现筛选。
4. 公布最终场景表和选择日志。此规则覆盖规模与单位异质性，**不宣称保证覆盖已知难度等级**；若版本文档有难度标签，报告但不据算法结果修改选择。

固定各场景官方默认对手、难度、终止规则、回合长度、奖励和观测模式，导出实际值而不是仅写“默认”。训练与测试使用相同场景分布但独立随机流。若场景没有可识别胜负事件，应在执行前修订指标或场景集合；不能事后将任意回报阈值当胜利。

## 3. 固定训练与评估规模

| 项目 | 建议值/规则 |
|---|---|
| 主训练种子 | 每算法×场景 10 个：0–9；完整配对运行 |
| 并行环境 | 每次运行 64 个，双方一致 |
| 步数终点 B | 10,485,760 个联合环境步 |
| 基础采样块 | 128 步×64 环境＝8,192 联合环境步 |
| 评估间隔 | 每 262,144 联合环境步，即 32 个采样块；另评估初始化策略 |
| 每检查点评估 | 100 个完整回合，评估不计入训练交互预算 |
| 主墙钟终点 T | 2 小时冷启动端到端用时 |
| 单次主运行上限 | 6 设备小时；达到 B 与 T 所需观察窗口均完成后即可停止 |

一个联合环境步指一个环境实例中所有智能体共同动作后的状态转移；64 个环境各推进一步计 64 步，不乘智能体数。自动重置的计数按真实环境转移统一处理。预算与评估频率选为采样块整数倍，避免终点舍入；相同步数终点和相同墙钟终点是两个不同的主估计目标。

每个运行持续到已获得 B 处评估且已覆盖 T；若先达到 B，继续训练以观察 T，但 B 处结果固定，不能用之后的策略替代。若先达到 T，继续到 B，以保留步数比较。6 小时仍未完成则按资源上限处理，不假装达到终点。

### 动作与评估
- IPPO 训练按类别分布采样；IQL 训练用 epsilon-greedy。只对合法动作采样。
- 主评估关闭探索：IPPO 取最大概率合法动作，IQL 取最大 Q 值合法动作；平局取固定动作索引。此比较衡量确定性部署策略，不是随机策略的期望表现。
- 双方采用相同的评估场景种子：主测试种子由固定、公开的独立种子生成器产生，每检查点 100 个，可跨算法和训练种子复用以降低测试噪声。调参使用另一组评估种子。不得用主测试反馈选择超参数。
- 每个回合记录胜负、原始团队累计回报和长度；同时记录训练损失、梯度异常、探索率及吞吐，仅作诊断。

## 4. 分数与主结果

采用可执行的默认定义：

**本实验归一化成功分数 NSS = 100 × 获胜回合数 / 100。**

平局、超时和失败回合均不计胜利；若环境自带成功事件，则使用并披露其精确定义。NSS 的范围为 0–100，它是本实验的归一化成功分数，**不是已确认的文献 normalized score，也不是回报线性归一化**。同时完整报告原始团队回报均值与区间。这样无需根据双方表现制造回报上下界，也无需额外锚点训练。

主结果包括：
1. B 步的 NSS 与原始回报，以及到达并评估 B 的时间；
2. T＝2 小时预算内可用策略的 NSS 与原始回报；
3. NSS—联合环境步和 NSS—墙钟曲线；
4. 补充：首次达到 NSS≥80 且下一次评估仍≥80的时间，事件记在第二次确认评估结束。该阈值预先固定，若普遍未达标仍保留，不换成更有利的阈值。

不报告“训练到最好分数所需时间”作为主指标，因为这会引入事后选择与评估频率偏差。

## 5. 训练实现与公平性

采用两者均支持的共享无记忆 MLP，建议两层、每层 128 单元、相同激活函数。IPPO actor 与 critic 各自使用该结构，IQL Q 网络同样结构；报告总参数量，但不声称总容量或计算量完全相同。若双方都只支持其他结构，训练前统一修订并冻结；不单独给一方增加循环记忆。

建议共同折扣 γ＝0.99，FP32，Adam，梯度范数裁剪 0.5，不使用混合精度或专属奖励归一化。IPPO 建议 GAE λ＝0.95、每采样块更新 4 轮、4 个 minibatch、value loss 系数 0.5；IQL 建议明确冻结为一阶独立 DQN 目标（目标网络合法动作最大值、无 Double/dueling 优先回放扩展），均匀回放、预热 16,384 联合步、epsilon 从 1.0 在前 20% B 内线性降至 0.05。终止状态不 bootstrap；时间上限截断的 bootstrap 按同一环境语义处理。

IQL 建议 replay 保存 65,536 个联合转移，采样时展开有效智能体；每采集 256 个联合转移更新一次，每批 256 个联合转移，目标网络每 200 次更新硬同步。记录实际有效智能体样本量、更新数和内存。PPO 与 IQL 不能同时保持相同更新规则且仍忠于各自算法，因此控制环境交互与资源额度，**不强制相同梯度步数**。

上述配置仅在目标实现确实支持时使用；冲突必须训练前解决并写入协议版本。每次运行固定 64 并行环境，不为一方单独搜索吞吐最优并发数。所有主训练在同型号独占设备上执行，随机交错算法和种子次序，以减少系统漂移。

### 对称调参
- 每算法 8 个候选配置；其余设置固定。
- IPPO 网格：学习率 {1e−4, 3e−4} × clip {0.1, 0.2} × entropy 系数 {0.0, 0.01}。
- IQL 网格：学习率 {1e−4, 3e−4} × 最终 epsilon {0.05, 0.10} × 目标同步间隔 {200, 800} 次更新。
- 使用已选场景中最小同质与最大异质场景；缺失类型时取所选场景规模两端。每候选每场景一个独立调参种子 100，预算 B/4＝2,621,440 联合步，且最多 1 设备小时。
- 以两个调参场景的等权终点评分选择每算法一个全局配置，而非每场景单独选。资源上限前未到终点的候选使用上限前最新可用策略分数，并明确该选择同时考虑资源可行性；算法性失败记 0 分。平局依次选预先编号较小者，不参照主实验结果。
- 这是等候选数、等场景、等种子、等步数上限及等设备时上限的有限调参，不保证找出各算法最优配置。不进行看见主结果后的额外调优。

## 6. JAX 计时与墙钟检查点规则

**主时间定义**：单调时钟从新进程启动计至策略评估完成，包括导入、初始化、JIT、训练、计划内评估与检查点写入。每次运行禁用或清空持久编译缓存，禁止复用另一算法/运行的已编译 executable；进程内后续 JIT 缓存正常保留。容器镜像和安装工作事先完成，不计入单次时间。OS 文件缓存不声称完全清空，通过交错顺序与日志控制其影响。

同时分项记录：初始化、首次及后续编译、环境/采样、优化更新、评估、检查点 I/O 与其余开销。首次训练调用若无法精确拆分编译与执行，明确标为“首次调用（含编译）”，不得将其全部伪称编译时间。另报告训练阶段累计时间和排除首次编译后的稳态吞吐；这些补充值不能替换主端到端计时。

每个计时边界等待有关 JAX 数组/设备工作完成，例如调用 `block_until_ready()`；GPU 预分配策略、CPU 线程、日志频率和同步位置保持一致，禁止把异步派发速度当训练速度。

每检查点记录：环境步数、参数快照时间、评估结束时间、持久化结束时间；主时间坐标取该检查点已完成评估并保存的时间。因此时间曲线反映**预算内已得到可用评价的策略**，而非把预算外评估倒填到预算内。

T 处成绩取“主时间戳≤T 的最后一个完整检查点”，不挑最好、不插值、不使用正在执行的评估或未来检查点。初始化策略也走同一计时和评估流程；若 T 内连初始化检查点都不可用，记为无可用策略的系统失败。NSS 时间曲线采用阶梯保持，披露 T 与所选检查点的时间差及对应步数。若某个大采样块跨过 T，不将结束后的参数回填到 T。

## 7. 随机性、统计与异常处理

- 分开训练环境、动作、网络初始化、回放采样和评估 RNG。相同种子编号用于配对比较，但不声称两算法轨迹相同。
- **重复单位为训练种子**。100 个评估回合用于估计每个策略表现，不能当成 100 个独立训练重复。
- 每场景报告两算法均值、种子分布、IPPO−IQL 的 NSS 百分点差和原始回报差；配对 bootstrap 重采样 10 个种子对，10,000 次，给 95% 区间。
- 相同步数时间报告 IPPO/IQL 时间比；对配对 log 时间比取均值再指数化，即几何平均时间比，并 bootstrap 区间。小于 1 表示 IPPO 更快。端到端和纯训练时间比分列。
- 跨场景主汇总为 4 个固定场景等权 NSS 差，以及各场景 log 时间比等权后的指数值。bootstrap 在每场景内重采样种子对；区间解释为对这四个固定场景的种子不确定性，不外推全部 SMAX 场景。场景等权原始回报不作唯一总指标，以免奖励尺度主导。
- 曲线区间标为逐点区间而非同时置信带；主终点预先固定。若做多场景检验，使用 Holm 校正；主要解读效应量、区间和一致性，不以单个 p 值裁决。

**未达标与失败**：
- 达到 NSS 阈值的时间在 6 小时封顶处右删失；报告成功达到比例、生存曲线及限制在共同 6 小时窗口的平均等待时间。大量删失时不计算仅成功运行的时间比。
- B 未在上限内达到者：到 B 时间右删失，B 分数记缺失/未完成，不把最后分数称为 B 分数。展示完成比例及可用终点分布。NSS 总体差可给保守敏感性界限：对缺失 B 分数分别填 0 或 100；完整配对的时间比仅作注明选择限制的描述，不能据此代表全部运行。
- 算法性失败（NaN、发散、可复现 OOM）计入失败率，不换种子；墙钟终点若有已保存可执行策略，用该最后可用策略并标记失败。没有可用策略的 NSS 按部署失败计 0，同时独立列出，不能掩饰成观察到的回合胜率。
- 明确的外部基础设施故障可用相同配置和种子从冷启动重跑一次；保留原日志、原因、重跑开销。仍失败则保留缺失，不持续重试直到成功。两类故障按预注册日志规则判定。

## 8. 硬件、预算与可行性

建议正式平台：**单张 NVIDIA A100 40GB、8 个固定 CPU 核、64GB 主存，每次仅运行一个实验进程**；固定驱动、CUDA、JAX/jaxlib 与 JaxMARL 版本。该硬件是建议，不是已获配资源，也不是来源事实。若只能使用其他设备，执行前整体改为同型号平台并重新冻结；不跨不同设备直接比较时间。

运行数：

- 调参：2 算法×8 候选×2 场景×1 种子＝**32 次**。

`H = Σ主运行实际小时 + Σ调参实际小时 + 预检小时 + 获准基础设施重跑小时`。
