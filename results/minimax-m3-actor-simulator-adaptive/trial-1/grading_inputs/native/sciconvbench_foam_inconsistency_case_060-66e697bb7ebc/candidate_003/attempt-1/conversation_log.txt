Q: For a classic dam-break problem with a sharp free surface, are you sure you want to use `twoPhaseEulerFoam`? (Note: this solver uses an Eulerian–Eulerian approach suited to mixing/dense flows and does not intrinsically produce a sharp interface; `interFoam` is the standard VOF-based solver for a sharp-interface dam-break. Should I switch the solver to `interFoam`, or do you specifically need `twoPhaseEulerFoam` for this case?)
A: Да, для dam-break с чёткой свободной поверхностью нужен именно `interFoam`, а не `twoPhaseEulerFoam`. Поправь в `system/controlDict` строку `application` на:

```foam
application     interFoam;
```

`interFoam` — это VOF-солвер, который и предназначен для задач с резкой границей раздела фаз (вода/воздух), какой и является классический dam-break. `twoPhaseEulerFoam` использует Эйлеров подход для двух взаимопроникающих континуумов и больше подходит для задач с перемешиванием/дисперсными потоками, а не для отслеживания чёткой свободной поверхности.

Остальная часть требования остаётся как было: 2D-сетка, экструдированная на одну ячейку по z с `frontAndBack empty`, инициализация водяного столба через `setFields` (`alpha.water = 1` внутри столба, `0` снаружи).

Q: Каковы физические размеры расчётной области (по x и по y) и водяного столба (ширина и высота) для этого dam-break?
A: В самой формулировке задачи конкретные метры не прописаны — там только общая постановка: "classic 2D dam-break", 2D mesh extruded one cell in z с `frontAndBack empty`, инициализация водяного столба через `setFields` (`alpha.water = 1` внутри, `0` снаружи) и solver `interFoam` в `system/controlDict`.

Предлагаю взять размеры, которые обычно подразумевают под "classic dam-break" — это сетка из стандартного туториала OpenFOAM **`damBreak`**, он хорошо верифицирован и на него куча бенчмарков. Не требование, а дефолтное предложение, если у тебя нет других предпочтений:

**Расчётная область (2D domain, front и back — `empty`):**
- длина по x: **4.0 м** (x ∈ [0; 4])
- высота по y: **3.0 м** (y ∈ [0; 3])
- по z: одна ячейка экструзии, обычно толщиной 0.01 м, центр при z = 0.005 м

**Водяной столб (resting on the bottom, у левой стенки):**
- ширина по x: **1.0 м** (x ∈ [0; 1])
- высота по y: **2.0 м** (y ∈ [0; 2])
- по z: на всю толщину экструзии (там воздух/вода разделяются только в плоскости xy)

Под эти размеры в `system/setFieldsDict` будет что-то вроде:

```foam
defaultFieldValues ( volScalarFieldValue alpha.water 0 );

regions
(
    boxToCell
    {
        box (1 2 0.01) (0 0 -0.01);
        fieldValues ( volScalarFieldValue alpha.water 1 );
    }
);
```

Вопрос: пойдут такие размеры (4 × 3 м, столб 1 × 2 м), или нужны другие пропорции — например, более длинный канал, пониже столб и т.п.?

Q: Хорошо, по геометрии и сетке всё ясно. Остался важный момент — **граничные условия**, особенно на верхней границе (атмосфера / открытый выход или жёсткая крышка?), и хотите ли вы добавлять модель турбулентности (обычно dam-break считают ламинарным, как в стандартном туториале)?
A: Да, согласна — давай придерживаться стандартного туториала `damBreak`, чтобы бенчмарк был узнаваемым:

**Граничные условия (`0/U`, `0/p_rgh`, `0/alpha.water`, и т. д.):** как в исходном `damBreak`:
- **`left`, `right`, `bottom` — `wall`**: no-slip для `U` (`fixedValue (0 0 0)`), zeroGradient для `p_rgh`, zeroGradient для `alpha.water` (или `symmetryPlane` логика для контактного угла, но по факту в туториале ставят `zeroGradient`).
- **`top` — `atmosphere`**: `pressureInletOutletVelocity` (или `inletOutlet` с `phi`) для `U`, `totalPressure` с `p0 uniform 0` для `p_rgh`, `inletOutlet` для `alpha.water`. Это стандартная открытая атмосферная граница, без отражения волн обратно в домен.
- **`frontAndBack`** (одна z-ячейка) — как и договаривались, `empty`.

**Турбулентность:** ламинарный режим, как в стандартном туториале. В `constant/transportProperties` оставляем две фазы (вода + воздух с типичными `nu`), а файлы `constant/RASProperties` / `constant/LESProperties` либо не создаём вовсе, либо кладём `RASProperties` с `simulationType laminar;`. Никакой `k-epsilon`, `k-omega` и т. п. для классического бенчмарка не нужно.

**Физика в `constant/transportProperties`:**
- `water` — `nu 1e-6`, `rho 1000`
- `air` — `nu 1.48e-5`, `rho 1`
- `sigma` (коэффициент поверхностного натяжения) — `0.07` Н/м, как в туториале.

**`constant/g`:** `(0 -9.81 0)` — стандартная гравитация.
