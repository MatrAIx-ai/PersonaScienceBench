## 2. कार्यकारी मॉडल और डेटा मान्यताएँ

- ETTm1 में `HUFL, HULL, MUFL, MULL, LUFL, LULL, MUFL, MULL` जैसी स्वतः अनुमानित schema का उपयोग नहीं करेंगे: अपेक्षित सात channels की स्पष्ट सूची `HUFL, HULL, MUFL, MULL, LUFL, LULL, OT` होगी। Timestamp input feature नहीं होगा। सभी सात channels से सभी सात का forecast होगा; `OT`-only task नहीं। Schema असंगत मिलने पर mapping पहले लिखित रूप में तय होगी।

## 3. मुख्य configuration matrix
| घटक | पूर्वनिर्धारित विकल्प |
|---|---|
| Input context | 768 samples = 8 दिन, हर period और horizon पर समान |
| Period grid | 24, 48, 96, 192 samples |
| Reference | 96 samples; यह दैनिक-cycle hypothesis पर चुना गया है, official default नहीं |
| Forecast horizons | 96, 192, 336, 720 samples |
| Random seeds | 17, 29, 43; सभी configurations में paired |
| Task | सात-channel multivariate-to-multivariate forecasting |
| Fits | 4 periods × 4 horizons × 3 seeds = **48** |

Context 768 सभी मुख्य periods से विभाजित होता है; इसलिए period-fold padding का एक संभावित confound घटता है। Grid daily cycle के नीचे, उस पर और ऊपर settings देता है। यह exhaustive optimum search नहीं है। प्रत्येक horizon का अलग model train होगा। Reference के 12 fits इन 48 में शामिल हैं, अतिरिक्त नहीं।

**यदि native semantics अनिवार्य multi-period list हो:** branch count `K` को चुने गए implementation की documented executable configuration से लें और experiment freeze से पहले दर्ज करें। Entry 0 को sweep करें: `P(p)=[p,b₁,…,bₖ₋₁]`; शेष entries उसी configuration के मानों और उसी क्रम में स्थिर रहें। Reference `P(96)` होगा। List को sort, deduplicate या उसकी लंबाई बदलना निषिद्ध होगा। यदि executable configuration में period values नहीं मिलतीं, पूर्वनिर्धारित fallback `bⱼ=384×2^(j−1)` samples होगा; fold-padding/feasibility की जाँच अनिवार्य होगी। Duplicate values यदि native configuration से आती हैं तो सभी arms की वैधता जाँचें; असमर्थित होने पर उन्हें silently ठीक न करें—fallback anchors को पूरे sweep के लिए समान रूप से अपनाकर protocol freeze करें। यह सूची-policy चार configurations और **48 fits** ही रखती है, लेकिन इसका estimand “स्थिर अन्य branches के साथ पहली branch का period” होगा। Scalar और list परिणाम परस्पर interchangeable नहीं होंगे।

- Validation: `[34560, 46080)` = अगले 4 nominal months।
- Test: `[46080, 57600)` = अगले 4 nominal months।
- अतिरिक्त rows इस अध्ययन में नहीं; 57600 से कम rows होने पर इस protocol को executable न मानें, revised split पूर्वघोषित करें।

Forecast origin `t` पर input `[t−768,t)` और target `[t,t+H)` होगा। Stride 1 रखें। Train origins `768 ≤ t ≤ 34560−H`; validation origins `34560 ≤ t ≤ 46080−H`; test origins `46080 ≤ t ≤ 57600−H`। Target कभी अपने split से बाहर नहीं जाएगा। Validation/test inputs में पहले split की उपलब्ध history वैध है। Test के भीतर rolling origins पर पूर्व में देखे गए वास्तविक observations input में आएँगे; कोई online weight update नहीं होगा। यह rolling-origin, full-horizon forecast evaluation है, एक ही स्थिर origin से पूरे test interval का forecast नहीं।

प्रति-channel mean और standard deviation केवल train rows पर fit हों; उन्हीं से सभी splits transform हों। Validation/test से scaler, period selection या optimizer update नहीं होगा।

## 5. साझा training और architecture policy
**Period के अलावा स्थिर:** context, target channels, data windows/order, horizon के भीतर architecture, branch count, width/depth, patch policy, dropout, optimizer, scheduler, effective batch size और epoch count। Horizon बदलने से output head बदल सकता है; तुलना इसलिए प्रत्येक horizon के भीतर होगी।

प्रस्तावित साझा architecture knobs, जहाँ PDF implementation उनका समर्थन करे: hidden width 128, feed-forward width 256, 3 encoder blocks, 8 attention heads और dropout 0.1। Period-axis patching उपलब्ध हो तो patch length 8 और stride 8 रखें—मुख्य scalar grid के सभी periods इससे विभाज्य हैं। Model-specific decomposition, normalization और fusion options के लिए चुने गए implementation की एक executable base configuration freeze करें; exact commit, पूरी resolved config तथा unsupported knob mapping दर्ज करें। बिना source के layer topology बनाना उचित नहीं होगा। ऐसे शेष implementation-specific विकल्प केवल shape smoke test से तय हों, validation/test accuracy से नहीं। सभी arms में समान policy लागू हो।

Training recipe:
- Loss: standardized seven-channel mean squared error।
- AdamW, initial learning rate `1e−3`, weight decay `1e−4`, gradient clipping norm 1.0।
- 20 पूर्ण epochs, कोई early termination नहीं; epochs 1–2 linear warm-up, फिर cosine decay से `1e−5` तक।
- Effective batch size 32। Memory के कारण microbatch घटाने पर gradient accumulation से 32 बनाए रखें और सभी arms के लिए समान microbatch policy चुनें। अंतिम अधूरा batch रखें।
- FP32; सभी arms पर एक hardware/software stack और deterministic execution जहाँ समर्थित हो।
- प्रत्येक epoch के बाद पूर्ण validation MSE। सबसे कम validation MSE वाला checkpoint चुनें; tie पर सबसे पहला epoch। Test इस चयन में शामिल नहीं।
- प्रत्येक fit fresh initialization से। Seed model initialization, dropout और data shuffling को नियंत्रित करे। Training window permutation paired हो; भिन्न parameter shapes में identical initialization का दावा नहीं होगा।

20 epochs का budget जानबूझकर समान है; यह convergence की गारंटी नहीं। Training/validation curves से undertraining की सीमा रिपोर्ट करें। Per-period optimizer tuning मुख्य प्रयोग में नहीं होगी।

## 6. मूल्यांकन और विश्लेषण
**Primary metric:** train-standardized scale पर MSE। **Secondary:** उसी scale पर MAE। प्रत्येक model के लिए सभी valid forecast origins, सभी `H` lead positions और सातों channels को समान weight दें:
`MSE = mean_(origin,lead,channel) (prediction−target)²`; MAE इसी तरह absolute error का mean होगा। इससे overlapping windows में एक timestamp का अनेक lead positions पर योगदान जानबूझकर शामिल है; unit forecast case है, unique timestamp नहीं।

हर horizon पर रिपोर्ट करें:
1. चार settings के MSE/MAE, तीनों seeds के individual values, seed mean और sample SD।
2. हर non-reference period के paired अंतर `metric(p,s)−metric(96,s)`; negative बेहतर। इन तीन अंतरों का mean और SD तथा percent difference relative to reference भी दें।
3. प्रति-channel और lead-wise diagnostic curves अलग रखें; इनमें cherry-picking से मुख्य निष्कर्ष न बदलें।
4. Parameter count, training time, inference latency और peak memory के साथ error–cost trade-off दिखाएँ।

Test से पहले grid, checkpoints और analysis freeze हों। Validation-mean MSE से प्रति-horizon preferred period चुनना हो तो tie पर 96, फिर छोटा numerical period लें; test पर उस पहले चुने हुए period का प्रदर्शन दें। पूरे predefined test sweep को भी दिखाएँ, लेकिन test-best setting को deployable tuned winner न कहें। Horizons को primary analysis में अलग रखें; कोई supplementary across-horizon summary हो तो प्रत्येक horizon को समान weight और स्पष्ट label दें।

**निर्भरता और अनिश्चितता:** तीन seeds पर मजबूत significance, generalization या “statistically proven best” दावे नहीं। Seed SD confidence interval नहीं है। वैकल्पिक descriptive uncertainty के लिए प्रति-origin loss को leads/channels पर average करके paired period-minus-reference loss series बनाएं। समान sampled origin blocks सभी settings और seeds पर लागू करते हुए moving-block bootstrap करें: block length 768 origins, 2000 replicates; 1536-origin blocks से robustness जाँचें। फिर तीन seeds के differences average करें। यह temporal variation conditional on इन्हीं seeds को दर्शाता है; training-seed population की विश्वसनीय uncertainty नहीं। Overlapping windows को IID मानकर standard errors या t-tests न निकालें। कम स्वतंत्र blocks और अनेक comparisons की सीमा लिखें; confirmatory p-value claims न करें।
