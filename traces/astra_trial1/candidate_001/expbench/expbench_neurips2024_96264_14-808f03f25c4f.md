### 2. प्रस्तावित algorithm और rationale
```python
def sort_words(words):
    ordered = sorted(words, key=str.lower)
    return " ".join(ordered)
```
अंग्रेज़ी अक्षरों के घोषित दायरे में `lower` case-insensitive comparison key देता है। Python का `sorted` stable है, इसलिए समान keys वाले शब्दों का मूल सापेक्ष क्रम बना रहता है। Comparison के लिए key उपयोग होती है, output में मूल शब्द रहते हैं। नई sorted सूची बनाने से input नहीं बदलता और duplicates नहीं हटते। `join` ठीक एक separator space लगाता है और खाली सूची को खाली string बनाता है।

| ID | उद्देश्य | Input | अपेक्षित output: प्रस्तावित oracle |
|---|---|---|---|
| T1 | सामान्य अव्यवस्थित सूची | `["pear", "apple", "banana"]` | `"apple banana pear"` |

### 4. नियंत्रण और परीक्षण-विधि
- **Order नियंत्रण:** T2 baseline है; T1 और T3 उसी शब्द-संग्रह के permutations हैं। इनके outputs समान होने चाहिए क्योंकि अलग शब्दों की keys अलग हैं।
- **Stable-tie नियंत्रण:** T9 और T10 एक ही शब्द-संग्रह के permutations हैं, लेकिन outputs समान होने की माँग नहीं है। प्रत्येक में `apple` key वाले शब्द उसी input के सापेक्ष क्रम में रहने चाहिए।
- **Boundary नियंत्रण:** T6 और T7 क्रमबद्ध करने योग्य अनेक शब्दों के बिना joining और empty handling जाँचते हैं। T5 duplicate हटाने की त्रुटि पकड़ता है।
- **जाँच-संवेदनशीलता:** T1 के oracle की जगह `"pear apple banana"` मानने पर exact-match/order checks विफल होने चाहिए; `"apple  banana pear"` पर formatting check और T5 में एक `pear` हटाने पर conservation check विफल होना चाहिए। ये जानबूझकर गलत fixtures हैं, प्रोग्राम के देखे गए outputs नहीं।

### 5. प्रत्येक परीक्षण की जाँच
1. **Exact match:** परिणाम `str` हो और तालिका के प्रस्तावित oracle से अक्षरशः बराबर हो।
2. **शब्द-संरक्षण:** खाली output के लिए tokens `[]`, अन्यथा `output.split(" ")` लें। `collections.Counter(tokens) == collections.Counter(input)` हो। इससे spelling, multiplicity और शब्दों का संरक्षण जाँचा जाएगा।
3. **क्रम:** हर adjacent token जोड़ी के लिए पहले की lowercase key दूसरी से बड़ी न हो।
4. **Stable ties:** प्रत्येक lowercase key के लिए input और output में उस key वाले मूल-spelling tokens की subsequence समान हो।
5. **Format:** non-empty input पर कोई empty token न हो; केवल सामान्य single spaces separator हों; leading/trailing whitespace, tabs और line breaks अनुपस्थित हों। `n` शब्दों पर spaces की संख्या `n-1` हो। Empty input का output ठीक `""` हो।
6. **Input संरक्षण:** call से पहले ली गई सूची की copy से call के बाद input सूची बराबर हो।

**स्वीकृति मानदंड:** T1–T10 सभी निर्धारित परीक्षणों में exact-match सहित सभी लागू checks पास हों; permutation और stable-tie नियंत्रण संतुष्ट हों, और जानबूझकर गलत fixtures संबंधित checks से अस्वीकृत हों। किसी एक की विफलता पर implementation को इस contract के लिए स्वीकार न करें। सभी पास होना घोषित दायरे का प्रमाण होगा, गैर-अंग्रेज़ी या invalid inputs की correctness का नहीं।

### 6. व्यवहार्यता और रिपोर्टिंग
Standard Python में साधारण assertions या `unittest` तथा `collections.Counter` पर्याप्त हैं। किसी अतिरिक्त dependency, dataset, network या GPU की आवश्यकता नहीं है। केवल दस छोटे cases और कुछ गलत fixtures के लिए CPU और memory लागत नगण्य रहने की अपेक्षा है; कोई मापा performance दावा नहीं किया जा रहा है। Sorting सामान्यतः `O(n log n)` comparisons लेगी, जिनकी लागत शब्दों की लंबाई पर निर्भर है; joining कुल output लंबाई के अनुपात में होगी। नई सूची, keys और output के लिए अतिरिक्त memory लगेगी।

यदि बाद में परीक्षण चलाए जाएँ, रिपोर्ट में Python version, प्रत्येक test का expected और actual output (`repr` रूप में), pass/fail और विफल invariant दर्ज करें। अभी ऐसी कोई result रिपोर्ट उपलब्ध नहीं है।
