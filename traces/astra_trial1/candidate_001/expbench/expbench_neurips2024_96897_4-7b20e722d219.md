# अंतिम experiment design

यह **प्रस्तावित protocol है, निष्पादित प्रयोग नहीं**। Brief केवल वैज्ञानिक प्रश्न और design-only सीमा तय करता है। नीचे model, BAdam व्यवहार, budgets और निर्णय-सीमाएं मेरे चुने हुए defaults हैं; इन्हें स्रोत की मंशा या सत्यापित BAdam implementation नहीं माना जाए।

## 1. प्रश्न, estimands और scope

प्राथमिक perturbation प्रत्येक trainable matrix के लिए **ΔWₘ(t)=Wₘ(t)−Wₘ(0)** होगा। प्राथमिक comparison समान tokens देख चुके, paired BAdam और **Adam** runs का होगा। AdamW का उपयोग नहीं होगा; दोनों में weight decay शून्य रहेगा।

दो अलग endpoints होंगे:
- ΔW के singular-value tail में heavy-tail के अनुकूल प्रमाण। यह finite-dimensional spectrum का दावा होगा, किसी asymptotic distribution का प्रमाण नहीं।
- Entropy effective rank में optimizer equivalence: pᵢ=σᵢ/Σσⱼ; r_eff=exp(−Σpᵢ log pᵢ)। शून्य singular values का योगदान शून्य होगा।

स्थानीय task के प्रश्न में ‘various modules’ है, सभी architectures नहीं। Core से निष्कर्ष केवल चुने हुए model, data, modules और training horizon तक सीमित होगा।

## 2. सीमित-संसाधन core

**Model/data:** प्रस्तावित `EleutherAI/pythia-70m`, pretrained final checkpoint की pinned revision; `WikiText-103` का raw-v1 configuration, pinned dataset/tokenizer versions। सभी parameters trainable रहेंगे—कोई LoRA, adapter या quantized finetuning नहीं। Training split से deterministic packing द्वारा 512-token causal-LM sequences; documents के बीच EOS। Validation केवल tuning/quality monitoring के लिए, test split optimizer चयन में नहीं।

अपेक्षित architecture छह decoder layers है; downloaded configuration, parameter shapes और tied weights का inventory भविष्य में सत्यापित होगा। अपेक्षा गलत निकलने पर protocol पहले संशोधित होगा, परिणाम देखने के बाद नहीं।

**Budget:** प्रत्येक final run में 840 optimizer steps, effective batch 8 sequences, अर्थात **3,440,640 input tokens**। Microbatch 2 और accumulation 4 default हैं; memory के लिए बदलने पर effective batch और tokens स्थिर रहेंगे। पांच paired seeds: 11, 22, 33, 44, 55। हर pair समान pretrained initialization, data order और stochastic seeds से शुरू होगा; अलग pairs में data-order/stochasticity बदलेगी। Token exposure समान होगा, parameter-wise update exposure नहीं।

**Checkpoints:** step 0, 70, 210, 420, 840: baseline, early, mid और late snapshots। Step 840 confirmatory endpoint; अन्य checkpoints trajectory evidence होंगे। अंतिम cycle में steps 771–777 और 780, 790, 800, 810, 820, 830 पर selected perturbations भी सुरक्षित करेंगे, ताकि one-step और within-cycle phase effects स्पष्ट हों। ये secondary हैं, confirmatory tests बढ़ाने का माध्यम नहीं।

**Modules:** layers 0, 2, 5 में attention Q, K, V, output projection और MLP input/output projection—कुल 18 matrices। Fused QKV को architecture-सत्यापित row/head mapping से अलग करेंगे; naive contiguous slicing नहीं करेंगे। Matrix orientation केवल transpose तक standardize होगी, reshape करके कृत्रिम spectra नहीं बनाएंगे। Biases, normalization vectors और embeddings train होंगे, पर primary matrix panel में नहीं होंगे।

## 3. BAdam का स्पष्ट operational default

प्रस्तावित variant: **cyclic, layer-block Adam**। यह provisional operational definition है, verified reference BAdam नहीं।
- सात disjoint blocks: block 0 में token embeddings, final normalization और output head; blocks 1–6 में संबंधित decoder layer के सभी parameters। Tied embedding/head storage केवल एक बार assign होगा। Block sizes असमान होने का लेखा रखा जाएगा।
- निश्चित forward order 0→1→…→6; प्रत्येक block 10 optimizer steps active, फिर switch। एक cycle 70 steps; final run 12 पूर्ण cycles।
- Active block पर Adam update; β₁=0.9, β₂=0.999, ε=10⁻⁸। प्रत्येक parameter का bias-correction counter केवल उसके active updates पर बढ़ेगा।
- First/second moments inactivity में **retain और freeze** होंगे; inactive steps पर decay, reset या counter advance नहीं होगा। पहली activation से पहले moments शून्य। CPU offload अनुमत होगा, पर numerical semantics अपरिवर्तित रहेंगे।
- Inactive weights बिल्कुल अपरिवर्तित; कोई momentum-only update, decay या stale-gradient update नहीं। Gradients switch/step पर साफ होंगे। Frozen weights के पार activation gradients जहां आवश्यक हों वहां propagate होने चाहिए।

**अनिवार्य verification gate:** training से पहले वास्तविक BAdam reference paper/code और pinned commit से partition, order, interval, moments, counters, gradient handling और inactive weights का मिलान करें। मेल नहीं हुआ तो इस variant को ‘proposed cyclic block-Adam’ कहा जाएगा, BAdam पर definitive दावा नहीं। Researcher की सहमति से reference-faithful variant को नया primary बनाना हो तो पहले protocol amendment होगा।

Adam सभी parameters हर step update करेगा, वही β/ε और zero decay। BAdam में हर block को final checkpoint तक 120 active updates, Adam में प्रत्येक parameter को 840 मिलेंगे। हर snapshot पर block phase, last-active step, cumulative active updates, moment-counter और active learning rates log होंगे। यह अंतर algorithm का हिस्सा है; इसे छिपाकर ‘समान updates’ नहीं कहेंगे।

## 4. निष्पक्ष settings और tuning

- Shared causal-LM loss, sequence packing, effective batch, tokenizer, data stream, validation schedule और trainable parameter set। दोनों में dropout शून्य default; अन्य stochastic operations समान configuration पर।
- FP32 master parameters और optimizer states; supported GPU पर BF16 forward/backward दोनों में समान। FP32 fallback दोनों पर लागू होगा। Checkpoints में master weights, न कि rounded BF16 copies, सुरक्षित होंगे।
- Linear warmup 70 steps, फिर constant global learning rate। Global schedule inactive blocks को भी calendar time में पार करेगा; वास्तविक block-wise rates log होंगे।
- Primary में gradient clipping disabled, ताकि active-gradient subset बनाम full-gradient norm से अतिरिक्त confound न आए। NaN/divergence trial failure होगा, चुपचाप clipping नहीं जोड़ेंगे।
- प्रत्येक optimizer के लिए समान तीन learning rates: 1e−5, 3e−5, 1e−4; एक अलग tuning seed 101, प्रत्येक trial 210 steps। समान fixed validation subset पर अंतिम token-averaged NLL से चयन, exact tie में छोटा LR। Validation subset का token count और hash pinned होंगे। चयनित LR पांच final seeds में स्थिर रहेगा।
- यदि किसी optimizer के सभी trials अस्थिर हों, primary comparison रुकेगा; दोनों के लिए समान संशोधित grid की पूर्व-घोषणा होगी।

यह छोटा tuning budget practicality का समझौता है, globally optimal hyperparameters की गारंटी नहीं। Validation loss, ΔW Frobenius norm और training loss साथ दिखाएंगे, ताकि समान effective rank को समान learning quality न समझा जाए। Equal-compute और quality-matched comparison optional होंगे, primary नहीं।

## 5. Spectrum extraction और numerical controls

सभी चयनित matrices के **पूर्ण singular spectra** चाहिए; randomized/truncated SVD primary entropy rank या tail testing के लिए नहीं। FP32 master weights को FP64 में cast करके subtraction और SVD करेंगे; इससे अतिरिक्त subtraction rounding घटेगी, पर training में खोई precision वापस नहीं आएगी।

Checks:
1. Step 0 पर ΔW शून्य; inactive block के consecutive steps में exact parameter equality; active update और state counters की tiny deterministic fixture पर जांच।
2. Σσᵢ² और ||ΔW||²_F का relative discrepancy 1e−8 के भीतर; चुने हुए matrices पर alternate SVD routine, reconstruction residual और effective-rank agreement की जांच। Threshold न मिले तो numerical endpoint pending रहेगा।
3. Numerical-zero tolerance τ=max(m,n)·ε_FP64·σ_max; sensitivity में 10τ, 100τ तथा saved-weight quantization-scale पर प्रभाव दिखाएंगे। Entropy primary में solver के सभी nonnegative singular values से निकलेगी; tiny-value thresholding अलग sensitivity होगी।
4. Exact-zero ΔW के लिए entropy rank **undefined/zero-update flag**, न कि मनमाना rank=1। Near-zero ΔW के साथ norm और sensitivity warning। ऐसे endpoints हटाकर सकारात्मक summary नहीं बनाएंगे।

साथ में r_eff/min(m,n), energy-weighted entropy rank और stable rank=||ΔW||²_F/||ΔW||²₂ रिपोर्ट होंगे; केवल पहला entropy definition confirmatory है।

## 6. Heavy-tail analysis: फिट, calibration और निर्णय

Primary variable **σ**, न कि eigenvalue σ²। Scale normalization σ/σ_max fitting stability के लिए होगी; यह tail shape नहीं बदलती।

**Cutoff और size:** प्रत्येक spectrum के positive numerical singular values पर candidate lower cutoffs scan होंगे। Candidate tail में कम-से-कम max(64, ceil(0.10·min(m,n))) observations और tail max/min अनुपात कम-से-कम 5 आवश्यक होगा। उम्मीदवार cutoffs में fitted Pareto के KS discrepancy को न्यूनतम करने वाला चुनेंगे। ये conservative practical thresholds हैं, कोई universal theorem नहीं। पर्याप्त tail न मिले तो ‘inconclusive’।

**Candidates:** समान cutoff/support पर continuous Pareto, lognormal, exponential और exponentially truncated Pareto के likelihood fits। Cutoff selection, likelihood, KS distance, tail size, exponent और uncertainty सभी दर्ज होंगे। Candidate-comparison scores likelihood/AIC आधारित होंगे; formal iid likelihood-ratio p-values निर्णायक नहीं होंगे। आसपास के admissible cutoffs, जैसे selected cutoff के ऊपर/नीचे लगभग 10% tail-count बदलाव, पर conclusion stability आवश्यक होगी। Truncated Pareto का स्पष्ट वर्चस्व केवल ‘truncated heavy-tail-like’ कहलाएगा, untruncated heavy-tail support नहीं। Lognormal को power law नहीं कहा जाएगा।

**Calibration:** shape-matched synthetic matrices में (a) iid Gaussian, (b) correlated Gaussian, (c) variance-profile Gaussian और (d) known finite-variance Pareto-tailed singular values को random orthogonal factors से बनाया गया positive control शामिल होगा। Norm scaling real perturbations के समान होगी। Gaussian controls में dimensions/aspect ratios और कुछ condition-number regimes बदलेंगे। प्रत्येक scenario/unique shape के कम-से-कम 200 replicates पर **पूरा cutoff-selection-plus-fitting pipeline** दोहराएंगे; 200 अतिरिक्त independent replicates calibration validation के लिए। पहले controls पर thresholds lock होंगे, real optimizer labels खोलने के बाद नहीं।

Tail-support score को best Pareto/lognormal fit बनाम exponential fit के improvement से बनाएंगे। Light-tail controls पर 18-module panel के maximum score से family-wise 5% target का conservative threshold तय करेंगे; synthetic nulls की uncertainty भी रिपोर्ट होगी। Absolute fit discrepancy को fitted positive-control simulations से contextualize करेंगे। किसी shape पर false-positive calibration या positive-control detection अपर्याप्त हो तो उस shape को inconclusive रखेंगे, threshold ढीला नहीं करेंगे। यह synthetic null class के भीतर calibration है—वास्तविक dependent spectrum के लिए distribution-free guarantee नहीं।

**Per-run support:** admissible tail + calibrated score threshold पार + acceptable discrepancy + cutoff stability + truncated alternative का स्पष्ट वर्चस्व न होना। किसी module के लिए ≥4/5 seeds में यह pattern हो तो ‘finite-spectrum heavy-tail support’; अन्यथा mixed/inconclusive। यह 4/5 rule consistency criterion है, independent binomial significance test नहीं। Clear light-tail evidence केवल तब कहेंगे जब calibrated controls उस regime में पर्याप्त discrimination दिखाएं और exponential लगातार बेहतर हो।

Singular values को iid observations मानकर bootstrap confidence को निर्णायक प्रमाण नहीं बनाएंगे। Parametric iid bootstrap, यदि दिखाया जाए, diagnostic sensitivity होगा। Replication वास्तविक training seeds से आएगी; layers और checkpoints independent samples नहीं हैं। Adam के spectra पर भी बिल्कुल यही pipeline लागू होगी।

## 7. Effective-rank equivalence और precision

हर primary module और seed के लिए d=log[r_eff(BAdam)/r_eff(Adam)]। प्रस्तावित equivalence interval **[1/1.10, 1.10]**, अर्थात |d|<log(1.10)। Rationale: effective dimensionality में लगभग 10% से बड़ा बदलाव practically meaningful मानना; यह literature-derived सीमा नहीं है। 5% और 20% margins केवल sensitivity summaries होंगे।

- पांच paired seed differences पर mean log-ratio और confidence interval। Primary TOST paired-t model, α=0.05। 18 module equivalence hypotheses में प्रत्येक का TOST p=max(two one-sided p-values), फिर Holm correction।
- Equivalence तभी जब corrected tests margin के भीतर होने को support करें। Difference non-significant होना equivalence नहीं। Wide intervals, zero-update endpoints या model-assumption fragility → inconclusive।
- Assumption: seeds स्वतंत्र हैं और paired log-ratios लगभग normal हैं। पांच seeds में normality जांच कमजोर होगी; सभी individual values और leave-one-seed-out sensitivity दिखाएंगे। स्पष्ट skew/outlier sensitivity में confirmatory claim रोकेंगे और अधिक seeds वाला expansion सुझाएंगे; पांच seeds का naive bootstrap इस कमी को नहीं सुलझाएगा।
- Earlier checkpoints descriptive paired intervals होंगे, कोई confirmatory ‘किसी भी checkpoint पर significance’ खोज नहीं। भविष्य में उन्हें confirmatory बनाने पर enlarged multiplicity family पहले तय होगी।

## 8. संयुक्त प्रश्न का पूर्वनिर्धारित उत्तर

एक 18-row module table में BAdam tail status, Adam tail status, equivalence status, rank ratio interval, perturbation norm और seed consistency देंगे।

**Core panel के लिए affirmative उत्तर** तभी: final checkpoint पर सभी 18 modules में BAdam heavy-tail support और rank equivalence दोनों। Adam का अपना heavy-tail status अलग स्पष्ट होगा; ‘दोनों optimizers heavy-tailed’ तभी कहेंगे जब दोनों इस criterion पर खरे उतरें। Earlier trajectories व्यापक विपरीत pattern दिखाएं तो दावा केवल final horizon तक सीमित रहेगा, ‘पूरे finetuning के दौरान’ नहीं।

यदि कुछ modules ही दोनों criteria पूरा करें, उत्तर ‘module-dependent’; नाम और depth के साथ। किसी में convincing non-equivalence या light-tail evidence हो तो uniform claim समर्थित नहीं। यदि कमी मुख्यतः low precision/tail size है, उत्तर ‘inconclusive’, न कि ‘BAdam विफल’। Pooled mean किसी स्थानीय असहमति को नहीं छिपाएगा।
