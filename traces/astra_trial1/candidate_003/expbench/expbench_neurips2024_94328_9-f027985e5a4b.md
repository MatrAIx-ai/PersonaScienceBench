Входы fused QKV или gate/up квантовать один раз на общий вход, не независимо для каждой части. Не квантовать residual stream, attention probabilities и выходы каждого оператора просто на основании их существования: обозначение Ab относится к указанным входам GEMM.

### Коды и масштабы — общие для RTN/GPTQ
Использовать симметричную signed-сетку с нулевым zero-point: qmax=2^(b−1)−1, q∈[−qmax,qmax]. Диапазоны: [−7,7], [−31,31], [−127,127]; самый отрицательный код стандартного signed INTb не используется. Для группы s=max|x|/qmax; полностью нулевая группа отображается в ноль без деления. Quantize: round-to-nearest, ties-to-even, затем saturation; dequantize: s·q. Масштабы вычислять и хранить в FP32.

* **W:** по каждой выходной строке, непрерывные группы из 128 входных координат; последнюю неполную группу не дополнять фиктивными значениями. Масштабы определять по исходному для этого режима, уже преобразованному весу. Не применять percentile clipping, scale search или MSE clipping. Сетка весов одинакова для RTN и GPTQ и не переоценивается после GPTQ error feedback.
* **A:** динамический absmax per token по всей входной ширине данного линейного оператора; без статической калибровки, clipping search и группировки между токенами.
* **KV:** независимые динамические absmax масштабы K и V per layer, token, KV-head, по группам до 128 координат внутри головы; неполная последняя группа допустима. Масштабы не объединять между токенами или головами.

Единственный clipping — saturation на границах описанной сетки. Для GPTQ saturation возможен после компенсации ошибки; исходные scales остаются фиксированными. Этот выбор намеренно убирает скрытый подбор clipping как дополнительную переменную. Он не претендует на оптимальные настройки каждого метода.

### Точность
Модель и сохранённые неквантованные тензоры — BF16. Dequantized операнды приводить к BF16; накопление matmul — FP32 с BF16 выходом. Нормы (включая вычисление дисперсии), RoPE, softmax, reduction, GPTQ-статистики и NLL вычислять в FP32; результаты возвращать в BF16 там, где они входят в основной forward. Проверить, что выбранный backend действительно реализует этот контракт; отключить TF32 и недетерминированные альтернативы в reference-проверках. Не заявлять целочисленное выполнение или экономию памяти для эмуляции.

### GPTQ
Предлагаемый вариант: Hessian/Gram из входов соответствующего линейного оператора, FP32; damping λ=0,01·mean(diag(H)); размер блока error feedback — 128 входных колонок; act-order выключен; фиксированный естественный порядок колонок; группы весов 128, как у RTN. Мёртвые входные направления обрабатывать явным правилом GPTQ: нулевой Hessian diagonal заменять на 1 и соответствующие неактивные колонки занулять; случаи логировать. Если factorization не проходит после damping, прекращать данную конфигурацию, не менять damping незаметно.

Калибровать последовательно по decoder-блокам, обрабатывая QKV, attention output, gate/up, down в фактическом порядке графа. Для операторов текущего блока собирать входы с активными ранее квантованными операторами; A/KV fake quant соответствует оцениваемому режиму. Fused-проекции с общим входом используют одну входную статистику. Сохранить точный алгоритм обхода и adapter commit. RTN — непосредственное округление на той же сетке без Hessian и компенсации ошибки.

## 5. Как считаются метрики и реально используется KV
### PPL
На C4 и WikiText не добавлять BOS/EOS автоматически, не использовать chat wrapper. В каждом независимом блоке сбросить cache и position ids. Для токенов x₁…xL учитывать log p(xₜ|x₁…xₜ₋₁) при t=2…L; первый токен и padding не оценивать. Итог: exp(суммарный NLL / число оценённых токенов), не среднее PPL блоков. Публиковать и token count, и mean NLL.

**KV-квантование должно участвовать в каждом attention forward:** после вычисления K/V и необходимых преобразований записывать именно quantized codes/scales; attention читает только их dequantized значения. Для K выбранная точка — после RoPE и согласованного Q/K-преобразования, для V — после согласованного V-преобразования. Это относится и к текущему токену/блоку, а не только к ранее сохранённому cache. Не допускается BF16 fast path для prefill, который обходит KV-квантование.

Практический reference-режим — последовательный decoding с teacher forcing. Для основной оценки допустим ускоренный **causal chunked prefill** с блоками 256 токенов: K/V всего нового блока квантовать до attention, текущие и предыдущие токены читать только из dequantized cache, использовать точную causal mask. Per-token scales не зависят от будущих токенов, поэтому такой путь должен совпадать с последовательным в пределах точности. Реализация может хранить dequantized представление вместо packed codes, но только после обязательного Q→DQ bottleneck, без доступа attention к исходным K/V.

### Zero-shot
Использовать полный стандартный evaluation split каждого задания через фиксированную ревизию lm-evaluation-harness, num_fewshot=0. Шаблоны — штатные текстовые likelihood-шаблоны соответствующих задач данной ревизии, **без chat wrapper**, system prompt и примеров. Сохранить итоговые rendered prompts и правила whitespace/разделителей. Это оценка instruct-модели в унифицированном completion-протоколе, а не оценка оптимального chat prompting.

| Задание | Split | Основная метрика |
|---|---|---|
| HellaSwag | validation | acc_norm |
| PIQA | validation | acc |
| WinoGrande | validation | acc |
| ARC-Easy | test | acc_norm |
| ARC-Challenge | test | acc_norm |
| BoolQ | validation | acc |

Для acc_norm использовать именно length-normalization из зафиксированной task definition, сохранив её формулу/единицу длины; для acc — штатное ненормализованное правило. Сравнивать likelihood вариантов, без sampling/generation. При равенстве scores выбирать вариант с меньшим индексом. Общая метрика — невзвешенное среднее шести указанных accuracy; не смешивать её с accuracy по объединению всех примеров.

Context каждой задачи prefilling проходит через тот же квантованный KV-путь. Перед scoring вариантов клонировать именно полученный quantized cache; у каждой continuation независимая ветвь. K/V каждого токена варианта тоже квантовать до attention. Если harness считает context+continuation за один forward, заменить его attention/cache-путь эквивалентным chunked вариантом; обычного неквантованного prefill недостаточно. Проверить корректность границ токенизации context/continuation штатным harness-кодом. При превышении 4096 сохранить вариант ответа целиком и обрезать context слева; зафиксировать число таких случаев, правило одинаково для всех моделей.

## 6. Перенос QuaRot: карта преобразований и критерии допуска
До оценки качества исследовать реальный config и forward выбранного checkpoint. Проверить типы норм, размеры hidden/intermediate/head, число Q/KV-heads, наличие fused QKV и gate/up, RoPE, biases, tying embedding/lm_head и residual topology. Нельзя переносить LLAMA-имена модулей механически.

**Карта согласованных вращений** должна содержать исходный тензор, ось, преобразование, компенсирующий оператор, точку quantization и проверку эквивалентности:

1. **Residual basis R:** embedding выводит hR. Для row-vector записи линейного оператора hM переход между базисами задаётся M′=Rinᵀ M Rout. Attention/MLP выходы и skip-ветви должны возвращаться в один и тот же residual basis; lm_head компенсирует R. Bias также преобразуется при смене выходного базиса.
2. **Нормы:** folding обучаемых gains и перенос R разрешён только при доказанной совместимости конкретной нормы. RMSNorm и LayerNorm нельзя считать взаимозаменяемыми. Tied weights не разрывать незаметно: либо сохранить математически согласованное представление, либо явно материализовать эквивалентные тензоры и отразить это в манифесте.
3. **MLP:** общий вход gate/up согласуется с R, но произвольное вращение не проходит через elementwise gating/нелинейность. Online Hadamard помещать после gated product, до down, с обратной компенсацией в down.
4. **Attention V/O:** вращение внутри каждой V-головы компенсировать в соответствующей части O после concat heads. При GQA применять согласованное отображение повторяемых KV-голов в Q-heads.
5. **Q/K:** одинаковое ортогональное преобразование Q и K внутри сопоставленных голов сохраняет dot products. Выполнять его после RoPE, не предполагая, что оно коммутирует с RoPE; тогда cached K уже находится в нужном базисе. Проверить масштабирование scores и head mapping.

Использовать нормированные Hadamard-преобразования с детерминированными случайными знаками по seed там, где они допустимы в выбранном QuaRot adapter. Для неподдерживаемых размеров сначала проверить корректную факторизацию. Если её нет, остановить реализацию этой спецификации: generic orthogonal fallback допустим только как отдельно названный изменённый вариант, а не как незаметная подмена QuaRot. Математическая карта сама по себе не доказывает наличие готового adapter.

### Gates до основных запусков
* Unit tests ортогональности/обратимости в FP64: относительная Frobenius-ошибка <10⁻¹⁰; тесты fused slicing, biases, group tails, нулевых групп, saturation и допустимых кодов.
* FP32 исходная и вращённая без квантования на 16 фиксированных синтетических/калибровочных последовательностях длины 1, 17, 128 и 2048, плюс два окна 4096. При сравнении hidden states сначала вернуть общий базис. Относительная RMS-ошибка logits ≤10⁻⁴, max absolute error ≤10⁻², |Δmean NLL| ≤10⁻⁴ nat/token.
* BF16 gate на тех же текстах: относительная RMS-ошибка logits ≤10⁻² и |Δmean NLL| ≤0,01 nat/token. Это предварительно установленные инженерные допуски, не обещание точного побитового совпадения.
* Без квантования проверить cache/no-cache и full/chunked/одиночный decoding. С квантованием проверить chunked/одиночный decoding с тем же quantized KV: BF16 допуски выше; коды K/V для одного и того же входного тензора обязаны совпадать точно. Проверить reset, разные позиции, branching вариантов, отсутствие cross-example leakage.
* Инструментировать обращения attention: нет чтений исходного BF16 K/V в квантованном режиме. На контролируемом примере смена KV grid должна изменять attention-выход; отдельно сравнить Q→DQ с ручным reference. Считать saturation rate и nonfinite values.

**Стоп-критерий:** нарушение эквивалентности, NaN/Inf, неверный cache path или несовместимая карта преобразований блокирует запуск основной матрицы. Локализовать ошибку послойно и исправить её; не интерпретировать её как деградацию от квантования. Изменение допусков или алгоритма возможно только как документированная поправка протокола до получения основных результатов.

## 7. План анализа
Все сравнения парные на одних оценочных примерах и, где применимо, одинаковых seed.

1. **Потеря качества:** для каждой основной ячейки PPL, NLL, отношение PPL к BF16 baseline и разница accuracy в процентных пунктах. Вращённая неквантованная модель показывает численную цену преобразований; отдельно сравнить квантованную модель и с ней.
2. **GPTQ против RTN:** ΔNLL=NLL_GPTQ−NLL_RTN и Δaccuracy=accuracy_GPTQ−accuracy_RTN для каждого b. Меньший первый и больший второй означают преимущество GPTQ. Не предполагать знак заранее.
3. **Польза вращений:** QuaRot против no-rotation при b=4 отдельно внутри RTN и GPTQ. Это эффект выбранного полного пакета вращений при фиксированной сетке, не доказательство пользы каждого вращения по отдельности.
4. **Вклад A/KV:** W4A4KV4 против W4A16KV16; расширенные абляции уточняют разделение. Этот основной контраст измеряет совокупную добавочную потерю A/KV.

C4 — документы; WikiText — оценочные блоки, с оговоркой об остаточной зависимости между соседними блоками. В каждом resample пересчитывать NLL по сумме токенов, затем PPL. Для среднего эффекта одни и те же resampled indices использовать для всех seed. Эти 95% percentile intervals характеризуют вариацию **тестовой выборки условно на выбранных seed**, а не всю вариацию калибровки/вращения. Seed-разброс показывать отдельно. Не resample токены как независимые наблюдения.

Основные endpoint — WikiText PPL, C4 PPL и macro accuracy; отдельные задачи — диагностические. Главный вывод строить на величине эффектов и интервалах, не только на значимости. Если добавляются формальные тесты превосходства GPTQ, заранее применить Holm correction к девяти контрастам: 3 разрядности × 3 основных endpoint.
