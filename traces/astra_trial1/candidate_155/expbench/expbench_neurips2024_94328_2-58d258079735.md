# LLAMA2-7B 运行时裁剪与 PPL：最终实验设计

## 1. 要求、设计选择与研究目标
**来源已确认要求仅为**：LLAMA2-7B（`neurips2024/94328/2:setup_1`）、KV 非对称量化（`setup_10`）、PPL 指标（`setup_17`）；题目另要求输入对称量化。未查阅这些主题的原始全文，确认依据为研究者提供的信息。

**以下均是已获批准的拟议设计选择，不是已核实的原始设置**：输入/K/V 主条件均为 4 bit，权重 FP16，WikiText-2 raw 验证集选参、测试集报告，2048-token 上下文；所有目标输入、K 和 V 共用一个固定 r。8 bit 和 4096-token 上下文作为次要敏感性检查。r 是保留幅度／区间宽度系数，而不是被裁掉的元素比例。

目标是在明确的模型实现、数据、位宽、分组、上下文与搜索域下，得到 PPL—r 曲线，并选择接近验证集最优且不作多余裁剪的固定比例。不能预先给出最优数值，也不预设曲线单峰。

## 2. 模型和量化位置
采用 Llama-2-7b 基础模型而非 chat 变体，固定权重版本、配置、tokenizer、代码提交和依赖版本并记录校验值。关闭 dropout，使用 eval 模式和确定性设置。所有条件保持相同注意力实现、精度策略及运算路径；权重 FP16，量化参数、范围统计、RoPE 运算和评分统计使用 FP32，反量化结果转回模型计算 dtype。FP16 参考并非数学上的无限精度参考。

### 输入模块与分组
在每个 Transformer block 的以下线性层入口插入量化—反量化：
- `self_attn.q_proj`、`k_proj`、`v_proj`：对共享的归一化后输入只生成一次量化结果，供三个投影共同使用；
- `self_attn.o_proj`：对注意力输出在拼接 heads 后的输入量化；
- `mlp.gate_proj`、`up_proj`：对共享的归一化后输入只生成一次量化结果；
- `mlp.down_proj`：对 SiLU(gate) 与 up 分支乘积量化。

不在 embedding、RMSNorm 输出以外的其他位置、残差加法、softmax、RoPE 输入或 `lm_head` 额外插入输入量化。每个 token 的最后一维按连续 **128 元素**分组；尾组只用真实元素估计范围，不将 padding 纳入统计。若实现为打包而补齐尾组，补齐元素不参与计算和误差统计。模块列表与形状在初始化时导出，避免漏挂钩或重复量化。

### KV 位置与分组
K 在完成 RoPE 后、写入缓存前量化；V 在 v_proj 后、写入缓存前量化。K/V 各自按层、token、KV head 独立分组，组大小为一个 head 的维度，预期为 128，启动时依据模型配置核验。若配置不符则停止并修订清单，不静默改变设置。批量维不合并统计。Q 不作额外张量量化；其投影输入已按上述规则量化。

## 3. 比例与量化数学定义
统一定义 0<r≤1；r=1 无额外裁剪。每组范围在当前运行轨迹上即时计算，无校准集范围、无未来 token 统计。相同 r 不意味着相同绝对阈值或相同饱和率。

所有公式使用 FP32。`RNE` 表示四舍六入、恰好半整数时取偶数。检测到 NaN/Inf 时使该条件失败并记录，不用替换异常值掩盖问题。

### 对称输入量化
对组 x，a=max|x|，t=ra，y=clip(x,−t,t)。对 b bit，令 Q=2^(b−1)−1，整数范围为 [−Q,Q]（4 bit 使用 −7…7，保留 −8 不用；8 bit 同理为 −127…127）。
- a>0：s=t/Q，q=clip(RNE(y/s),−Q,Q)，反量化 x_hat=sq。
- a=0：输出精确零，约定 q=0、s=1。
- 非零常量输入组不特别跳过裁剪：仍按公式处理。

### 非对称 KV 量化
对组 x，l=min(min(x),0)，u=max(max(x),0)，c=(l+u)/2，h=r(u−l)/2：
- L_r=max(l,c−h)，U_r=min(u,c+h)；
- **先实际裁剪** y=clip(x,L_r,U_r)；
- 再定义含零量化包络 A=min(L_r,0)、B=max(U_r,0)。

令 M=2^b−1，整数范围 [0,M]：
- B>A 时，s=(B−A)/M，z=clip(RNE(−A/s),0,M)，q=clip(RNE(y/s)+z,0,M)，x_hat=s(q−z)。
- B=A 时，该组必为全零，约定 q=0、z=0、s=1，输出零。
- 非零常量组由于含零原始区间仍有正宽度，使用一般公式，不绕过裁剪。

包络扩展**不能取消 y 上已经发生的裁剪**。名义 r 不必等于 (B−A)/(u−l)，更不保证等于饱和比例；整数零点舍入还会平移实际可表示端点 [−zs,(M−z)s]。反量化后不再投影回 [L_r,U_r]。记录名义裁剪范围、包络、实际表示端点、宽度比和饱和率，以暴露这些差异。

“仅裁剪”条件直接使用上述 y，不做量化舍入；其 KV 缓存按模型浮点 dtype 存 y。

## 4. 缓存路径
采用因果 teacher forcing 的逐 token 前向路径，所有条件均禁用会自动维护另一份浮点 past_key_values 的旁路：
1. 当前 token 生成 K（RoPE 后）与 V。
2. 对新 token 的 K/V 分组统计、裁剪、量化。
3. 持久缓存保存整数码、每组 FP32 scale 和整数 zero-point；4 bit 可打包为两个码/字节，正确性优先的原型可先使用 uint8 容器，但必须如实说明非实际 4-bit 存储。
4. 注意力从该整数缓存读取并反量化，当前 token 也从同一路径读取；允许临时浮点反量化缓冲，但不得用保存的原始浮点 KV 代替。
5. 旧 token 的码、尺度和零点不可改变；不随新 token 重新估范围或重复量化旧缓存。

输入单独量化条件保持 KV 浮点缓存；KV 单独量化条件不插入任何输入量化。参考条件与仅裁剪条件也使用同一显式缓存推进路径，以减少实现混杂。

## 5. 数据与严格配对评分
固定 WikiText-2 raw 的具体发布版本与文件校验值。对每个 split，按原顺序用 `\n\n` 拼接所有原始 text 行，包括空行，不清洗、不去重；tokenizer 设 `add_special_tokens=False`。不插入 EOS，也不做逐文档 BOS。

对 token 流切分为不重叠、每段至多 C−1 个真实 token 的窗口，C=2048；每个窗口前添加一个 BOS，窗口之间清空所有层缓存、位置从零开始。最后不足窗口保留。每窗口总长度至多 C：BOS 不计分，每个真实 token 均计分一次，包括窗口第一个 token（由 BOS 预测）。不使用滑窗重复评分或跨窗口缓存。若批处理引入 padding，padding 不计分、不能进入缓存统计；首选单序列路径避免此复杂性。

对真实序列 t_1…t_m：用 BOS 的输出预测 t_1，然后仅输入真实前缀预测后续 token，不从模型采样；位置 j 不能看到 t_j 或未来 token。通过逐 token 路径实际复用缓存，不采用可能绕开缓存的整序列 loss 接口。计算 log-softmax 使用 FP32，累加 NLL 使用 FP64：NLL=总负对数似然/有效真实 token 数，PPL=exp(NLL)。记录每窗口 NLL 总和和 token 数。所有主条件使用同一分词缓存、窗口列表、有效 token 掩码及顺序。

## 6. 对照矩阵与诊断
主验证集对每个候选 r 运行：
- **R**：FP16 参考，无额外裁剪、无输入/KV 量化，只需运行一次；
- **C_joint(r)**：输入与 KV 都仅裁剪，不离散量化；
- **Q_joint(r)**：输入与 KV 都裁剪后量化；r=1 是必需的无额外裁剪量化基线；
- **Q_input(r)**：只对第 2 节所列输入模块量化及裁剪，KV 不作额外处理；
- **Q_KV(r)**：只对 K 和 V 量化及裁剪，输入保持参考路径。

单独量化条件对同一候选比例集合评测，不分别选择后再拼接成所谓“共同比例”。它们是定位作用来源与交互的对照，不改变主选参目标。

端到端主要报告 ΔNLL(C_joint−R)、ΔNLL(Q_joint−C_joint)、ΔNLL(Q_joint(r)−Q_joint(1))，并给出对应 PPL。这些差值描述实际运行轨迹上的变化，虽然 NLL 差值可代数相加，不能解释为相互独立、无交互的因果误差分量。

**共用参考张量诊断**：从高精度参考运行的验证集前 8 个窗口，以固定规则每隔 32 个 token 抽取目标输入与 K/V 的组，在线累计诊断，避免保存全部激活。对完全相同的 x 计算 y 和 x_hat：裁剪 MSE=mean((y−x)^2)，离散化 MSE=mean((x_hat−y)^2)，总 MSE=mean((x_hat−x)^2)，以及交叉项、归一化 MSE、饱和率、区间宽度和尺度。零能量组的归一化 MSE 标为不可定义，另报绝对 MSE。总 MSE 通常不等于前两项之和。按层、模块、K/V 分开汇总，禁止只挑有利层展示。该诊断固定输入分布，不能直接预测端到端 PPL，也不与 PPL 加权优化。

## 7. 扫描、细化、等效阈值和冻结
全部选参仅使用验证集 Q_joint：
1. 粗扫 {1,.99,.97,.95,.90,.85,.80,.70,.60}。
2. 若最小 r 是验证 NLL 最低点，向下按 .10 递减扩展，最低至 .10；若继续在 .10 最优，标记“搜索边界最优”，不宣称内点或全局最优。
3. 预先设实际近似等效阈值 **δ=0.001 nat/token**，对应约 0.10% 的相对 PPL 差异。它是本设计的精度容忍选择，不是来源事实。
4. 找出全部粗扫点中 NLL≤粗扫最小值+δ 的点，在它们与相邻已测点形成的区间内按 .01 网格细扫，并保留所有原点；不假定单峰。
5. 在细扫最小点及所有差距≤δ 的细扫点周围 ±.01 区间内，以 .002 网格再细化一次，截断到 [.10,1]。到此停止；不因测试结果追加比例。
6. 验证集经验最小点 r_min：NLL 精确平局时取较大 r。将 r_min 及每个较大 r 的配对 ΔNLL 作区块 bootstrap，构造同时的双侧 95% 区间。只有整个区间落在 [−δ,+δ] 内才视为统计上支持的实际等效；区间包含零本身不构成等效证据。最终 r* 取 r_min 与被判等效候选中最大的 r；若无候选满足则取 r_min。

同时报告经验最小 r_min 和按规则选择的 r*，避免把容忍范围内的较弱裁剪说成数值最优。细化是自适应选择，验证区间为选参支持而非无偏的性能保证；独立测试集才是冻结后的确认性报告。

## 8. 不确定性与测试集
将同一 split 的连续 **4 个评分窗口**组成不重叠区块，末尾不足 4 个仍保留。使用相同区块索引同时重采样所有条件，2000 次，有放回；随机种子固定为 94328。每次根据抽中的 NLL 总和与 token 总数重新计算 NLL、PPL 和差值，不平均窗口 PPL，不把相关 token 当独立观测。

选参中的同时区间可用 bootstrap 最大绝对中心化 ΔNLL 偏差的 95% 分位数作为共同半宽。测试报告配对差值的百分位 95% 区间，并在需要同时解释多项比较时另给同时区间。以 2 和 8 窗口区块重复不确定性估计作为依赖性检查，不据此改选比例。若区块数量很少或区块长度改变导致明显不稳定，明确说明区间不可靠；它们不覆盖模型实现、领域迁移或数据集选择不确定性。

冻结 r*、代码、数据处理和统计规则后，测试集仅报告 R，以及 r=1、r=r* 下的 C_joint、Q_joint、Q_input、Q_KV；重复条件合并。测试集不扫描、不重新选 r。

次要敏感性检查分别为：8 bit/C=2048，以及4 bit/C=4096，其他选择不变。先在各自验证集评估主 r* 的迁移，并按相同选参程序得到该配置的独立 r*_secondary，随后冻结再测各自测试集；明确区分“主比例迁移”和“重新调参”。4096 使用相同原始 token 流但重新切窗，因此与2048的差异同时包含上下文／窗口边界效应，不能称为纯量化效应。不要求额外执行8 bit/4096交叉条件。

## 9. 实现正确性与可行性闸门
正式评测前拟进行以下检查；本交付未执行它们：
- 人工小张量覆盖零组、正负常量、单侧区间、异常值、尾组、半整数舍入、r=1及强裁剪；核验码范围、含零包络、实际裁剪先后顺序与公式。
- 4-bit 打包／解包逐码精确往返，尾部 bit 不污染结果；读取只依赖整数缓存及元数据。
- 修改原始浮点 K/V 后，已写入缓存的输出不变；旧缓存校验和随新 token 写入保持不变。当前 token 同样不得绕过缓存。
- r=1 的仅裁剪结果应与参考一致（允许既定浮点路径的舍入容差）；自定义参考逐 token 输出与可信实现逐 token／因果整序列输出作小样本比较。建议 FP32 微型组件误差≤1e−6；FP16模型验证 NLL差≤1e−3 nat/token，超过时先诊断路径，不把实现差异当量化效果。
- 检查 RoPE 位置、因果性、BOS 对齐、有效 token 数、重置行为和所有模块调用次数；改变未来 token 不得改变早期预测。
- 每次输出运行清单、成功窗口数、异常记录和缓存存储 dtype；中途失败不选择性删除高损失窗口。

当前环境无 GPU、数据或预装依赖，不妨碍交付设计，但不支持声称已得到结果。后续需合法模型权重、对应 tokenizer、固定数据版本及支持的 PyTorch/模型库环境。FP16 7B 权重约需14 GB十进制显存；典型32层、32 heads、head维128配置下，2048长度的完整FP16 KV约1 GiB，4-bit码约0.25 GiB外加尺度/零点，4096约翻倍。临时反量化、激活、加载和框架工作区另占内存，因此单张24 GB GPU可能可行，32–48 GB更宽裕，须通过单窗口峰值内存核验后判断。建议主机内存32–64 GB并预留权重及输出磁盘空间；这些是条件性估计，不是资源申请或实测消耗。

逐 token 解码与大量比例扫描可能耗时显著；在批准执行后，可先计时一个窗口，再按有效 token 数和条件数量外推并预留余量。本设计不估造GPU小时，不以输入仿真或uint8容器宣称速度／内存加速。
