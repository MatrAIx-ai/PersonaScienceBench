## 3. 方法与共同训练协议

### 3.1 BAdam 的操作性定义和拟定实现

采用**块坐标 AdamW**：非活动参数冻结，每个优化步只更新一个活动块；长期轮换覆盖全部 decoder 层。它不等于每步全参数 AdamW，也不是低秩更新。

- 按模型原顺序将 decoder 层划为连续块；搜索每块 1 层或 2 层。执行前核对模型层数；若为标准 80 层，则对应 80 或 40 块。
- 块内 attention、MLP 权重及层内 norm 参数全部可更新；embedding、输出头和最后的层外 norm 固定。活动范围的差异是方法定义的一部分，不宣称与 LoRA 可训练参数量相等。
- 每个**优化器步**切换一次块，同一步所有梯度累积 microbatch 使用同一活动块。每轮块遍历使用种子控制的随机排列，下一轮重新排列；不要把 microbatch 当作轮换步。
- BF16 参数计算，FP32 Adam 一、二阶矩和 FP32 master 权重；非活动块状态保存在 CPU，并跨轮换保留，不重置、不在非活动时衰减。偏差修正计数按块实际更新次数；全局学习率按已处理训练 token 调度。
- AdamW：β=(0.9, 0.999)，ε=1e−8，weight decay=0；仅对活动参数梯度按全局范数 1.0 裁剪。选择零衰减是为了避免冻结/非活动参数的衰减语义混杂。

**执行前核查条件**：确认所选 BAdam 实现是否支持上述轮换、局部计步、持久状态、分布式冻结和 CPU 状态管理；检查冻结层仍正确传播计算活动层梯度所需的信息。如果实现与此不同，应在训练前修订登记，明确称为哪种 BAdam 配置，不能虚称权威默认设置。小模型数值检查应覆盖两次重新激活后的状态、更新掩码和块访问次数。

### 3.2 LoRA 配置

- 冻结全部原权重，在每层 attention 的 q_proj、k_proj、v_proj、o_proj，以及 MLP 的 gate_proj、up_proj、down_proj 上添加标准 LoRA。
- 搜索 rank r∈{16,32}；缩放 α=2r，采用标准 α/r 定义；dropout=0.05；不训练 bias、norm、embedding 或输出头，不使用 DoRA 或量化。
- 初始化 A 为种子控制的标准随机初始化、B 为零，锁定具体库和初始化规则。
- 使用同样 β、ε、零 weight decay、梯度范数裁剪和 FP32 优化器状态，仅作用于适配器参数。

### 3.3 共同训练设置

- 相同起始权重、tokenizer、训练/验证记录、文本模板和标签；不使用 Instruct chat template。
- 训练文本为 `Question:\n{题目}\n\nSolution:\n{原始解答}`，末尾添加 EOS。仅解答与 EOS 计入交叉熵，题目、前缀和 padding 标签屏蔽。
- packing 使用独立样本 attention 隔离和一致的位置处理，禁止一个样本读取同 pack 的另一题；必须先验证后端支持。
- 训练恰好一遍保留训练数据。定义 T 为全部非 padding 输入 token 数，同时报告有监督解答 token 数。最后一个不足全局 batch 的批次双方使用相同处理，不通过重复样本补齐暴露量。
- 序列长上限 4096；目标全局 batch 为 16 个 packed 序列，即每步最多 65,536 token。实际总长度和步数以冻结 packing manifest 为准。
- 各方法可因显存采用不同 microbatch/梯度累积，但有效全局 batch、优化步边界和样本顺序必须一致；若改变分布式实现，验证 token 加权损失归一化一致。
- 学习率前 3% 训练 token 线性 warmup，之后 cosine 降至峰值的 10%；BF16、非量化，启用 activation checkpointing 和兼容的高效 attention。
- 固定数据顺序种子进行调参；正式重复按成对种子改变顺序。禁用额外模型 dropout 的更改。
- 训练长度不因验证表现提前终止；只选择完整一遍后的模型。记录每块访问次数，若训练步数短到不能完成一次完整遍历，则预先修订轮换/长度方案并重新批准，不能接受“部分层从未训练”的主比较。

### 3.4 规模相当的调参和选模

每方法 6 次完整长度试验，均使用同一个专用调参种子：

| 方法 | 学习率峰值 | 第二维 | 试验数 |
|---|---|---|---:|
| BAdam | 5e−6、1e−5、2e−5 | 每块 1 层、2 层 | 6 |
| LoRA | 5e−5、1e−4、2e−4 | rank 16、32 | 6 |

采用不同学习率范围是因为参数化不同；此处公平是相同候选数、数据暴露量和验证机会，不是完全相同数值或计算费用。

- 主要验证指标：整份固定验证集上按有监督 token 加权的解答负对数似然，越低越好。它可统一处理代码/混合格式，但不是数学准确率的完美代理，应列为限制。
- 每个候选仅在训练结束后做用于选模的正式验证。出现 NaN/不可恢复训练发散的候选记为失败，不追加替代候选；纯基础设施故障只允许原样重跑并记录。
- 最低验证损失者胜；差值≤1e−4 nats/token 时按事前顺序选择较小活动块/rank，再选较低学习率。
- 最优配置冻结后，用新的 5 对种子从原始基座重新训练。调参运行不混入正式重复。若最优点在网格边界，不事后扩网格后只报告赢家；扩展必须作为另一个预登记阶段。

## 4. 对照与零样本评测

### 4.1 模型组

1. 未微调同版本 BF16 基座。
2. 固定选定配置后的 5 个 BAdam 模型。
3. 固定选定配置后的 5 个 LoRA 模型。

基座用于显示两种微调相对于起点的变化，不参与训练种子变异估计。LoRA 主评测保持适配器未合并，避免合并舍入引入额外变量；若必须合并，应提前做一致性检查并统一登记。

### 4.2 固定零样本输入和生成

所有题目使用以下单一模板，不含示范、检索或工具调用：

`Question:\n{原始题目}\n\nSolve the problem step by step. End with the final answer in \\boxed{...}.\n\nSolution:\n`

此处“零样本”只指推理时没有例题，不是没有数学训练。

- greedy decoding，do_sample=false，单次生成，不投票、不重试；max_new_tokens=2048，遇 EOS 停止。
- 提示 token 加输出上限必须不超过所锁定模型上下文限制；不得静默裁剪测试题。若执行前检查发现超限，先修改全组统一协议并登记，不能针对个别模型调整。
- 测试前冻结提示、生成配置、评测程序、符号工具版本和超时。单元测试使用人工构造例子或验证材料，不根据测试集模型输出修正规则。

### 4.3 答案提取与评分

- 用括号配平解析最后一个完整 `\\boxed{...}`。如果不存在，提取最后一个显式 `Final answer:` 后的单行答案；仍不存在则判解析失败。不使用“输出中任意最后一个数字”宽松兜底。
- GSM8K 从数据字段中按冻结规则取标准答案；生成答案做格式规范化和可安全解析的有理数等价比较，不任意忽略正负号、百分号或单位含义。
- MATH 使用版本锁定的保守规范化与安全符号等价评分器，支持预定义的分数、根式、集合/元组规则；禁止执行模型生成代码。每个符号比较设 2 秒超时，不能确定等价时按不正确记入主分数。
- 解析失败、空输出均按错误计分。达到输出上限时，若已存在完整可评分答案仍正常判分，否则记错误；分别报告截断率及截断且正确率，不追加 token 或重采样。
- 评分后的人工抽查仅评估评分器误差，采用方法标签盲化并覆盖成功、失败、超时和截断。事后发现评分错误时，保留冻结主结果，并透明报告对全部方法一致应用的修正版敏感性分析，不只修正某个模型。
- 报告各模型 GSM8K、MATH 准确率及解析失败率、截断率；MATH 领域/难度分层只作为探索性解释。

## 5. 重复、统计与判定

### 5.1 主要估计量

对第 s 对种子和基准 b，定义准确率差 d_sb=Acc(BAdam)_sb−Acc(LoRA)_sb。

主效应为：

Δ = (1/S) Σ_s [(d_s,GSM8K + d_s,MATH)/2]。

两个基准等权，不按题目数量混合。报告单位为准确率百分点，以及每对种子的差值、方法均值和种子标准差。

正式 S=5；建议预登记种子对 101–105，调参种子单独使用。相同种子编号配对训练顺序，方法内部随机性使用派生子种子；这不意味着两种方法具有相同初始化噪声。

### 5.2 95% 区间

保存每个模型每道题的 0/1 正确性矩阵。进行 10,000 次**配对交叉重采样**：
1. 从 S 个种子对中有放回抽取 S 对，同一抽样同时用于两种方法、两个基准。
2. 在每个基准内有放回抽取题目索引；同一组题目索引用于所有抽中的种子和两种方法。两个基准独立抽题；如审计已发现测试题族，则以题族作为重采样单位并保留按题目加权的准确率。
3. 重算 Δ 和分基准差值，取 2.5%/97.5% 分位数。

这保留方法配对和“种子×题目”的交叉结构，不能把 S×N 个格子当作独立观测。另报告仅重采样种子、固定整份测试集的区间，并对每对种子的宏平均差做配对 t 区间敏感性分析。前者对应固定基准的不确定性，题目重采样则要求测试题可代表相应题目分布。

5 对种子仍很少，bootstrap 尾部和正态近似都可能不稳，不能保证名义覆盖。若不同区间方法结论明显冲突，明确标为推断不稳健。资源不足减至 3 对必须在查看正式效果前决定并披露；结果视为低重复度证据，不把题目多当作种子充分，也不进行看结果追加种子的可选停止。

### 5.3 事前判定

建议实际意义阈值 δ=1.0 个百分点，这是**设计假设**，不是已确认的领域标准。

- Δ 的主 95% 区间下界>0：按预设标准支持 BAdam 统计优越。
- 下界>δ：支持至少 δ 的实际有意义优势。
- 下界>0 但≤δ：可支持正差异，但不能确认至少 1 个百分点的优势；点估计超过 δ 本身不够。
- 区间上界<0：支持 LoRA 更好；上界<−δ 则支持其实际有意义优势。
- 区间包含 0：对方向的证据不足；不等于两者等效。若整个区间位于 [−δ,δ]，可另注明差异与预设“小幅差异”范围一致，但不替代专门设计的等效性检验。

主要确认性比较只有一个宏平均 Δ。分基准区间默认描述性，不声称同时覆盖；若进行“各基准均更好”等额外确认性检验，对两项检验采用 Holm 校正。报告潜在基准间方向冲突，宏平均优势不意味着每个数学领域均优势。

## 6. 资源与运行量：估算，不是可行性承诺

### 6.1 候选平台与实现

候选：单节点 8×H100 80GB、NVLink/NVSwitch、高带宽 CPU 内存且主存至少 2TB、足够 NVMe 检查点空间。它是供估算和校准的配置，不是任务已有资源或必需采购。

- 双方冻结/可训练 BF16 权重采用 FSDP/ZeRO-3 类参数分片；activation checkpointing、microbatch 起步为每 GPU 一条 4096 序列，再以梯度累积达到相同全局 batch。
- BAdam 的持久 FP32 master/Adam 状态在 CPU 按 rank 分片保存，仅将活动块所需状态搬到 GPU，更新后写回；冻结块计算需要的权重按需 all-gather。该动态更新与分片组合必须实际验证，不能假定标准库即插即用。
- LoRA 使用分片的基座和适配器优化器状态；主方案先尝试 GPU 驻留适配器状态。双方使用相同硬件口径，具体卸载差异记录为成本组成。
- 如果 CPU 卸载过慢或实现不兼容，可预先转为更多 GPU/不同分片方式；不得只为一方量化、缩短训练或减少上下文来“解决”主比较。

### 6.2 内存账本

以十进制 GB 粗算，参数量和实际 shape 执行前重新清点：

| 组成 | BAdam | LoRA |
|---|---|---|
| BF16 基座权重 | 约 140GB 总量 | 约 140GB 总量 |
| 理想 8 路持久权重分片 | 约 17.5GB/GPU | 约 17.5GB/GPU |
| 可训练参数 FP32 master | 4P_B 字节，接近但低于 280GB，主存保存 | 4P_L 字节 |
| FP32 Adam 两矩 | 8P_B 字节，接近但低于 560GB，主存保存 | 8P_L 字节 |
| 活动梯度 | 2–4P_a 字节，是否分片需实测 | 2–4P_L 字节，是否分片需实测 |
| 激活、all-gather、临时缓存 | 单独测峰值，不能忽略 | 单独测峰值，不能忽略 |

P_B 为所有允许训练 decoder 参数数，P_a 为当前一/两层活动块参数数，P_L 为 LoRA 参数数。按标准架构估计单 decoder 层约 0.85B 参数，一/两层活动梯度总量约 1.7–6.8GB，活动 master+两矩总量约 10.2/20.4GB；实际驻留每卡份额取决于分片，不能直接假设都除以 8。层权重 all-gather 另有约 1.7GB/层 BF16 量级，以及双缓冲等开销。

LoRA 参数按各目标矩阵 r(d_in+d_out) 求和。若锁定配置为 80 层、隐藏维 8192、MLP 28672、GQA K/V 输出 1024，则七类投影合计约 12.94M×r 参数：rank16 约 207M，rank32 约 414M。相应 BF16 适配器权重约 0.41/0.83GB，FP32 master+两矩约 2.49/4.97GB，加上梯度后仍需激活和通信空间。

BAdam 全部 CPU master+矩状态可能接近 840GB，因此建议 2TB 主存以容纳数据、状态搬运和保存峰值；采用分片流式 checkpoint，禁止保存时在单个 rank 聚合全部状态。保留多个优化器检查点需要 TB 级磁盘。以上未证明 80GB/GPU 足够，也未估出吞吐。

### 6.3 总运行量公式

- 调参：2 方法×6 候选=12 个完整训练。
- 正式：2 方法×5 种子=10 个完整训练。
- 合计 22T 输入 token；若减为 3 对，则为 18T。这里每次都是相同数据一遍。
- 每次训练步数由固定 packing 和全局 batch 决定，可粗估 K≈ceil(T/65,536)，最终使用实际 batch manifest。

若候选 c 的实测稳定吞吐为 q_c 个全局非 padding token/秒，单次训练小时为 T/(3600q_c)。总 GPU 小时约为：

Σ_调参 [g_c T/(3600q_c)] + S Σ_两方法 [g_m T/(3600q_m)] + 验证、评测、校准与故障预留 GPU 小时。

q 必须包括轮换、CPU 状态搬运和通信；不同配置不能共用未经验证的吞吐数字。调参验证共 12 次整份验证集 teacher-forcing；正式测试为 2S+1 个模型各评 GSM8K/MATH。若测试题共 N 道，生成 token 上限为 (2S+1)N×2048，另计提示 prefill 和验证开销。预留 20%–30% 工程冗余仅是预算建议，不是实际失败率预测。

### 6.4 执行前门槛

真正执行时、且在正式实验之前完成：
1. 小模型核对冻结参数不变、活动更新与参考优化器一致、状态恢复、分片恢复、损失掩码和 packing 隔离。
2. 在目标 70B 配置上至少覆盖两轮完整 BAdam 块遍历和最坏序列长度，验证显存/主存稳定、无 OOM、无 NaN、checkpoint 可恢复；LoRA 对最高 rank 做对应检查。
3. 峰值显存低于设备可用量的约 85%，主存低于约 80%，作为建议安全线；否则调整系统设置并复测。
4. 测得包含状态 I/O 的吞吐、检查点时间和评测成本，代入总预算公式。预算不足时，事前决定是否减到 3 对或暂停，不根据胜负选删运行。

固定 GPU 小时下的性能可作为未来辅助研究，需另行登记训练 token 预算；它不改变本主实验，也不由相同 token 比较自动推出。

## 7. 本设计能回答什么

本设计可支持的结论是：**对于锁定的原始 Llama 3-70B BF16 基座、经题族去污染和长度筛选后的指定 MathInstruct、这组 BAdam/LoRA 实现与等规模调参流程、相同训练 token 暴露量，以及固定 GSM8K/MATH 零样本生成和判分协议，哪一种方法具有更高的预期准确率，差值多大、对训练种子和题目变化是否稳健。**

它不能自动推广到 Instruct 版、其他 Llama 版本、QLoRA、其他训练长度、固定时间预算、所有数学能力或所有 BAdam/LoRA 超参。也不能通过微调清洗证明没有预训练污染。

目前不能判定 BAdam 必然更好：更广泛的参数更新可能提高适应能力，也可能带来优化不稳、块轮换效率损失或遗忘；LoRA 的低秩约束可能限制容量，也可能提供有效正则化。仓库中没有实测结果。结论必须由冻结协议后的成对实验及不确定性分析产生，而不是从可训练参数量或方法名称推断。
