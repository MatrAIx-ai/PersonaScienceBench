## 1. 定位、事实与研究目标

**主要问题与效应：**在同一模型、同一智能体脚手架、同一初始任务实例和共同资源上限下，显式 CoT 提示相对直接动作提示造成的任务成功率变化。该效应包括生成推理文本带来的计算、延迟和输出长度变化，是提示干预的总效果，不是内部推理机制的证明。

## 2. 两组提示及统一智能体协议

### 2.1 共同基础提示
以下英文模板用于两组，任务描述和接口说明按实例机械填充；正式运行前冻结原文与文件哈希。

```text
You are an agent completing a WorkArena++ task.
Complete the task using only the available actions and current observations.
Task: {task_description}
Available actions and their JSON schema: {action_schema}
Return exactly one JSON object with exactly these keys:
{"reasoning": "...", "action": {one valid action}}
Do not output text outside the JSON object.
Follow the action schema; do not invent tools or arguments.
```

**CoT 组唯一附加指令：**
```text
Before choosing each action, reason step by step briefly about the current state,
the task requirements, and the next useful step. Put this reasoning in "reasoning",
then provide the next action in "action".
```

**非 CoT 组唯一附加指令：**
```text
Choose the next action directly. Set "reasoning" to an empty string
and provide the next action in "action".
```

两组都使用相同的 JSON 外壳，不给 CoT 组额外任务知识、演示、规划器、检索或反思轮次。非 CoT 是“不要求且指示不输出显式推理”，不意味着模型没有内部推理。此最小比较包含指令措辞和推理输出的联合变化；不能进一步声称已排除所有措辞效应。

### 2.2 统一动作解析与失败处理

- 每次响应只允许一个 JSON 对象；必须含字符串 `reasoning` 和一个满足已冻结动作 schema 的 `action` 对象，不允许其他键或多个动作。
- 解析器只执行 `action`；不评价推理是否正确，不将推理内容转换成额外工具请求。
- 两组的语法检查完全相同。非 CoT 输出非空推理、CoT 输出空推理均记录为干预依从性问题，但只要动作合法就照常执行，不因此特殊判失败，也不从主分析剔除。主分析按原分配条件计算。
- 非法 JSON、输出截断和非法动作均消耗一次决策步和已产生的 token；返回同一固定错误信息。不使用另一个 LLM 修复、不赠送额外重试。若仍有共同预算，可在下一步继续。
- 一个决策步至多调用模型一次并执行一个动作。明确的终止动作使用所选基准/适配器支持的终止协议；终止后的成功仍由原生验证器判断，不由智能体声明决定。

### 2.3 历史、观察与轨迹分化

**主实验选择：不把 `reasoning` 字段放入后续模型历史。** 两组都只保留任务说明、历史动作、工具结果和观察；完整原始响应另存于离线审计日志。这样主要比较的是当前决策内的显式推理，而不是额外的跨步推理记忆。结论不自动推广到保留完整 CoT 历史的智能体。

统一历史政策如下：
1. 固定保留共同指令、任务说明及当前观察；历史按完整的“动作—结果/观察”单元保存。
2. 超过共同输入 token 上限时，从最早完整单元开始删除；不用 LLM 摘要。
3. 当前观察本身过长时，使用两组相同、与结果无关的观察序列化和确定性裁剪规则。实施前对选定观察接口固定元素顺序、保留字段和裁剪顺序，并用测试样例核查。
4. 为共同单次输出上限预留上下文空间，输入上限不得超过模型上下文容量减去这部分空间。

两组在启动时具有相同任务与状态；动作一旦不同，后续观察自然可能不同。这是处理产生的轨迹分化，不应强行同步观察、回放另一组轨迹或在分析中控制掉这些差异。

- 目标总体是冻结版本内、符合预先技术资格条件的全部任务模板。资格条件仅涉及实例能否生成、观察/动作接口是否兼容和验证器是否可用，不能根据模型成功率排除难题。
- 若存在官方类别/难度元数据，按其分层；否则只用可核实的类别，若都没有则进行不分层随机抽样，不人工猜测难度。
- 设第 h 层有 N_h 个合格模板，总数 N。**主权重 W_h=N_h/N：模板等权，而不是让实例更多的模板权重更高。** 每个模板内对种子和重复等权。这是本设计的目标分布，并不假定它就是官方排行榜分布。
- 成本允许时覆盖全部模板；否则在层内对模板无放回随机抽样。总模板数 K 由功效与预算规划决定；采用按 N_h 比例分配、最大余数取整。每层建议至少抽两个模板（仅一个模板的层则全取）；预算连这一要求都达不到时，应调整研究范围或精度目标，不能承诺可靠的总体区间。
- 每个入选模板抽取相同数量 S 的实例种子。通过固定种子的可复现程序从声明的实例生成分布抽取，且与校准实例不重叠。清单、抽样种子和权重在看正式结果前冻结。
- 若任务存在天然不可生成的实例，按与条件无关的规则在分配运行前替换并记录；不能运行失败后将其改称无效实例。

可另报告官方权重下的辅助指标（仅当官方权重确实存在），但不替换主指标。

### 3.2 主要模型与脚手架

**必需主实验只使用一个模型。** 预先列候选模型，在查看确认性结果前按以下顺序选择：
1. 可稳定访问、可锁定具体版本且满足数据与使用授权；
2. 支持所选观察模态、结构化动作输出以及明确的上下文和生成上限；
3. 优先选择没有强制隐藏推理预算、或能够固定并计量推理预算的模型；
4. 在独立校准任务上达到事前定义的接口可用性标准，而非选择 CoT 收益最大的模型；
5. 若多者合格，选在总经费上限内预估可完成最多配对样本者；并列按预先固定候选顺序决定。

记录精确模型 ID、版本、访问日期、采样参数及费用表。建议主实验温度固定为 0，其他参数使用同一已记录值；若服务不支持则冻结其可支持设置。温度为 0 也不能假定服务绝对确定。

固定一个脚手架：相同观察处理、工具权限、动作空间、系统指令、记忆、解析器、超时和错误政策；不另加规划/反思模块。实例重置校验、验证器和运行代码均版本化。模型选择阶段不得依据正式测试集表现调提示。

### 3.3 配对、重复与随机化

- 每个模板 t、实例种子 s、重复 r 构成一对；两组分别从同一已校验的初始快照运行，浏览器会话、账号状态、服务端数据和缓存隔离或重置，不共享记忆。
- **建议正式重复数冻结为 R=3**，每个条件对每个实例均运行三次。这是设计选择，不是来源事实；若功效/成本规划要求改动，必须在正式运行前一次性冻结，不能按某组结果追加重复。
- 每一对随机决定 CoT 先运行还是非 CoT 先运行；在模板、实例和重复间随机排序，并将配对安排在相近时段。记录时段、主机和服务版本。
- 接口允许时记录生成种子；共享种子并不保证不同提示共享相同随机输出。重复用于估计运行随机性，不当作额外独立任务模板。

## 4. 预算、校准与冻结程序

### 4.1 共同预算

每次运行设置共同的：最大决策步 A、单次生成 token 上限 O、累计生成 token 上限 G、输入上下文上限 I、活动墙钟时间上限 T，以及相同工具调用超时。若任一累计预算用尽则结束，并运行原生验证器。活动墙钟时间应包含正常模型与工具延迟；被确认的基础设施停机按故障政策处理。

**仅作可行性起点的示例值：**A=50、O=1,024、G=25,000；这些值不是固定要求或来源设置，I 和 T 必须根据实际接口及校准选择。最后一轮输出上限取 O 与剩余 G 的较小者。两组都没有额外的免费“思考调用”。

### 4.2 事前选择及冻结

1. 先登记总费用上限 C_max、可接受总工期、最小有意义差异 δ*（成功率的绝对百分点）及模型候选表。
2. 用不纳入主分析的校准实例检查 JSON 解析、动作语义、重置一致性、验证器可用性、日志和预算计数；给两组相同的校准机会。
3. 对预先列出的少量预算档，依据接口可运行性、两组合并的截断比例、成本和时长选择一个主预算档。例如可事先设定“选择在经费内且合并输出截断率低于 5% 的最小档”；若无档满足，修改资源范围并披露，而不是偷偷增加某组预算。不得以 CoT 成功率差最大为选档标准。
4. 结合下节样本量规划，冻结 K、S、R、A、O、G、I、T、模型/脚手架版本、全部提示、任务清单、排程、故障政策和分析代码。若资源约束与功效目标冲突，优先增加独立模板、其次增加实例，最后才增加重复，并在正式运行前说明实际可达到的精度。
5. 正式期间不根据成功率提前停止、调提示或改预算；不可避免的版本变动作为协议偏离报告，不能无说明地混合版本。

相同预算上限不等于相同实际推理开销。主实验回答共同资源政策下的效果；成本差本身是重要辅助结局。

## 5. 主要结局、估计和结论规则

### 5.1 结局

主要结局 Y 为：一次运行结束时，基准原生验证器是否确认任务已成功完成（成功=1，否则=0）。固定预算耗尽时也检查状态，避免将已完成任务误判失败。若验证器无法运行或返回不确定结果，按缺失结果处理，而非让模型自行评分。

辅助结局包括动作步数、工具调用数、输入/输出及可计量的隐藏推理 token、活动时长、费用、格式错误率、预算耗尽率和两组依从性。统一统计所有运行，不只比较成功运行的成本；“每成功一次的总成本”可作为附加指标，成功数为零时记为不可定义。

### 5.2 估计量及配对/聚类单位

对层 h 中模板 t、实例 s、重复 r，定义：

`D_htsr = Y_CoT,htsr − Y_direct,htsr`，取值为 −1、0、1。

模板内平均 `d_ht = mean_(s,r)(D_htsr)`；主要估计量为：

`Δ_hat = Σ_h W_h × mean_(t in sampled h)(d_ht)`。

报告两组加权成功率、Δ_hat 的百分点值、95% 置信区间，以及配对结果中仅 CoT 成功和仅对照成功的比例。**配对单位为同一模板—种子—重复；主要聚类单位为模板。** 不把不同步骤、同模板种子或重复运行当成独立模板。

### 5.3 95% 区间

主要方案是预先固定的分层模板簇 bootstrap（建议 10,000 次重采样）：在各层内对模板重采样，携带模板内全部实例、重复及两组配对结果，按固定 W_h 重算 Δ_hat，取百分位 95% 区间。它针对从声明的任务生成总体再抽样时的平均效果；应避免将其误称为有限固定清单的精确随机化区间。额外的实例/重复主要提升模板均值精度，而非增加独立簇数。

模板很少、稀疏层或全为同类结果时，该近似区间可能不可靠。冻结样本量前用覆盖率模拟检查；不满足预定覆盖率容忍度时，应增加模板或改为明确的固定模板范围分析。若只能研究极少数模板，报告逐模板效应和宽泛不确定性，不给出强的总体优越性结论。不得在看正式结果后挑选最有利的区间算法。

### 5.4 结论判据

事前确定 δ*>0，例如 **5 个百分点只是可讨论的实用阈值示例**。

- 95% 区间下限大于 0：支持该配置与目标任务分布下存在平均改善。
- 下限还大于 δ*：进一步支持改善超过事前实用阈值。
- 区间包含 0：证据不足，不能解释为无效。
- 区间上限低于 δ*：可排除达到该阈值的改善，但未必能排除小幅改善。
- 只有整个区间落在事前设定的 `[−δ*, +δ*]` 内，才可按预先声明的保守等效判据讨论实用差异很小；上限小于 0 则支持性能下降。

主实验只有一个主模型、一个主预算和一个主要效应。类别及错误类型分析为辅助探索，不据其显著与否改写总体结论；若另设多个确认性模型/预算检验，需单独预注册多重检验校正。

## 6. 样本量规划步骤

1. 在结果未知时确定 δ*、双侧 α=0.05 和目标功效（建议 80%，也可根据资源选 90%）；不得从预计可获得的显著性倒推 δ*。
2. 用外部信息或独立校准配对估计 `q = P(D≠0)`，即两组成功状态不一致率，并估计模板内 D 的相关性 ρ。小校准样本只能提供范围，因此同时考察多个合理 q、ρ 情景，不把点估计当真值。
3. 忽略聚类时，`Var(D)=q−Δ²`。粗略独立配对数可用 `n_ind ≈ (z_(1−α/2)+z_power)² × (q−δ*²) / δ*²` 作起点；须保证假定的 q、δ* 对应合法的配对概率，且该近似不是最终功效保证。
4. 每模板约 m=S×R 对时，用 `1+(m−1)ρ` 作为保守的一层设计效应初筛；同一实例重复与不同实例还可能具有不同相关性，最终不能仅靠这个简式。
5. 对候选 K、S、R 进行层级配对二元结果模拟：保持预设基线成功率、q、δ*、模板效应及同实例重复相关性，按实际分层权重、缺失情景和主分析算法估计功效与 95% 区间覆盖率。模型假设和模拟代码一并冻结。
6. 选取经费内达到目标功效/覆盖率的最小方案；若不能达到，则报告可检测差异与预计区间宽度，接受精度有限，不用更多同模板重复伪装成足够的独立任务数。这里的模拟属于未来规划步骤，本次没有执行。

## 7. 平台故障、缺失与智能体失败

在运行前建立按日志可审计的分类表，尽可能由不知道条件标签的人员裁定。

- **智能体失败：**非法动作、格式错误、正常预算超限、未满足任务条件、智能体造成的不可恢复状态等，均按实际终局验证为 0 或 1，不因失败而重跑。
- **平台故障：**任务启动前服务不可用、明确的 API 5xx/基础设施中断、环境无法重置、验证器基础设施异常等。正常慢响应或 CoT 因输出更多而耗尽时间不自动归入此类。
- **重跑规则：**一对中任一运行发生确定的平台故障，则废弃该次配对作为正式尝试、保留日志，并从原始快照重新运行整对，重新随机先后。建议最多两轮整对重跑；两组适用同一规则，不因观测到成功或失败决定是否重跑。全部尝试均计入总资源账单。
- **未解决缺失：**达到故障重试上限仍缺结果，不等同于已观测的智能体失败，不静默删除模板，也不换一个更容易的实例。

缺失存在时：报告各条件故障/缺失率及完整配对估计，后者只能在缺失近似不依赖潜在结果的假设下代表目标效应。同时对所有预定样本做最坏/最好情景界限：为下界将缺失 CoT 设为 0、缺失对照设为 1；上界反之，按原权重计算，并对两端进行簇级不确定性分析。若缺失足以改变改善结论，就不作总体优越性断言。另报告“把无法完成评测的运行计为失败”的运行可靠性指标，但不得将其混称为纯任务能力。

### 运行量与成本公式

若有 K 个模板、每模板 S 个实例、每实例 R 次重复、一个模型和一档预算：

`正式轨迹数 L = 2 × K × S × R`。

例如 K=60、S=5、R=3 将产生 1,800 条轨迹，**仅为算术示例，不是已经确定或完成的规模**。可选 M 个模型、B 档预算、P 套提示对完全交叉时，运行量再乘 M×B×P；不必默认采用全交叉。

`预计费用 = Σ轨迹[p_in×输入token + p_out×输出token + p_reason×另计费推理token + 工具/环境费用] + 校准与故障重跑费用`，其中 token 价格按一致单位换算，隐藏推理若已包含在输出计费内不重复计费。输入 token 应累加每次调用的完整计费上下文，不能只算初始提示。

`预计总活动时长 = Σ轨迹时长`；墙钟工期约为总活动时长除以可用有效并发度，再加配对排程、限流、重置和故障开销。并发必须有隔离环境，并在条件间均衡。

### 设计理由与边界

配对减少实例难度差异；重置防止状态污染；随机顺序降低时段和服务漂移偏倚；共同动作协议减少解析器偏袒；丢弃推理历史减少跨步记忆混杂；固定资源政策让主比较有明确实施意义；原生验证避免文本自评；模板级分析防止伪重复。

未来实施需要：可获得且合法使用的 WorkArena++ 版本及环境、可重复任务生成/重置、可信验证器、可锁定模型服务或权重、日志与成本计量、并行隔离与足够经费。本次工作区没有这些输入，但设计交付不以其当前存在为前提。
