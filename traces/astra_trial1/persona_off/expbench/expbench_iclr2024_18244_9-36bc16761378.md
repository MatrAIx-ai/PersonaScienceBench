# Experiment design: PDF period sensitivity on ETTm1

## 1. Status and objective
This is a proposed experiment, not an executed study. The supplied material names PDF and ETTm1 but does not identify the implementation or establish period semantics or benchmark settings. All numerical settings below are **proposed protocol choices**, not documented PDF defaults.

The primary objective is fixed-recipe sensitivity: how changing period values changes predictive error, with other settings fixed. This is not a comparison of independently optimized models. Report results by forecast horizon; there need not be one universally best period.

## 2. Pre-execution verification checklist
Before running, record in a frozen manifest:
- PDF paper/model identity, repository revision, model class, dependency versions, and full configuration. Verify this is the intended forecasting model rather than an unrelated acronym.
- Period parameter name, units, scalar/list behavior, whether list order matters, and whether singleton lists are legal. Trace how it changes folding, patches, branches, padding, and parameter counts.
- Valid periods for the proposed input length, any divisibility/minimum-cycle constraints, and output shape for all horizons. Confirm whether padding includes the forecast segment as well as history.
- Dataset file checksum, timestamp cadence, seven expected numeric channels, missing values, and exact split indices. Check that future targets cannot enter model inputs or fitted preprocessing.
- A forward-pass and small training smoke test for every distinct shape configuration, with no test-set-driven configuration decisions.

Unknowns do not prevent delivering this design; the conditional grid rules below define how to adapt it. Resolve and freeze adaptations before comparative training, based on validity and documentation—not measured test performance.

## 3. Primary factors and reference
**Conditional sample-unit grid:** if periods are lengths in 15-minute samples and singleton periods are supported, use period lists **[24], [48], [72], [96], [144]**. These represent 6, 12, 18, 24, and 36 hours under the proposed cadence. Primary list cardinality is always one. Set **[96] as the design reference**, a daily-cycle hypothesis—not a claimed PDF default. The grid includes shorter and longer alternatives, not just integer-day cycles.

Use look-back **L = 384 samples** (four days at the assumed cadence), fixed across all settings. Train separate direct multi-step models for horizons **H = 96, 192, 336, 720**. Each training example has input shape L × 7 and target shape H × 7 under the proposed multivariate task. Do not add a weekly period to this short-history grid merely because it is a plausible calendar cycle.

### Conditional revisions
- If valid periods must divide L, the bounded fallback grid is **[24], [48], [96], [128], [192]**, retaining [96] as reference. This avoids forced padding for the history when divisibility by period is the only restriction; other patch constraints may still apply.
- For additional restrictions, retain only valid candidates. Seek at least three values bracketing the reference where possible. Any replacement must come from a validity-based, predeclared candidate set and be recorded before training. If 96 is invalid, choose the valid candidate nearest 96, ties favoring the smaller value, and relabel it as a design reference. Do not silently clip periods during training.
- If singleton periods are unsupported and a K-period list is required, use a valid baseline list B from the verified implementation, explicitly identifying whether it is documented or analyst chosen. Hold K, order, and K−1 entries fixed; vary one designated entry through up to five valid values around its baseline value. For sample-valued entries, candidate multipliers are 0.5, 0.75, 1, 1.5, and 2, rounded to the nearest legal value with deterministic ties and duplicates removed. Preserve ordering/uniqueness constraints without reordering other branches. This tests one coordinate conditional on B, not all possible lists. If fewer than three variants are legal, declare a reduced comparison and its limited scope.
- If periods are frequencies, learned indices, or another quantity, do **not** reinterpret the sample grid as if equivalent. Use the verified mapping to construct equivalent sample lengths where possible; otherwise predeclare at most five legal native-unit settings and describe the changed estimand.

Structural ablations—changing list cardinality, branch count, look-back, patch size, or learned versus fixed period selection—are separate, optional studies and do not enter the primary ranking.

## 4. Proposed ETTm1 protocol
Adopt the conventional-style setup below as an assumption to verify, not as a supplied source fact:
- 15-minute cadence; seven numeric input channels; multivariate-to-multivariate forecasting of all seven channels. If the intended benchmark is univariate or multivariate-to-single-target, revise the target definition before training and do not mix its scores with this study.
- Chronological index boundaries, using zero-based half-open intervals: training **[0, 34560)**, validation **[34560, 46080)**, test **[46080, 57600)**. These correspond to proposed 12/4/4 blocks of 30-day months, not necessarily calendar-month boundaries. Ignore later rows for this benchmark and record any mismatch with the available data.
- Generate stride-one forecast origins separately for each H. Every target window must lie entirely within its assigned split. Validation/test inputs may use preceding history from earlier splits, as available at that origin. For a segment [a,b), use origins t from max(a,L) through b−H, inputs [t−L,t), and targets [t,t+H). No test-time refitting or parameter updates.
- Fit per-channel mean and standard deviation on training rows only; apply the same transform everywhere. Exclude timestamps from numeric target channels. Keep any implementation-required calendar covariates fixed and future-known only. Freeze internal normalization options as well.
- Check regular cadence, duplicates, gaps, and nonfinite values. Prefer the clean benchmark file; if repair is necessary, document one causal, training-defined policy before training. No interpolation using future validation/test observations.

## 5. Fixed training recipe
Use **five paired seeds: 11, 22, 33, 44, 55**, shared across every period and horizon. Within each horizon/seed, use the same data ordering and seed-controlled initialization/dropout. Shape changes can prevent identical weight draws; seed pairing is a blocking device, not a guarantee of identical randomness.

Proposed recipe: standardized-target MSE loss, Adam with learning rate 1e−3, betas (0.9, 0.999), epsilon 1e−8, weight decay 0, batch size 32, gradient-norm clipping at 1, constant learning rate, and maximum 50 epochs. Evaluate full validation MSE after each epoch; stop after 10 consecutive epochs without a lower value. Save the lowest-validation-MSE checkpoint, breaking ties by earliest epoch. Use the same precision, loader behavior, and checkpoint rules throughout.

Freeze all non-period architecture and patch settings from one verified baseline configuration before the sweep. No per-period architecture adjustment or optimizer tuning. If memory requires a change, adopt one smaller batch size for the entire comparison rather than only the difficult cells. If the recipe is demonstrably unusable in a training/validation-only feasibility pilot, revise it once globally, document why, and restart the primary comparison. This does not become period-specific tuning.

Equal maximum epochs and identical stopping rules need not imply equal realized updates or runtime. Record both. The primary comparison is recipe-matched, not claimed compute-matched.

## 6. Metrics and selection
**Primary metric:** standardized-scale MSE, averaged uniformly across all forecast origins, all H lead positions, and all seven channels, separately for each horizon. **Secondary:** identically aggregated standardized MAE. Report mean and sample standard deviation across the five seed-specific checkpoint scores. Also report channel-wise metrics and lead-position profiles to expose hidden trade-offs.

Optionally inverse-transform predictions and report native-unit errors per channel, especially the oil-temperature channel if present. Do not interpret a pooled raw-unit metric across heterogeneous channels as the primary benchmark score.

For each horizon independently, choose the period with lowest **mean validation MSE across the five seeds**. Resolve exact ties in favor of the reference, then by the frozen grid order. This is a validation-selected recommendation, not a test-selected winner.

Prespecify test reporting for every grid cell and each candidate-versus-reference contrast. The principal recommendation comparison is the validation-selected setting versus the reference at each horizon, using the already selected checkpoints with no train-plus-validation refit. If the reference is selected, report that fact rather than manufacture a nonzero contrast. Do not change the grid, recipe, or recommendation after test inspection. A table by horizon is mandatory; any pooled summary is supplementary and equally weights horizons with its convention explicitly stated.

## 7. Paired effects and uncertainty
For each horizon and seed s, compute Δs = MSE(candidate,s) − MSE(reference,s); negative values favor the candidate. Report mean paired Δ, its seed standard deviation, all five paired differences, and a descriptive 95% paired t interval using four degrees of freedom. Report relative change versus the reference mean alongside absolute change. Apply the same reporting to MAE as secondary evidence. Five seeds give limited precision, so avoid strong significance claims.

These seed intervals describe training randomness conditional on this fixed test segment. They do not establish uncertainty over all future time series. Forecast origins are **not independent replicates**: adjacent target windows overlap by H−1 observations, and errors also have serial dependence. Do not calculate standard errors treating all origin/lead/channel entries as independent.

As a separate robustness analysis, form paired loss-difference series by origin, averaging leads/channels and then seeds. Use a paired moving-block bootstrap over contiguous origins, preserving candidate/reference alignment, with 2,000 resamples and block length max(H,672) samples; check twice that length as a sensitivity analysis. This is conditional on fitted models and relies on approximate local stationarity; it does not combine all sources of uncertainty or eliminate distribution shift. If formal candidate-wide claims are wanted, predeclare multiplicity correction across the four horizons and candidate contrasts; otherwise label these contrasts descriptive and do not select favorable intervals post hoc.

## 8. Diagnostics, compute, and feasibility
For every period/horizon combination, record trainable parameter count, branch count, folded shapes, patch count, number and fraction of padded elements, padding value/mask policy, truncation if any, and whether padded positions can influence predictions. Log parameter and operation-count changes caused by period choices. Such changes are mechanisms of the actual implementation effect, not automatically controlled away by identical nominal widths.

Record epochs/updates completed, best checkpoint epoch, training and validation time separately, peak device memory, and inference latency/throughput on identical batch sizes and hardware after warm-up with appropriate synchronization. Report distributions over repeats rather than a single timing. Do not promise that a smaller period is cheaper.

For P valid settings, four horizons, and five seeds, the primary budget is **P × 4 × 5 fits**: at P=5, **100 fits**, with the reference already included. Grid validation, smoke tests, and any globally revised pilot are additional and must be logged separately. Test evaluation adds no training fits. Optional ablations have separate budgets and labels.

The present environment has no supplied dataset, dependencies, GPU, or network access, so no training runtime is asserted. For eventual execution, stage verified data and code in an appropriate environment, validate all forward shapes, pilot resource use on the reference and highest-memory shapes, then estimate the budget. Prefer reducing the grid to a frozen three-value bracket (60 fits) over silently dropping seeds or horizons after seeing results. If that is still infeasible, explicitly rescope before the study starts. Cache fixed preprocessing, checkpoint runs, and record failed cells with reasons. Do not rank incomplete configurations as if directly comparable.

## 9. Conclusions and limitations
The experiment can estimate period-setting effects for a specified PDF implementation, fixed training recipe, chosen horizons, and one chronological ETTm1 split; identify a validation-selected recommendation at each horizon; and describe capacity/padding/cost trade-offs.

It cannot establish a universal best PDF period, prove that calendar cycles cause a gain, isolate a purely mathematical period effect when capacity/padding also change, or generalize reliably to other datasets, splits, look-backs, target modes, or retuned architectures. The bounded grid and five seeds limit resolution. Any empirical conclusion must await execution; no performance ordering or outcome is predicted here.
