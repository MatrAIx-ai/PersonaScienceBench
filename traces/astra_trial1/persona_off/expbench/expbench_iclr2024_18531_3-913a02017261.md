# Experiment design: mechanic triggering and agent survival

This is a proposed experiment, not an executed study. The supplied brief identifies hierarchical versus non-hierarchical agents and score-threshold mechanics such as pirate invasions, but supplies no simulator, agents, threshold values, or intervention APIs.

## 1. Questions and estimands

Choose one target mechanic and document its exact eligibility rule. Let agent class a be hierarchical (H) or non-hierarchical (N).

**Primary: effect of the first activation.** Run episodes with identical natural target-mechanic behavior up to the first eligibility boundary. Define time zero at the state immediately before the first activation would take effect, while the agent is alive. Randomize activation (Z=1) versus suppression (Z=0). Use a prespecified common follow-up horizon τ, in simulator steps or simulator time, not wall-clock runtime. For remaining time to terminal failure T, estimate:

μ(a,z) = E[min(T(z), τ) | class a, alive and first eligible].

The mechanic effect is Δa = μ(a,1) − μ(a,0). Negative values mean activation shortens survival. The primary class comparison is I = ΔH − ΔN; positive values mean the effect is more favorable or less harmful for H. Prespecify I as the primary contrast and report both class-specific effects and survival curves.

**Precise later-activation policy:** In the primary experiment, deliver the first eligible activation in Z=1 and skip it in Z=0. Thereafter block every new activation of the target mechanic in both arms through follow-up. Allow the initial event and its downstream consequences to unfold normally; do not erase enemies or consequences already generated. Specify in the mechanic implementation which delayed spawns belong to that event and which would be new activations. Do not queue or replay the suppressed event. Thus this is a one-activation-versus-no-activation contrast under a common later-suppression policy, not the effect of the game's entire natural recurring mechanic schedule.

**Complementary: total-survival regime effect.** In separate evaluation episodes, randomize at episode start to the target mechanic naturally enabled, including all subsequent eligible activations, versus disabled for the entire episode. Measure survival from reset, including episodes that never reach eligibility. With a separately prespecified common horizon τ0, estimate the class-specific difference in restricted mean total survival and its class interaction. This is an intention-to-treat regime effect; it is not the effect of actually experiencing a first trigger. Do not condition this analysis on reaching the threshold.

## 2. Interpretation of hierarchy

Randomization identifies the activation effect within each class's eligible-episode population. It does not make agent architecture itself randomized or ensure the two classes reach comparable states. The interaction I therefore compares mechanic effects in each class's own eligible-state population, not an intrinsic architecture effect at identical states.

Define the target agent population and weight independent trained agents equally, with eligible states sampled under a common protocol. Agents that never qualify have no post-eligibility effect to estimate; report their frequency and do not silently drop them from the complementary regime analysis. Report eligibility probability, time and score at eligibility, and state composition by class.

A standardized secondary comparison is possible only if both classes can validly operate on a prespecified common distribution of eligible states. Check overlap in relevant state features and avoid extrapolation beyond shared support. Environment snapshots alone do not supply valid recurrent memory, high-level goals, option execution state, or other controller history. Restoring each agent's own history-compatible state is necessary for faithful within-agent branching; transplanting arbitrary controller memories across architectures is not valid. If shared-state evaluation cannot be justified, retain the conditional population interpretation.

## 3. Agent replication and controls

Use multiple independently trained agent instances per class, with independent training seeds and prespecified checkpoint selection. Episodes from one checkpoint are not independent training replications. If only fixed supplied checkpoints are available, restrict inference to those checkpoints rather than a training population.

Specify and harmonize, where scientifically appropriate:
- observations, action opportunities, reward function, task distribution, and environment version;
- training experience and compute accounting, optimization and tuning effort, checkpoint selection, and exposure to the target mechanic;
- evaluation action stochasticity, time limits, initial-state distribution, and termination rules.

Define hierarchy operationally, including temporal abstraction and controller structure. Capacity or compute matching may be imperfect; document residual differences and, if feasible, prespecify matched sensitivity comparisons rather than asserting that architecture is isolated. Freeze learned parameters during evaluation, while allowing normal controller-memory updates. Use the same trained checkpoints in treatment and control conditions. Do not retrain an agent separately for each primary intervention arm. Training-exposure questions would require a separately labeled factorial extension.

## 4. Randomization and valid branching

Use balanced randomization within trained agent and prespecified evaluation strata. Allocate treatment at first eligibility without using future outcomes. Initial scenarios should be sampled identically across classes; sharing scenario seeds can reduce variance but does not guarantee identical eligible states.

Preferred implementation if validated: save a complete eligible snapshot, branch it into activation and suppression, and evaluate both. Restore environment state, event queue, counters, random-number generator state, and controller memory. Prevent any cross-branch contamination. Randomize execution order. Shared random streams or exogenous schedules may improve precision only if their coupling preserves each arm's correct marginal dynamics; divergent event counts can otherwise misalign a single global random stream. Paired branches are one paired experimental unit, not two independent observations.

If faithful cloning is unavailable, randomize activation versus suppression on independently generated eligible episodes. This does not require exact state matching: randomization balances the eligible-state distribution in expectation. Record assignment probabilities and failures. Analyze assigned treatment as primary; any intervention noncompliance is a fidelity problem, not a reason for outcome-dependent exclusion.

For the episode-start experiment, randomize enabled/disabled within agent, with valid paired initial snapshots or seed blocks where available. Keep the primary and complementary protocols labeled separately because their later-trigger policies differ.

## 5. Intervention fidelity and confound safeguards

Before collecting confirmatory evaluation data, validate the following using instrumented checks, not assumed engine capabilities:

1. **Eligibility interception:** identify the exact processing boundary, including score updates, death checks, warning emission, event scheduling, and activation. Prespecify how same-tick death and eligibility ties are ordered. Include only agents alive at the defined intervention boundary.
2. **No score manipulation:** never add, subtract, freeze, or reset score to induce or prevent the trigger. At assignment, score, rewards already accrued, resources, progression, and histories must match under branching. In randomized unpaired episodes, inspect balance without selecting episodes based on survival. Later score changes caused by the mechanic are mediators and must not be artificially equalized.
3. **Selective suppression:** block only the target activation and its queued work. Verify that suppressed events do not execute late and that both primary arms block all later new activations. Check enabled behavior against ordinary game behavior and no-op instrumentation against unmodified execution where reproducible.
4. **Warnings:** proposed primary treatment is the complete target-event package, including event-specific warning cues. Intercept before the earliest such cue and deliver or suppress that cue consistently with assignment. If warnings occur before the score threshold, the earlier warning boundary must be used and the eligibility definition revised explicitly. If cues cannot be intercepted, equal cue exposure followed by randomized execution estimates execution conditional on a warning, not the full trigger-package effect. Do not silently mix these estimands. Suppression must not introduce an extra arm-identifying debug cue.
5. **Simultaneous mechanics:** unrelated score-linked events remain governed by their ordinary rules in both arms; their occurrence at the boundary should match in paired branches. If the target event cannot be separated from simultaneous events, redefine the intervention as a documented bundle before evaluation or decline the isolated-mechanic causal claim. Subsequent differences caused by the intervention are legitimate downstream effects, not baseline confounding.
6. **Bookkeeping:** specify event identifiers, consumed eligibility flags, cooldown and queue behavior so suppression cannot cause an immediate retry. In the primary protocol any remaining target-mechanic bookkeeping must not create non-event differences unrelated to the assigned intervention.

The key causal safeguard is assignment among agents already alive and eligible. Comparing episodes that ever trigger with episodes that never trigger is not an acceptable causal analysis: reaching the threshold requires survival and reflects score progression and ability. Do not count pre-trigger time as survival gained from activation or condition on post-treatment score.

## 6. Failure, respawns, and censoring

Define the absorbing failure event before evaluation. Proposed default is terminal episode failure/game over. If the game has respawns or multiple lives, a nonterminal death is not the primary event; continue through permitted respawns and record first death and lives lost as secondary outcomes. If first death is scientifically preferred, change the definition prospectively and apply it to both classes and all arms.

Follow primary episodes for the same τ after eligibility, irrespective of time spent reaching it. Follow complementary episodes for τ0 from reset. Episodes alive at the horizon are administratively right-censored, not counted as deaths. Integrating survival to the horizon gives restricted mean survival; with no early censoring it is simply the mean of min(T, horizon).

Native time limits, success terminations, disconnects, and simulator crashes require explicit treatment. A success ending is not automatically noninformative censoring: define whether the target becomes time to any episode termination or use a competing-event analysis for death. If continuation after success is valid, document it. Do not equate crashes with deaths. Log technical losses, assess arm dependence, and prespecify rerun rules independent of outcomes. With early censoring, survival estimation requires credible censoring assumptions; use sensitivity analyses/bounds when those assumptions are doubtful. If native limits prevent equal post-eligibility follow-up, revise the horizon or simulator protocol before confirmation rather than ignore informative truncation.

## 7. Analysis, uncertainty, and planning

Estimate arm-specific survival curves and RMSTs, within-class effects, and I. Weight trained agents according to the prespecified target, normally equally; do not let agents producing more eligible episodes dominate accidentally. Show eligible counts and censoring/fidelity summaries alongside estimates. Optional precision adjustment may use only prespecified pre-intervention state variables, never downstream scores or damage.

Respect replication structure in uncertainty estimates. A cluster or hierarchical bootstrap should resample independent trained-agent instances, then evaluation units within them, preserving branch pairs. If training runs were genuinely paired, preserve those pairs at the outer level. Shared scenario blocks can induce additional cross-agent dependence: retain block structure and use an appropriate crossed/multiway bootstrap or model. A prespecified mixed-effects or cluster-robust analysis is another option, with small-cluster limitations acknowledged. Report confidence intervals for RMST differences and the interaction. Few independent trained agents cannot be remedied solely by thousands of episodes.

Plan resources without invented effect sizes: first choose a scientifically meaningful interaction difference in time units, or a desired confidence-interval half-width, plus error rate and desired power if using hypothesis testing. Use a separate pilot or external evidence to estimate eligibility rate, censoring, between-agent variability, within-agent variability, and branch-pair correlation. Simulate candidate designs under plausible variance and effect ranges to choose numbers of independent agents and episodes. Account for primary eligibility screening costs. Prefer more independent agents when between-agent variance dominates. Freeze horizons, analysis, exclusions, and sample-size rules before confirmatory outcomes; use prespecified blinded variance re-estimation if necessary. Treat complementary and exploratory outcomes as secondary or explicitly adjust for multiple confirmatory tests.

## 8. Concrete logging and feasibility gates

Log: game/configuration hash; agent class, architecture, training seed, checkpoint and exposure; initial scenario seed; episode and pair identifiers; eligibility rule and boundary time; pre-trigger score/resources/lives; snapshot and controller-state identifiers; assignment probability and arm; random-stream identifiers; warning, queued-event and actual activation timestamps; simultaneous mechanics; every later activation attempt and suppression; relevant damage, deaths, respawns, score trajectory, terminal outcome; follow-up time, censoring reason, and technical failures.

Feasibility gates before confirmation:
- verify the named mechanic exists and its full trigger/cue ordering is understood;
- establish selective activation/suppression with no score editing, or narrow the estimand to the actual manipulable package;
- establish valid follow-up and terminal-event definitions;
- validate snapshots and controller restoration if branching is used, otherwise use ordinary randomization;
- establish independent trained-agent replication and sufficient eligible episodes for the planned inference;
- lock protocol, fidelity tolerances, horizons, and analysis before the confirmatory evaluation.

If activation/suppression is absent but an episode-start enable/disable switch is valid, only the complementary causal regime experiment is feasible. If no valid intervention is available, provide a explicitly noncausal descriptive fallback: report survival by class, score/state trajectories, eligibility rates, and remaining-survival associations at clearly defined landmarks, accounting for censoring. Adjustment or matching does not by itself identify the trigger effect; deterministic thresholds may leave no comparable untreated states. Label all trigger and architecture comparisons as associations and do not infer causality from before/after plots.

## 9. Remaining implementation decisions

Specify the game and target mechanic; exact boundary, warning and repeated-event semantics; thresholds and time units; horizons; terminal failure/respawn/success handling; supported suppression and snapshot APIs; agent-class definitions and training comparability; target population and weighting; evaluation scenario distribution; meaningful effect or precision target; and available replication resources. These are unresolved implementation decisions, not reported experimental findings.
