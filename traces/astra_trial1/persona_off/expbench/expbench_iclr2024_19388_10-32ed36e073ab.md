# Experiment design: identifying rare patterns in tabular data using Docta

## Scope and status
This is a proposed experiment, not an executed study. Two **working interpretations**, rather than confirmed source intent, are evaluated separately:

1. **Isolated rare records:** individual observations separated from the ordinary data distribution.
2. **Recurring rare multivariate subgroups:** low-prevalence collections defined by shared joint structure, including structures invisible to univariate rarity checks.

The primary testbed is controlled synthetic tabular data. A real dataset is unnecessary for this deliverable. All numbers below are proposed design choices, not documented Docta requirements.

## 1. Capability gate: what must be verified first
No authoritative Docta documentation, version, source, or examples were available locally. Before implementing the Docta arm, obtain and record the exact package identity/version and verify:

- supported tabular input types, categorical encoding, missing-value handling, and feature scaling;
- whether labels are required, their permissible form, and whether fitted predictions or a separate model are required;
- documented output semantics and score direction;
- whether outputs concern record rarity, label quality, neighborhoods, clusters, or subgroup rules;
- inductive versus transductive operation, randomness, and CPU/dependency requirements.

Do not invent API calls or infer anomaly detection from the existence of a quality score. Branch as follows:

| Verified output | Permitted evaluation and interpretation |
|---|---|
| Record rarity/anomaly scores | Evaluate isolated-record ranking and coverage of rare subgroups; a ranking alone does not establish subgroup discovery. |
| Native groups/rules | Evaluate subgroup discovery directly, plus any documented record scores. |
| Record scores but no groups | Optionally evaluate an explicitly external subgroup-extraction stage. Attribute results to a **Docta-assisted pipeline**, not native Docta subgroup discovery. |
| Label-quality diagnostics only | Supply independently generated task labels as described below. Evaluate label-error detection separately from association with rarity. A label-quality score is not assumed to be a rarity score. |
| No usable documented workflow | Complete only a specification of the proposed comparisons. The question of identifying rarity using Docta remains unanswered. |

External generation, preprocessing, baselines, and group extraction must remain separately identified in code and reporting.

## 2. Synthetic testbed and reference truth
### Shared structure
Use 10,000 rows per main table, with 12 independent standard-normal features and four categorical features. Two categorical columns, A and B, take integer-coded levels 0–7; two nuisance columns have four uniformly distributed levels. Integers are category codes, not presumed ordered measurements.

A separate variable Z ~ Normal(0,1) supports the optional supervised-label branch. It carries no rarity information. Keep generator membership, clean labels, corruption indicators, and random row identifiers in a separate evaluator-only table. Shuffle row order. Do not supply group names, generation component IDs, or derived reference-rule indicators to a detector.

Use exact planted counts for prevalence p in {0.1%, 0.5%, 1%, 5%}: 10, 50, 100, or 500 records per group. Finite-sample uncertainty at 10 members is itself an evaluation target.

### A. Isolated-record family
Ordinary numeric records follow the shared independent normal distribution. To create isolated anomalies, replace the 12-dimensional numeric vector with r·u, where u is an independently drawn uniform unit direction and r is drawn uniformly from [8,10]. Categories and Z retain their ordinary distributions.

Reference truth is generator membership. These are unusual valid observations, not malformed cells or label errors. Different random directions avoid deliberately creating one compact anomaly cluster, though especially at higher prevalence some anomalies can have nearby peers. Measure within-anomaly and anomaly-to-background nearest-neighbor distances to document whether the intended isolation holds; do not discard difficult evaluation seeds after viewing outcomes.

### B. Compact recurring-subgroup family
Replace the first two numeric coordinates of planted members with Normal(4, 0.2²), independently; other features remain ordinary. This creates a small, tight cluster, a useful contrast to isolated anomalies. It is deliberately not an interaction-only test, and univariate detectors may succeed.

Reference truth is component membership; the known generating coordinates provide feature-level reference information. There is no exact observed-data boundary because Gaussian distributions overlap, so report that uncertainty rather than treating all background overlap as a detector defect.

### C. Interaction-only recurring-subgroup family
Draw A uniformly from {0,…,7}. For planted records set B=A. For background records draw D uniformly from {1,…,7} and set B=(A+D) mod 8. Leave every other feature distributed identically between groups.

The planted subgroup is the exact rule **A=B**, with support p. Both A and B are marginally uniform in both components. Thus neither column alone reveals membership; the information lies in their joint relation. All generated values are valid and there is no cell or label corruption.

This is a recurring relational subgroup, not necessarily a tight Euclidean cluster. Its reference membership is exact and observable through a legitimate relation, not a hidden generator ID. The construction privileges a known class of relational patterns; success on it does not demonstrate arbitrary interaction discovery.

As a prespecified extension, plant two disjoint subgroups defined by D=0 and D=1, each at p, and draw background D uniformly from {2,…,7}. Evaluate recovery of each subgroup rather than allowing their union to count as two discoveries. Use this extension at p={0.5%,1%} to test multiple-group recovery without expanding the primary grid excessively.

### Generation checks before scoring
For each table, verify counts, row-order randomization, absence of truth fields from inputs, and that nuisance features and label corruption rates are not systematically tied to planted membership. Report empirical marginal differences with sampling uncertainty. Verify equal A and B marginals analytically from the generator and summarize their sample deviations; do not regenerate until an arbitrary significance test passes.

## 3. Labels if Docta requires them
Define clean task labels Y*=1[Z>0]. Keep Z as an ordinary available feature. This makes task labels predictable while remaining independent of rarity membership.

- **Clean-label condition:** provide Y=Y*.
- **Corrupted-label condition:** independently flip each label with probability 0.05, using randomness independent of features and planted membership. Preserve the flip mask only for evaluation.

Use the same underlying features in paired clean/corrupted comparisons. Do not create corruption only within rare groups; that would confound rarity with label errors. Report any finite-sample imbalance in flips by group.

If an external classifier or predictions are required, verify that requirement and produce out-of-fold predictions rather than in-sample predictions. Use the same label/model information for comparable supervised baselines, and report unlabeled rarity baselines separately. Do not use planted membership as training labels for the primary discovery experiment.

With label-quality-only outputs, evaluate both label-error PR-AUC and rarity-ranking metrics, but name the latter **association between label-quality scores and rarity**. Success only on corrupted labels supports error diagnosis, not rare-pattern discovery. Consistent rarity enrichment on clean labels could support a limited, externally validated screening use, but not prove native rarity or subgroup detection. If no useful rarity ranking or recoverable groups result—or no valid required label workflow is available—the proposed Docta rarity question remains unanswered even if label-error detection works well.

## 4. Development, evaluation, and replication
Use disjoint random-seed lists fixed before analysis:

- **Development:** 10 seeds per primary family/prevalence setting, used to select preprocessing, documented options, thresholds, and any external extraction parameters.
- **Evaluation:** 30 fresh seeds per setting, with all choices frozen.
- **Multiple-group extension:** 10 development and 30 evaluation seeds at each of its two prevalence settings.

The primary feature-data grid contains 3 families × 4 prevalences × 30 evaluation seeds = 360 evaluation tables. The extension adds 60. These are modest tables, but total runtime remains unverified. Run the clean-label branch first if labels are required; treat the paired corruption branch as an additional, explicitly budgeted analysis.

Where inductive fitting is supported, generate independent fit and score tables with the same mechanism and 10,000 rows each; use fitting-table preprocessing only. Do not assume an anomaly-free fitting set. If Docta is transductive, score each table as a whole and describe that protocol; evaluation seeds and truth still cannot influence model selection. Avoid comparing inductive and transductive results as if their information access were identical.

## 5. External preprocessing, baselines, and extraction
### Preprocessing
Use a development-selected pipeline: median/IQR scaling for numeric features and one-hot encoding for nominal categories when appropriate. Fit transforms only on permitted fitting data; in a transductive analysis, explicitly disclose whole-table fitting. No missingness is introduced in the primary study. Preserve a raw categorical view for relation-based group search.

### Record baselines
Compare with random ranking, a univariate tail/category-frequency score, k-nearest-neighbor distance, and Isolation Forest. Select a small, prespecified development grid, such as k in {10,30,100}. Record algorithms and implementation versions at implementation time. Give all methods the same raw information and disclose method-specific encodings. These baselines are external to Docta.

### Subgroup comparisons
If native groups exist, evaluate them directly. Otherwise, an optional external score-to-group stage may search a bounded library of candidate groups: numeric intervals or two-feature rectangles and categorical equalities, pairs, and pairwise relations. Apply the identical library to baseline scores.

For the interaction test, include all eight modular-offset relations for eligible eight-level categorical pairs, not just the true offset. This is a **restricted-library evaluation**; report it separately from unrestricted native discovery because the library deliberately contains the reference rule. Candidate membership may be computed from observed features, never hidden truth.

For each candidate, compute support and enrichment among the top-ranked records. Use development/null-calibrated enrichment thresholds, restrict support to [0.05%,10%], and suppress near-duplicate groups using development-fixed membership overlap rules. Freeze the rule library and search budget before evaluation. Include a direct support-based ranking of the same candidate library to show whether Docta scores add value beyond the external search itself.

## 6. Controls
1. **Matched no-plant controls:** no radial anomalies, no compact cluster, and independent uniform A and B for the interaction family. The interaction null gives each offset probability 1/8 rather than treating the same deliberately depleted relation as a null.
2. **Column-shuffled controls:** independently permute feature columns within a table, preserving marginals while breaking multivariate relations. These are primarily interaction controls; numeric marginal outliers can survive shuffling.
3. **Random-score controls:** quantify chance ranking and score-to-group extraction behavior.
4. **Prevalence sweep at fixed geometry:** separates frequency sensitivity from changes in anomaly distance or cluster separation.
5. **Ordinary rare-category contrast:** a supplementary table with a 1% valid category independent of all other features. This distinguishes simple category-frequency detection from interaction recovery.
6. **Clean versus independent label flips:** where relevant, separates rarity from label corruption.

Use 100 independent null-development tables to calibrate the entire external group-search procedure, for example the maximum enrichment over the candidate library for a nominal 5% probability of any false group. Then use 30 independent null-evaluation tables per relevant setting to estimate the observed probability of any discovery and number of discoveries. Finite Monte Carlo resolution and confidence intervals must be reported; do not assert exact error control for native methods or unvalidated thresholds.

## 7. Outcomes and analysis
### Record-level outcomes
Use precision–recall AUC, reporting the prevalence baseline, and precision/recall at inspection budgets k={10,50,100,500} rows, equivalent to {0.1%,0.5%,1%,5%} of a 10,000-row table. Also report background false-positive rates. Use reproducible randomized tie-breaking and do not select k using evaluation truth. Report each family separately; optionally report ROC-AUC only as a secondary measure.

These metrics test ranking against planted membership. They do not by themselves establish discovery of a recurring pattern.

### Group-level outcomes
Convert returned rules/clusters into evaluation-table membership sets. Match discovered and reference groups one-to-one by maximum total Jaccard overlap, accepting matches only when Jaccard ≥0.5. Report sensitivity at thresholds 0.25 and 0.75 without replacing the primary threshold.

Report:
- group precision and recall;
- membership precision, recall, and Jaccard for matched groups;
- unmatched and duplicate discoveries;
- exact/logically equivalent relation recovery for the interaction family, where interpretable rules are returned;
- recovery of generating features, where output semantics permit it;
- null probability of any group discovery and mean false-group count.

Merged groups cannot match multiple reference groups. At single-group settings, group recall is essentially a per-table success indicator; summarize over seeds. If no groups are returned, group-level performance is unavailable unless an explicitly external extraction stage is evaluated.

### Uncertainty and comparisons
Use paired seeds across methods and 95% seed-level bootstrap intervals for metrics and paired differences. Treat seeds, not individual rows, as independent replication units. Use binomial intervals for null discovery proportions. Report all prevalence settings and distinguish exploratory contrasts from prespecified comparisons; use Holm correction if making formal claims across multiple method/family comparisons.

Inspect failure cases using evaluator truth only after metrics are fixed. Important failure modes include tiny groups, tight clusters with low within-group distance, diluted numeric distance in nuisance features, encoding sensitivity, and relation-library bias. Do not tune on these evaluation failures and then report the same seeds as held-out evidence.

## 8. Feasibility and interpretation
No GPU is planned. Store generator seeds and summary results, stream independent tables, and cap subgroup libraries rather than attempting exhaustive conjunction mining. A later CPU pilot on development data should measure time/memory, especially for nearest-neighbor calculations, repeated fits, and null searches. Set a runtime budget before expanding; if reductions are necessary, freeze and disclose a smaller balanced evaluation grid before examining its results.

Possible conclusions are conditional:
- Successful documented record scoring supports rare-record screening under the tested distributions.
- Recovery of interaction groups with correct membership supports rare-subgroup discovery only for the tested representation and search procedure.
- Improvement only after external extraction supports that combined pipeline, with the direct-library baseline indicating the incremental contribution of Docta.
- Label-error performance alone does not answer the rarity question.
- Absent a verified Docta workflow, baseline and generator specifications cannot establish that Docta identifies rare patterns.

The study would not establish business importance, causality, real-world usefulness, detection of arbitrary interactions, or a universal definition of rarity. Rare observations may be perfectly valid. Synthetic results would require later domain-specific validation before operational use.
