# Experiment design: runtime clipping versus perplexity on LLAMA2-7B

## 1. Status and scope

This is a design, not a report of executed experiments. Neither the perplexity curve nor a numerical optimal clipping ratio is presently known.

**Fixed requirements:** LLAMA2-7B; symmetric input quantization; asymmetric cached-key/value quantization; runtime clipping as the intervention; perplexity as the accuracy endpoint. Source-topic clarification establishes only LLAMA2-7B (setup_1), asymmetric cached K/V quantization (setup_10), and perplexity (setup_17). Symmetric input quantization comes from the question.

**Everything below specifying an implementation, dataset, precision, ratio convention, or decision threshold is a proposed assumption**, not recovered source intent. The researcher approved the proposed shared retained-range multiplier and stream-specific clipping controls. The resulting optimum will be conditional on this configuration and searched range.

## 2. Concrete primary configuration

| Item | Proposed choice |
|---|---|
| Checkpoint | `meta-llama/Llama-2-7b-hf`, base model, not chat; record immutable revision, tokenizer files, and hashes before execution |
| Reference | Evaluation mode, no dropout; FP16 weights and persistent unquantized activations/cache; FP32 range calculations, quantization arithmetic, and loss accumulation; use the same attention backend in all arms |
| Weights | Unquantized FP16 throughout, including embeddings and output head |
| Bit widths | 4-bit input activations, 4-bit cached keys, 4-bit cached values |
| Input sites | Inputs to every layer's `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, and `down_proj`; no added quantizer on embeddings, residual additions, normalization outputs except as consumed by these listed operators, or the language-model head |
| Input granularity | Independently for each token and contiguous group of 128 input channels; final partial group permitted; identical shared source activations entering Q/K/V or gate/up reuse the same quantized representation |
| Cache granularity | Independently for each token, layer, head, and K/V stream, across the complete 128-dimensional head vector |
| Cache positions | Quantize keys after RoPE and values after value projection; never quantize keys before RoPE in this configuration |
| Primary ratio | One constant r shared across all specified inputs, keys, and values; ranges still depend on the current tensor group |
| Context | Independent blocks of at most 2,048 tokens; batch size one for the correctness/reference implementation |
| Dataset | Hugging Face `wikitext`, configuration `wikitext-2-raw-v1`; pin revision and record content hashes |

Four bits deliberately provide a substantial accuracy stress test; this does not imply that four bits were intended by the source. Grouped input activations limit outlier coupling. Per-token/head cache ranges are causally simple and avoid retroactively changing old entries. Other granularities, especially channel-wise keys, could produce different conclusions.

## 3. Exact quantizer arithmetic

Use round-to-nearest, ties-to-even, denoted RN. All statistics refer to the unquantized, current group entering the relevant quantizer in that arm. Reject NaN/Inf inputs as implementation failures. Perform calculations in FP32 and cast reconstructed tensors back to FP16 for model computation. Clamp integer codes after rounding as a numerical safeguard.

### Symmetric inputs

For a group x, set a=max|x| and c=r a. Use signed integer codes q in {-7,…,7}; the remaining possible four-bit pattern is unused. The zero point is exactly zero.

If a=0, return all zeros with q=0 and scale s=0, handled explicitly without division. Otherwise:

- s=c/7;
- x_clip=clip(x,-c,c);
- q=clip(RN(x_clip/s),-7,7);
- x_hat=s q.

Thus both symmetric endpoints are exactly representable in the ideal arithmetic. Choosing 15 symmetric levels rather than an uneven {-8,…,7} range is intentional and must be recorded.

### Asymmetric K/V: endpoint-affine quantization

For each current K or V group, let m=min(x), M=max(x), d=M-m, and h=m+d/2. Contract the observed interval about its midpoint:

- L=h-r d/2;
- U=h+r d/2.

Use unsigned codes q in {0,…,15}. If d=0, store a constant group: offset L=m, scale s=0, q=0, reconstruction m. Otherwise:

- s=(U-L)/15;
- x_clip=clip(x,L,U);
- q=clip(RN((x_clip-L)/s),0,15);
- x_hat=L+s q.

This is an **endpoint-affine quantizer with a floating offset**, equivalently x_hat=s(q-z) with real zero point z=-L/s. Store FP32 L and s; do not round z to an integer. L and U are representable endpoints up to floating-point precision.

An interval that excludes zero is valid: z can lie outside [0,15], and zero need not be representable. Even when zero is inside the interval, its real zero point need not be integral. Do not force inclusion of zero or round/clip z; either change would alter the stated contraction. This explicit representation is asymmetric, but is not a conventional integer-zero-point kernel contract. It may require a custom kernel for deployment. At r=1 no observed values are range-clipped, though they still incur rounding error.

The main study uses exact FP32 metadata in a numerical simulation. Packing codes or reducing metadata precision is a separate implementation validation, not an unnoticed change to the quantizer.

## 4. Causal inference and scoring protocol

Use the tokenizer without automatic BOS/EOS insertion or chat formatting. For each official dataset split, concatenate the provided text rows in their recorded order with a single newline separator, preserving empty rows. Tokenize once and store token IDs and a hash. Do not concatenate across splits.

Partition each resulting stream into nonoverlapping blocks of 2,048 tokens; retain a final block if it contains at least two tokens. Within every block:

1. Reset all caches and reset position IDs to zero.
2. Feed tokens t_0,…,t_(n-2), one at a time, with cache enabled and a causal mask.
3. The logits after t_j score target t_(j+1). Do not score the first token of a block; do not score transitions across block boundaries.
4. At each layer, compute the current key/value, quantize them, append their codes/metadata, and use the reconstructed cache for attention, including the current token. There is no parallel persistent FP16 cache in the quantized arm.
5. Freeze each entry's metadata and codes on insertion. Never recompute its range using later tokens. Input statistics use only the current token/group. Use no cache eviction, sliding window, chunked-prefill quantizer, or dynamic scaling policy in the primary experiment.

This intentionally simple one-token protocol ensures that actual quantized cache consumption is tested. A full-sequence forward pass that bypasses this cache is not an acceptable substitute. All arms use identical blocks, positions, target masks, and inference structure.

Compute each target loss with FP32 log-softmax, sum losses in FP64 offline, and report

NLL = (sum of all scored target losses)/(number of scored targets), PPL=exp(NLL).

Do not average block perplexities. Report the scored-token count and the number of omitted boundary targets. This defines a reproducible PPL protocol, not a claim of equivalence to every published WikiText benchmark.

## 5. Data roles and ratio search

- **Diagnostics/calibration:** first 128 blocks from the training split. No learned clipping parameters or weight calibration are needed; use these blocks for instrumentation and implementation checks only.
- **Selection:** the complete official validation split under the specified blocking protocol.
- **Final assessment:** the untouched official test split. Do not inspect test losses when choosing or refining ratios.

Primary validation sweep:

r ∈ {1.00, 0.99, 0.975, 0.95, 0.925, 0.90, 0.85, 0.80, 0.70, 0.50}.

This is a retained-range multiplier: smaller r means stronger clipping, not a retained percentile. Exclude r=0.

**Bounded expansion:** if the current empirical validation NLL minimizer is the smallest searched ratio, add 0.25; if that becomes the minimizer, add 0.125; if that becomes the minimizer, add 0.0625. Stop expansion at 0.0625. Exact minimizer ties go to larger r. If the final minimum is at this lower boundary, explicitly report that the search did not establish an interior optimum.

**Bounded refinement:** after expansion, let r_b be the best searched ratio. Add r_b+0.005k for integer k=-5,…,5, retaining values in [0.0625,1]. Deduplicate using exact decimal representations. Perform this one refinement round only; no test-directed or unlimited refinement. The final candidate set has at most 23 ratios.

## 6. Selection returning one fixed operating ratio

Report two distinct quantities:

1. **Empirical NLL minimizer:** r_min, the tested ratio with the smallest validation NLL; break exact ties toward larger r.
2. **Accuracy-equivalent operating choice:** use the proposed practical tolerance ε=0.001 nats per scored token. Define E={r: NLL_val(r)≤NLL_val(r_min)+ε}. This corresponds to a PPL factor of at most exp(0.001), approximately 1.001, relative to the validation minimum. It is a proposed practical tolerance, not a statistical equivalence result.

For deterministic selection, sort the tested ratios. Partition E into runs consecutive in that tested list; a non-equivalent tested ratio breaks a run. Select the run with the largest endpoint span. If spans tie, choose the run with the lowest minimum NLL; if still tied, choose the run with the larger upper endpoint. Within that run choose the tested ratio nearest its endpoint midpoint; break a distance tie by lower validation NLL, then larger r.

The selected r_op is the one fixed operating ratio. This favors the center of a broad *observed* accuracy-equivalent region rather than a potentially sharp minimum. It does not certify untested points between candidates. If only one candidate qualifies, select it. If r_op differs from r_min, explicitly report both and their validation NLL/PPL difference.

Reconstruction error remains a secondary diagnostic, not an arbitrary weighted addition to NLL. Before any test scoring, freeze candidate scores, r_min, r_op, controls, and analysis code in a selection manifest. Never change r_op in response to test results.

## 7. Controls and held-out comparisons

Evaluate these primary test arms:

- FP16 reference with no quantizers;
- all specified quantizers active at r=1;
- all specified quantizers active at the frozen r_op;
- r_min as a separately labeled secondary accuracy arm if it differs from r_op.

On validation and test, also evaluate the following diagnostic controls at r_op, without allowing them to alter selection:

- input quantization only, with floating-point K/V cache;
- K/V quantization only, with unquantized projection inputs;
- all quantizers enabled, but only input clipping active: (r_input,r_K,r_V)=(r_op,1,1);
- all quantizers enabled, but only cache clipping active: (1,r_op,r_op).

Input-only and cache-only quantization at r=1 provide corresponding uncontracted ablation anchors. If resources permit, precommit K-only and V-only clipping controls (1,r_op,1) and (1,1,r_op). Quantization-only ablations and clipping-only ablations answer different questions and must not be conflated.

Primary held-out contrasts are r_op versus r=1 and r_op versus FP16. Report NLL differences, PPL values and ratios, and token counts. A frozen secondary 1,024-token context check on the test split can assess context sensitivity; it cannot retune the ratio and must be labeled secondary.

## 8. Quantization-error and mechanism diagnostics

Use the fixed training diagnostic blocks and collect bounded per-layer/head/stream aggregates rather than all activations:

- pre-rounding clipping rate: fraction outside the contracted bounds;
- final endpoint-code occupancy, separately, since rounding can produce endpoint codes without clipping;
- clipping MSE between x and x_clip;
- rounding MSE between x_clip and x_hat;
- total MSE between x and x_hat, normalized by mean(x²)+10^-12;
- mean signed error, maximum absolute error, range widths, scales, and fraction of degenerate groups;
- K/V-specific summaries by layer/head and token position;
- attention-output error by query position and the age of keys/values used, where practical;
- FP32 logit KL divergence against the reference on a fixed subset of token positions.

Do not assert that clipping MSE plus rounding MSE equals total MSE; a cross term can exist. Compute local quantizer diagnostics on identical reference tensors for clean paired comparisons. Separately collect diagnostics from each quantized model trajectory, where upstream error changes the tensors themselves. Quantization error in a stored entry is fixed; cache-age-dependent effects arise from how later queries use that entry.

Interpretation: stronger contraction reduces quantization step sizes but loses extreme values. The experiment tests which effect dominates and where; neither monotonic PPL nor an interior minimum is assumed.

## 9. Uncertainty and reporting

Save per-block loss sums and target counts for every arm. For each predeclared contrast use 2,000 paired bootstrap replicates of contiguous runs of four evaluation blocks, drawing the same block indices for both arms and recomputing token-weighted NLL and derived PPL ratios. Treat the last incomplete run explicitly. Report percentile 95% intervals and a one-block resampling sensitivity analysis. These are approximate corpus-sampling intervals; blocks are not independent tokens, and the dataset has limited independent content.

The held-out confidence intervals are conditional on the validation-selected policy, not a complete measure of uncertainty in the selected ratio. Report the full validation curve, E, search boundaries, and any separation between r_min and r_op. State whether r_op improves held-out PPL over r=1, and quantify its gap to FP16 even if no improvement occurs. An accuracy-equivalent validation choice is not automatically statistically equivalent on test. Label ablations and secondary-context checks exploratory/secondary rather than searching them for a new winner.

## 10. Feasible staged implementation and resource plan

**Stage A — inexpensive correctness checks:** CPU synthetic tests of symmetric sign behavior, integer code bounds, ties-to-even rounding, endpoints, positive-only/negative-only asymmetric intervals, zero and constant groups, r=1 behavior, and FP32 reconstruction. Verify clipping reduces the represented range monotonically. Test cache immutability and storage metadata.

**Stage B — model plumbing:** on a future equipped environment, instrument one or two short blocks. Confirm the no-quantization cached path agrees within declared numerical tolerance with the same model's noncached causal reference. Disable quantizers to verify hook transparency. Check that changing a future suffix leaves prior logits, codes, and metadata unchanged. Inspect every cache read to confirm it derives from codes plus metadata; perturb an old cached code and check reconstruction and downstream logits, ruling out a bypassed FP16 cache. Assert the intended site/head/group counts and position IDs.

**Stage C — smoke test and cost estimate:** run a small training-only diagnostic subset at r=1 and one stronger ratio, check finite losses, and measure tokens/second and peak memory. This is an implementation gate, not evidence for selecting r. Finalize and version tolerances and implementation fixes before the validation sweep.

**Stage D — validation and freeze:** execute the bounded candidate search, diagnostics, and controls; record all configurations and freeze the selection manifest.

**Stage E — held-out assessment:** score the frozen arms, bootstrap paired comparisons, and write the conditional conclusion.

A future accelerator with roughly 24–48 GB memory is a reasonable starting target, subject to measurement: 7B FP16 weights alone require about 14 GB decimal; a 2,048-token FP16 K/V cache is about 1 GiB for this architecture, before activations and workspaces. Packed four-bit K/V codes would be about 0.25 GiB plus metadata; fake quantization may not achieve that saving. Avoid storing a full reference trajectory or simultaneously resident duplicate models. Sequential runs and online diagnostic aggregates keep memory manageable. Token-by-token inference and a multi-ratio sweep may be slow; benchmark before scheduling and parallelize independent arms across available devices rather than changing the causal protocol. No latency or memory improvement is claimed by the accuracy simulation.

The current environment cannot support the proposed model evaluation as supplied: no GPU, no model/data inputs, and disabled network. Checkpoint authorization, pinned data artifacts, framework dependencies, and a suitable accelerator must be provisioned later. This does not prevent completing the design.
