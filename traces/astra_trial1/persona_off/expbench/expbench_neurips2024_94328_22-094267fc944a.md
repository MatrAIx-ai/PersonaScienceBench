Minimum scope: LLaMa-2 base 7B. Conditional extensions: base 13B and 70B. The operational QuaRot target is W4A4 with packed 4-bit K and V cache storage, subject to verification and documented exceptions. Primary results concern device execution time; wall-clock request metrics are supplemental.

## 1. Systems and verification gates
**Proposed hardware:** one dedicated NVIDIA A100 80 GB SXM GPU for 7B and, if feasible, 13B. For 70B propose four A100 80 GB SXM GPUs on one NVLink-connected node, with tensor parallelism of four for both methods. Do not compare a multi-GPU FP16 run with a single-GPU QuaRot run as a paired speedup. These are planning choices, not supplied hardware facts. Record host CPU/RAM, GPU clocks, power limits, topology, driver, CUDA, framework, compiler, implementation commit, and kernel versions. Disable unrelated GPU workloads and keep power/clock policy fixed.

**Baseline:** identical base checkpoint and tokenizer, FP16 weights, floating activations, and FP16 KV cache, with documented higher-precision reductions/accumulators. Use an optimized compatible attention implementation, not an intentionally slow reference baseline. No CPU offload or cache eviction in shared-fit trials.

**QuaRot gate:** inspect configuration and kernel dispatch, then perform a small future smoke test/profile. Confirm packed 4-bit weight storage and actual low-bit compute pathways; describe activation quantization granularity, scales, clipping, and transient representations. Confirm *both* K and V are packed at 4 bits, with real scale/metadata allocation included. Inventory exceptions such as embeddings, output head, normalization, residuals, softmax, accumulators and temporary dequantized buffers. Check each benchmark mode—including decoding—uses the intended path. A fake-quantized FP16 implementation or an FP16 KV cache does not satisfy this target. Record backend, fusion, graph capture, padding and cache allocation policies for both systems. Use consistent GB/GiB units in the actual report.

Estimate cache payload as
`2 × layers × batch × allocated_sequence_length × KV_heads × head_dim × bytes_per_element`.
Use checkpoint configuration, especially KV-head counts rather than attention-head counts. For FP16 use 2 bytes; for the packed target use 0.5 bytes plus actual metadata/alignment. Account for each implementation's reservation policy, and verify actual per-rank allocations under tensor parallelism rather than assuming perfect sharding. **Decode work convention:** prefill computes logits for the P prompt positions and populates P cache entries. **Prefill:** start after a usable cache arena has been established but before required per-request cache setup/reset and model execution; end when prompt logits and the P-entry cache are available. Report maximum supported batch and throughput at that batch, but never label unequal-batch throughput ratios as paired speedups. Report quantized-only feasible cells as capacity benefits, with no invented FP16 latency.

## 7. Limited quality-validation gate
Acquire model/tokenizer access under the applicable LLaMa-2 terms and record hashes. Keep quantization calibration data separate from timing/quality evaluation. Before timing, test finite logits, expected tensor/cache shapes, correct cache positions, and cached versus noncached forward consistency within implementation-appropriate tolerances. Evaluate held-out next-token negative log-likelihood/perplexity over a fixed 128×2048-token set (or document a licensed equivalent), including a streaming cached path that exercises quantized K/V. Also use a small deterministic generation sanity set to catch corrupt outputs. This is a limited screening criterion, not a guarantee of downstream quality or a claim about expected degradation. ## 8. Attribution and interpretation
The primary estimand is the performance of two deployable implementation stacks at equal work, not an isolated causal effect of bit width. Different attention kernels, fusion, tensor-core utilization, layouts, launches, graph support and tensor-parallel communication can explain some gains or losses. A faster QuaRot stack demonstrates end-to-end performance under the documented conditions; it does not by itself prove that every gain comes from quantization or that other GPUs will behave similarly. Optional diagnostics—floating-point rotated model, W4A4 with FP16 cache, and targeted kernel profiles—can help separate rotation, cache and kernel effects if supported, but are not prerequisites and must not replace the main verified configuration.
