### Event 4 — Actor

**Answer**

````text
## Objective and contract
Design, but do not execute, an experiment evaluating a program that sorts a list of words and returns one space-separated line.

**Source-stated requirements:** alphabetically sort a list of words; return them on one line with spaces between words.

**Approved experimental contract:** input is a Python list of nonempty strings containing no whitespace. Preserve each string exactly and retain all occurrences, including duplicates. Output is a string joined by exactly one ASCII space, with no leading or trailing whitespace and no newline. An empty list returns `""`. No raw-text tokenization or normalization is performed.

**Explicit ordering assumption:** use case-sensitive Unicode code-point lexicographic ordering, as implemented by Python string comparison. This is an experimental convention, not a source-confirmed definition of “alphabetical.” The core scope consists of lowercase ASCII words. Mixed case, punctuation, and accented characters are convention-specific extensions.

## Proposed implementation
```python
def sort_words(words):
    return " ".join(sorted(words))
```
`sorted` produces a new list, preserving the input list and duplicate occurrences; `join` supplies exactly the required separators and naturally returns the empty string for an empty list. No validation or behavior for invalid inputs is part of this design. This simple algorithm directly separates ordering from rendering and needs only standard Python.

## Independently specified oracle cases
Expected strings below are literal, hand-specified oracles, not generated by calling the proposed implementation or another `sorted` expression. Quotes delimit strings and are not part of the output.

| Scope / purpose | Input list | Expected output string |
|---|---|---|
| Core: empty | `[]` | `""` |
| Core: singleton | `["kiwi"]` | `"kiwi"` |
| Core: ordinary unsorted | `["pear", "apple", "banana"]` | `"apple banana pear"` |
| Core: sorted control | `["apple", "banana", "pear"]` | `"apple banana pear"` |
| Core: reverse-sorted control | `["pear", "banana", "apple"]` | `"apple banana pear"` |
| Core: duplicates | `["pear", "apple", "pear", "apple"]` | `"apple apple pear pear"` |
| Core: all identical | `["fig", "fig", "fig"]` | `"fig fig fig"` |
| Core: prefixes | `["apple", "app", "apricot", "a"]` | `"a app apple apricot"` |
| Core: lexicographic, not length order | `["b", "aa", "a"]` | `"a aa b"` |
| Extension: mixed case | `["apple", "Banana", "Apple", "banana"]` | `"Apple Banana apple banana"` |
| Extension: punctuation | `["apple", "apple!", "!apple", "apple-"]` | `"!apple apple apple! apple-"` |
| Extension: accented letters | `["éclair", "zebra", "eagle", "Éclair"]` | `"eagle zebra Éclair éclair"` |

The extension oracles follow the declared code-point convention: uppercase ASCII precedes lowercase ASCII; punctuation is significant; `É` and `é` follow ASCII letters. Prefixes sort before longer strings having that prefix. These extension expectations must not be represented as locale-aware dictionary ordering.

## Measurements and correctness checks
For every test, record the input, scope, expected output where available, actual output, and separate Boolean results for the following checks. Exceptions or non-string returns fail valid-input cases.

1. **Exact oracle match:** actual string equals the hand-specified expected string, character for character.
2. **Ordering:** decode the returned string as described below and check each adjacent pair is nondecreasing under Python string comparison. This validates the property without sorting the input to create an oracle.
3. **Multiset preservation:** compare `collections.Counter(decoded_output)` with `collections.Counter(input_words)`. Counts and spelling must match exactly.
4. **Exact formatting:** an empty input must produce `""`. For a nonempty input, the result must be nonempty, contain no whitespace other than ASCII separators, have no leading/trailing space, and contain no empty fields when split on `" "`. Rejoining the fields with `" "` must reproduce the result exactly. These checks, together with preservation, enforce the contract.
5. **Permutation invariance:** for each base list, every tested rearrangement must yield the same output as the original. Enumerate all distinct permutations of small cases using `itertools.permutations`; deduplicate repeated tuples for duplicate inputs. For larger optional cases use deterministic seeded shuffles and record the seed and number of shuffles.
6. **Repeat-sort invariance:** a list-to-string function cannot validly be called directly on its own string result. Define a test-only decoder `decode("") = []`, otherwise `decode(s) = s.split(" ")`, applied only after output-format validation. Require `sort_words(decode(sort_words(words))) == sort_words(words)`. This is a canonical-output round trip, not raw-text input support. It is unambiguous because input words cannot contain whitespace.

**Pass criteria:** every valid core oracle case must pass exact equality, ordering, preservation, formatting, and applicable invariance checks. There is no allowed error rate. Report extension results separately; passing the complete approved code-point contract requires all selected extension cases as well. A property failure is a failure even if another property passes. Invariance alone is insufficient: for example, always returning an empty string is invariant but violates the other checks. Passing this finite suite supports correctness within the tested contract; it is not proof for all possible lists.

## Controls and fault injections
Already-sorted, reverse-sorted, singleton, and empty inputs are functional controls with known outcomes, not runtime benchmarks. Validate the test harness using deliberately incorrect variants, kept separate from the candidate:

| Injected fault | Detecting case / check |
|---|---|
| Return descending order | Ordinary or reverse-sorted case; oracle and ordering |
| Leave input order unchanged | Unsorted or reverse-sorted case; oracle and ordering, permutation invariance |
| Remove duplicates using a set | Duplicate case; oracle and multiset preservation |
| Drop a word or append an extra word | Singleton or ordinary case; oracle and multiset preservation |
| Join with two spaces, or add a leading/trailing space or newline | Nonempty cases; exact equality and formatting |
| Sort by length rather than lexicographically | `["b", "aa", "a"]`; oracle and ordering |
| Lowercase the returned words | Mixed-case extension; oracle and multiset preservation |
| Use a case-insensitive comparison key | Mixed-case extension; oracle and code-point ordering |

Each listed faulty variant must be rejected by at least its designated check. If a mutant survives, investigate the harness or coverage before accepting candidate results. Do not require every mutation to fail every check: a reversed output can preserve the multiset and formatting correctly.

## Feasible implementation and analysis plan
Use a standard-library-only Python module for the function and a `unittest` test module containing the literal oracle table and property helpers. Use `collections.Counter` for preservation, `itertools` for small permutations, and optionally `random.Random` with a recorded fixed seed for reproducible generated lowercase ASCII lists. Generated cases can vary list size, word length, common prefixes, and duplicate frequency; use the property checks rather than deriving expected strings with the same sorting implementation. Fix any optional sample sizes before execution and report them, rather than implying an unspecified sampling effort gives exhaustive coverage.

A future implementation can be checked locally with `python3 -m unittest -v`; no network, third-party dependencies, dataset, or GPU is needed. First review the oracle strings, then exercise the harness against fault injections, then test the candidate. Summarize counts of cases and checks attempted/passed/failed separately for core and extensions. For failures retain the exact input and escaped expected/actual strings so whitespace faults are visible. No timing study or statistical significance analysis is needed for these deterministic correctness assertions.

## Resource complexity
Let `n` be the number of words, `C` their total character count, and `L` their maximum length. Comparison sorting takes at most `O(n log n)` comparisons; string comparisons can inspect up to `O(L)` characters, giving a coarse worst-case sorting bound of `O(n log n · L)`. Joining takes `O(C + n)` work and output space. The sorted list and sorting workspace require `O(n)` auxiliary references; strings need not be copied for sorting. Total additional space including the output is `O(n + C)`. These are asymptotic estimates, not measured runtimes or imposed budgets. Exhaustive permutation testing grows factorially, so restrict it to the small controls; it is a harness cost, not the program's complexity.

## Remaining limitations
Locale-aware collation, case folding, canonical Unicode equivalence, normalization, punctuation removal, raw-text parsing, invalid input behavior, command-line transport, and file I/O are out of scope. If they become requirements, revise both the contract and its oracles first. No experiment has been executed and no correctness or performance outcome is claimed.
````
