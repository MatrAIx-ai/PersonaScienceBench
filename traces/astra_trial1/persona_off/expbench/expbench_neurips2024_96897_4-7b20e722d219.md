# Experiment design: BAdam perturbation spectra versus Adam

## 1. Status, question, and scope

This is a proposed experiment, not a report of an executed study. The supplied material specifies only the scientific question and that the deliverable is design-only. All model/task selections, optimizer configurations, budgets, numerical thresholds, and statistical tolerances below are proposed choices, not source-confirmed settings.

The study asks two separate questions:
1. Do BAdam's cumulative learning perturbations have singular-value tails consistent with heavy-tailed behavior?
2. Are their effective ranks practically equivalent to Adam's, for corresponding transformer matrices?

A positive answer to one does not imply a positive answer to the other. Heavy tails in Adam are also measured, but cannot substitute for evidence about BAdam. Conclusions apply to the selected model, task, training regime, and sampled modules—not transformers or BAdam variants generally.

## 2. Core model, task, and arms

### Proposed model/task
- Model: the base GPT-2 checkpoint, approximately 124M parameters, with 12 transformer layers, hidden width 768, and MLP width 3072. Verify these dimensions against the actual pinned configuration before execution.
- Task: causal-language-model finetuning on WikiText-2, using its standard train/validation/test splits and GPT-2 tokenizer. Pin model/tokenizer revisions, dataset version, document handling, and preprocessing.
- Pack training documents with end-of-document separators into length-512 sequences; do not mix data between splits. Use a fixed effective batch of 16 sequences, or 8,192 nonpadding tokens per optimizer step, through gradient accumulation if necessary.
- Train for 600 optimizer steps: 4,915,200 training tokens per main run. Cycle through training data as necessary, reshuffling reproducibly at epoch boundaries. This is a modest adaptation study, not a claim that this budget is optimal or prevents overfitting.

### Optimizer arms
The proposed primary BAdam target is a **blockwise, whole-layer/block Adam variant**, not a coordinate-sparsified or adapter-only variant. A real implementation must be identified and pinned before execution; the supplied inputs contain none.

Proposed executable configuration:
- Six blocks, each containing two consecutive transformer layers.
- Put token/position embeddings in block 0 and final layer normalization in block 5. GPT-2's tied token-embedding/output weight is one parameter object and belongs only to block 0; do not duplicate it in the schedule.
- Activate one block for 10 consecutive optimizer steps. Visit blocks 0–5 in cyclic order, giving a 60-step cycle and 10 cycles overall. Inactive parameters are frozen and receive neither gradient updates nor weight decay.
- Proposed state policy: discard moments when leaving a block; on reactivation initialize its moments and local bias-correction clock anew. This is a substantive choice, not a generic property asserted of BAdam. Record actual state behavior, including counters, from the chosen implementation.
- Proposed underlying update: AdamW, with β1 = 0.9, β2 = 0.999, ε = 10⁻⁸, and decoupled decay 0.01 on matrix weights, excluding bias and normalization parameters.

With this configuration, use **three separately identified arms**:
1. BAdam with the proposed AdamW-based block update.
2. Full-parameter AdamW: mechanistic comparator matching the underlying update convention, without block freezing or scheduled moment resets.
3. Literal full-parameter Adam: original coupled-L2 update, coefficient 0.01 on the same parameter groups, clearly distinguished from AdamW. This is the arm that directly addresses the wording 'comparable to Adam.'

Use the same betas, epsilon, precision, clipping rule, parameter grouping, and learning-rate schedule form wherever meaningful. The equal numerical decay coefficient does not make coupled and decoupled regularization equivalent; the AdamW arm makes that distinction visible.

**Implementation-dependent substitutions:** perform a short implementation audit before registering the protocol. If the chosen BAdam supports an Adam rather than AdamW backend, make literal Adam its matched comparator; the extra AdamW arm becomes optional. If moment retention, block grouping, or step-clock semantics cannot be configured as above, document the supported behavior and revise the protocol before outcomes are inspected. Do not silently modify a library and call the resulting method the established BAdam variant. A failure to identify a suitable implementation means the BAdam study cannot yet proceed; a custom emulation would need its own label.

## 3. Training controls, tuning, and replication

- Same pretrained initialization in every arm. Pair seed IDs across arms, including data order, dropout seeds, and evaluation subsets. Five independent paired training seeds are the proposed main replication target. Pairing improves precision but need not make random-number consumption identical in every implementation.
- Primary budget: equal training-token exposure. Each arm sees the same minibatches at the same step indices. BAdam has only 100 active update steps per block by the end; Adam and AdamW update all blocks 600 times. Do not call these equal-update or equal-compute comparisons.
- Proposed schedule: 30-step linear warmup followed by cosine decay to 10% of peak learning rate, indexed by global optimizer step. Record how this interacts with BAdam's local moment clock. Global gradient-norm clipping at 1.0 is computed over the parameters actually receiving gradients; log pre/post-clipping norms and frequencies because the active sets differ.
- Equal tuning opportunity: peak learning rates {1×10⁻⁵, 3×10⁻⁵, 1×10⁻⁴}; one separate paired tuning seed; one full 600-step trial for each candidate per arm. Select the candidate with the lowest final validation negative log-likelihood, subject to numerical stability, using a predeclared deterministic tie-break. Thus, with three arms, tuning requires nine runs and the main experiment fifteen runs. Do not select learning rates using rank or tail results.
- Keep all other hyperparameters fixed. Report the selected learning rates; the primary estimand is performance under equal tuning budgets, not a pure optimizer change at one shared learning rate. A shared-learning-rate sensitivity run is optional.
- Evaluate pretrained, intermediate, and final validation loss on the same fixed evaluation tokens. Evaluate final test loss only after selection and protocol lock. Final comparisons remain at step 600, not each arm's best checkpoint.

Task-learning adequacy is a gate on interpretation: require finite training and a reproducible held-out loss reduction relative to initialization. Report paired per-seed changes and their uncertainty. If an arm has negligible updates, unstable loss, or no demonstrated held-out improvement, retain the spectral result but label the conclusion about meaningful finetuning inconclusive. A low-norm or untrained perturbation is not evidence of successful low-rank learning. Equal tokens need not yield equal predictive quality; show rank and tail results alongside loss.

## 4. Learning perturbations, modules, and checkpoints

For each selected matrix, define the primary object as

ΔW(t) = W(t) − W(0).

Use the same original pretrained tensor for subtraction in every arm. This is cumulative displacement, not a gradient, single-step update, or the spectrum of W(t). Retain checkpoint-increment displacements only as diagnostics.

Sample layers 0, 5, and 11, representing early, middle, and late depth. At each layer analyze six matrices separately:
- attention Q, K, V, and output projection;
- MLP expansion and contraction.

This gives 18 matrix targets. Split GPT-2's fused QKV tensor using verified axis/order metadata. Its Conv1D weight convention may transpose the usual linear-layer layout; transpose only for consistent labels, since transpose preserves singular values. All these GPT-2 matrices have min(m,n) = 768, although MLP aspect ratios differ. Do not concatenate matrices or pool their singular values. Biases and normalization vectors are excluded; embeddings and the tied output weight are optional, separate strata.

Primary cycle-boundary checkpoints: steps 60, 180, 360, and 600, corresponding to 0.492M, 1.475M, 2.949M, and 4.915M tokens. The confirmatory rank-equivalence endpoint is step 600; earlier checkpoints characterize trajectories.

Block-recency controls:
- Save selected-matrix snapshots at steps 550, 560, 570, 580, 590, and 600, the ends of the six blocks in the final cycle; compare Adam arms at exactly those token counts. Reuse step 600 rather than count it twice.
- Log each matrix's active-step count, tokens since its last update, block position, and current learning rate. Cycle-boundary checkpoints have equal completed cycles but unequal recency—do not describe them as phase-neutral.
- Predeclare a lower-replication sensitivity experiment: reverse the six-block order for three of the paired seed IDs, rerunning BAdam only and reusing the corresponding Adam controls. This is a diagnostic of depth/order confounding, not a second five-seed confirmatory study. If it reverses conclusions, label the result schedule-sensitive. If resources cannot support it, explicitly restrict conclusions to the forward schedule.

## 5. Numerical workflow and effective rank

Save master-precision weights or master-precision displacements for the selected tensors. Disable quantization for the core experiment. Proposed training is mixed-precision forward/backward with FP32 master weights; compute displacements from those master weights, not rounded inference exports.

Analyze one tensor at a time on CPU or an available accelerator. Convert to float64 for subtraction and full SVD where feasible; this cannot recover precision already lost during training. For each ΔW record:
- full singular values, dimensions and aspect ratio;
- Frobenius and spectral norms, and ||ΔW||F / ||W(0)||F;
- reconstruction/energy consistency and finite-value checks;
- effective ranks and numerical-resolution flags.

Use full rather than truncated SVD for the 18 selected moderate-width matrices. Define a numerical-floor diagnostic τ = max(m,n) ε64 σ1. Report counts below τ, but do not automatically discard small singular values from the primary energy calculation. Compare representative float32 and float64 decompositions and rank sensitivity after removing values below 10τ and 100τ. If master-weight resolution or decomposition uncertainty materially changes the conclusions, mark them unresolved. Analyze synthetic zero, known-low-rank, isotropic, and prescribed-spectrum matrices to validate code before processing study outcomes; these are pipeline tests, not empirical evidence about BAdam.

Primary rank:

p_i = σ_i² / Σ_j σ_j²,
R_E = exp(−Σ_i p_i log p_i).

Also report normalized energy-entropy rank R_E/min(m,n), stable rank Σσ_i²/σ1², and the smallest rank capturing 90% of energy. Singular-value entropy using σ_i/Σσ_j is a labeled optional sensitivity metric, not the same definition. Exactly zero displacement has undefined energy-entropy rank and no usable tail; record it separately rather than entering a fabricated rank of one. Numerically unresolved near-zero displacements are likewise flagged.

Matching corresponding matrices removes size differences from paired optimizer comparisons. Native dimensions and aspect ratio remain explicit strata for comparisons across modules or an extension model; dividing rank by min(m,n) does not eliminate all shape effects.

## 6. Effective-rank equivalence and multiplicity

For each matrix at step 600 and each paired seed, compute

d_s = log[R_E,BAdam / R_E,Adam].

Proposed practical equivalence bounds are ±log(1.20), corresponding to a ratio between 0.833 and 1.20. The rationale is an interpretable approximately 20% multiplicative tolerance, narrower than gross low-rank/full-rank contrasts while potentially measurable with modest replication. It is a design assumption, not a validated scientific tolerance. Show sensitivity to ±log(1.10) and ±log(1.30), without replacing the primary margin after seeing results.

Use paired two-one-sided t tests (TOST) at α = 0.05 on seed-level log ratios. For each of the 18 primary matrix claims, take the larger one-sided p value and apply Holm correction across the 18 claims. Report paired geometric-mean ratios, ordinary uncertainty intervals, and the multiplicity-adjusted equivalence decision; ordinary intervals alone are not simultaneous confidence bands. State the small-sample log-ratio distribution assumption and inspect the individual pairs. If that assumption is seriously questionable, report descriptive uncertainty and inconclusive confirmatory equivalence rather than manufacturing precision. A nonparametric/bootstrap sensitivity analysis is descriptive at five seeds and is not a cure for weak replication.

If present, the BAdam–AdamW mechanistic comparisons form a separately labeled secondary family of 18 Holm-adjusted tests; they cannot establish the literal-Adam claim. Earlier checkpoints, normalized-rank differences, and secondary ranks are estimation/sensitivity analyses, not additional unadjusted confirmatory claims.

An attention or MLP submodule family passes rank equivalence only if all three sampled depths pass its corrected primary tests. A broad 'across sampled modules' rank claim requires all 18 to pass. Failure to pass means **equivalence not established**, not automatically meaningful difference. Distinguish a point estimate outside the margin with strong supporting uncertainty from a wide interval compatible with both similarity and difference. Do not use matrices, checkpoints, or singular values as extra independent training replicates. Five seeds may simply be insufficient for a narrow, multiplicity-controlled conclusion; that is an acceptable study outcome.

## 7. Tail analysis

### Variable, support, and cutoff
Fit positive singular values σ, not σ² and not eigenvalues of WᵀW. Use complementary cumulative plots rather than relying on histograms or a visually straight log-log segment.

For each matrix, seed, and checkpoint, consider candidate lower cutoffs at observed singular values, requiring at least max(50, ceil(0.10 min(m,n))) values above the cutoff. For the proposed matrices this is 77 values. Require at least a fivefold range σmax/σmin,tail for an eligible claim; otherwise classify the tail as weakly identified. These are proposed screening thresholds, not universal guarantees of power-law identifiability.

Choose the Pareto lower cutoff by minimizing the tail Kolmogorov–Smirnov distance among eligible candidates. Fit its exponent by continuous maximum likelihood, with density convention f(σ) ∝ σ^−α, α > 1. Record the chosen cutoff, tail fraction, dynamic range, exponent, and fit error. Run cutoff sensitivity using adjacent eligible cutoffs and a common fixed tail fraction, such as the largest 20% of singular values. Boundary solutions and unstable fits are flags, not evidence.

### Alternative distributions and adequacy
At the same chosen cutoff and on the same tail observations, fit:
- a Pareto/power-law tail;
- a lognormal distribution conditioned above the cutoff;
- an exponential tail;
- an exponentially truncated power law.

Use maximum likelihood and report log-likelihood contrasts and AIC differences, with ΔAIC ≥ 4 proposed as a descriptive separation threshold. Compare fitted survival curves and residuals. If all fits are poor, do not call the least bad one a success.

Use 1,000 parametric bootstrap refits for diagnostic goodness-of-fit calibration, including cutoff reselection; p < 0.10 is a proposed model-warning threshold. Bootstrap fit procedures must reproduce the support/cutoff search, not pretend the cutoff was fixed a priori. Because singular values of one learned matrix are dependent, ordinary independent-tail bootstrap p values and exponent intervals are **model-based diagnostics**, not calibrated population-level hypothesis tests. Do not use an IID likelihood-ratio significance test to make the final scientific claim. Seed-to-seed reproducibility, cutoff stability, module consistency, and contrasts with alternatives carry the evidential weight.

### Interpretable tail labels
- **Power-law-compatible:** adequate range/support, no strong diagnostic fit failure, stable cutoff behavior, and no alternative favored by ΔAIC ≥ 4; describe remaining indistinguishability explicitly.
- **Broader heavy-tail-compatible:** Pareto and/or lognormal provide acceptable descriptions and outperform exponential by ΔAIC ≥ 4, without a clearly preferred light-tailed alternative. A lognormal is heavy-tailed in the absence-of-positive-exponential-moments sense, but not a power law.
- **Truncated-tail preference:** truncated power law is favored and adequate; report finite-range power-law-like behavior, not an asymptotically heavy-tailed distribution.
- **Light-tail preference**, **heterogeneous**, or **inconclusive:** as supported by fit comparisons, insufficient support, instability, or disagreement.

If truncation and an untruncated heavy tail cannot be distinguished, describe the evidence as finite-range compatibility, not proof of asymptotic behavior. Finite matrix spectra cannot establish an asymptotic law.

At the final checkpoint, a matrix receives reproducible heavy-tail-compatible evidence only if at least four of five seeds meet the broader compatibility rule, including its alternative-fit requirements. Report all five fits and any contradictory seed; this 4/5 rule is a descriptive reproducibility rule, not a binomial significance test. A module-family claim requires this at all three sampled layers. Earlier checkpoints show emergence or disappearance but cannot rescue a failed final endpoint by post hoc selection. No confirmatory multiple-testing p-value claim is made from these dependent spectral diagnostics.

## 8. Separate and joint adjudication

Produce a six-family × three-depth table at each checkpoint with BAdam tail label, Adam tail label, BAdam/Adam rank ratio and uncertainty, corrected equivalence status, perturbation magnitude, and task-learning context. Add AdamW mechanistic results in a separate panel.

At the primary final endpoint:
- **Joint support within sampled scope:** each selected BAdam matrix shows reproducible heavy-tail-compatible evidence and each literal-Adam rank comparison passes equivalence, with adequate learning and no decisive numerical/schedule failure.
- **Partial support:** only one component is supported; state which. For example, heavy-tail compatibility with rank inequivalence is not a positive joint answer.
- **Heterogeneous support:** some module families/depths satisfy both criteria and others do not. Name them rather than averaging them away.
- **Inconclusive:** insufficient spectral range, non-identifiable alternatives, inadequate learning, or rank intervals too wide. Do not equate lack of rejection with heavy tails or equivalence.

If rank equivalence holds only versus AdamW, say so and keep the literal-Adam question unresolved or negative according to its own evidence. If conclusions depend on cutoff or block order, make that dependence part of the result. The heavy-tail wording in any final conclusion must remain 'consistent with' rather than 'proved.'

## 10. Feasibility and workflow

Core forward-schedule budget with three arms: 24 runs including tuning, totaling 14,400 optimizer steps and approximately 118 million training tokens. The proposed reverse-order diagnostic adds three BAdam runs, 1,800 steps, and approximately 14.7 million tokens. A two-arm Adam-backed implementation reduces the corresponding core budget to 16 runs. These counts exclude evaluation and optional extensions; they are not runtime promises.

For 124M parameters, FP32 weights, gradients, and two full moment buffers alone occupy roughly 2 GB before activations, mixed-precision copies, framework overhead, and checkpointing. A single modern 16–24 GB GPU is a plausible target with small microbatches and accumulation, subject to a memory check; no such compute is asserted available here. Wall time must be measured rather than inferred from parameter freezing.

The 18 selected GPT-2 matrices contain approximately 35.4 million parameters: roughly 142 MB per FP32 spectral snapshot. Four cycle checkpoints plus five distinct additional final-cycle phase checkpoints give nine snapshots per main run, about 19 GB across fifteen runs, before metadata, restart checkpoints, and diagnostics. Store the pretrained reference once. Process SVDs sequentially; a 768×3072 matrix costs roughly O(3072×768²) arithmetic for dense spectral decomposition. Analyze final checkpoints first, then trajectories; do not substitute top-k SVD for a full-spectrum entropy-rank estimate without a quantified residual-energy bound.

1. Obtain and pin data, model, optimizer implementation, parameter groups, and block-state semantics.
2. Validate freeze behavior, tied-weight membership, state clocks, decay, token counters, fused projection extraction, and spectral code using small non-outcome checks.
